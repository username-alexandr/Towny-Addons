# CraftoUI Fabric 0.8.6 — вылет при переходе из города

Исправлен клиентский вылет из отчёта `crash-2026-10-25_23.23.05-client.txt`: `NullPointerException` в `Protocol.str`, вызванный `CivicScreen.extractRenderState` при отрисовке отсутствующих данных города. Отчёт указывает CraftoUI 0.8.5, Minecraft 26.2 и Fabric Loader 0.19.4.

## Причина

Ответ сервера мог прийти между клиентским тиком и следующим кадром. Поле данных города уже сбрасывалось при переходе, например в материалы, а раскладка и кнопки оставались от предыдущего экрана до следующего тика. Отрисовка проверяла наличие раскладки и обращалась к уже отсутствующему JSON города. Такое же рассогласование возможно при локальном переходе и открытии подтверждения.

## Исправление

Переобновление раскладки выполняется перед извлечением каждого кадра, если данные изменились. Данные, список кнопок, текст, карта и геометрия города синхронизируются одной перестройкой интерфейса. Между сменой данных и перестройкой старые элементы не принимают действия, ввод и прокрутку: старый идентификатор кнопки не используется с новым токеном ответа. Escape остаётся доступным.

Новый дизайн города, группы действий, карточки прогресса, темы и удаление подборщика из городской навигации сохранены. Серверная логика, протокол и данные аддонов не изменены.

## Установка

**Нужен только новый клиентский JAR `CraftoUI-Fabric-26.2-0.8.6.jar`.**

1. Закройте игру.
2. Удалите предыдущий CraftoUI Fabric JAR из `mods/` профиля GML и положите новый. Не оставляйте обе версии.
3. Если профиль распространяется через GML, обновите его файл мода и синхронизируйте клиент.
4. Запустите игру. Серверный CraftoUI **0.8.5** оставьте; для этого исправления сервер перезапускать не требуется.

Архив 0.8.6 содержит клиент 0.8.6, неизменённые сервер/API 0.8.5, полный исходный код и Wrapper. Требования Java 25, Minecraft 26.2, Loader ≥0.19.4, Fabric API 0.161.0+26.2 сохранены.

## Проверка и её границы

Воспроизведение выполняет настоящий исходный `CivicScreen` с явно обозначенными двойниками Minecraft UI и транспорта: `tools/city-lifecycle-test/run.py`. Сценарий «тик → ответ сервера → отрисовка без следующего тика» на исходнике 0.8.5 падает с той же цепочкой `Protocol.str:69 → CivicScreen.extractRenderState:157`, что и присланный отчёт.

После исправления пройдены **19 проверок**: переходы к материалам, карте, истории, казне, приглашениям и целям; локальное открытие страницы; подтверждение; запоздалый ответ; блокировка старых контролов; возврат в город; потеря членства; серверная ошибка; повторные переходы и изменение размеров окна. В сценарии повторения выполнено 30 циклов между городом и материалами. Отчёты до/после находятся в `validation/0.8.6/`.

Также повторно пройдены **188 модульных тестов: common 75 + server 113, без ошибок и пропусков**. Сборка выполнена Java 25.0.2 и Gradle 9.0.0; комплектный Wrapper 9.5.1 в этом прогоне не использован.

Клиент собран с оригинальными проверенными по SHA-1 библиотеками Minecraft 26.2. Двойники используются только в отдельной проверке и не входят в JAR. Полный графический Minecraft и реальное сетевое подключение в этом прогоне не запускались. Результаты прежнего Folia-прогона сохранены в каталоге 0.8.5 и не выдаются за новую проверку сервера.
