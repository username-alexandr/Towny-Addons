# CraftoUI 0.9.9 — город, склад и дерево развития

## Изменения

- В городском экране заголовок и описание расположены ближе; большие суммы показываются кратко, полное значение остаётся в подсказке. Карточки казны и участков открывают нужный экран, повторные кнопки удалены.
- Склад аддона Builds оформлен как отдельное широкое окно с подсказками, но использует настоящие слоты, перенос предметов и права аддона. На узком экране остаётся компактная раскладка.
- Кнопка «Постройки и исследования» открывает дерево. Для 90 зданий есть реальные зависимости в каталоге Builds: ратуша — начало, следующая ветвь становится видимой только после выполнения всех её условий. Действующие уровни берутся из API Builds и Research. Уже построенные здания старого города не исчезают из дерева. Действуют фильтр ветвей, вкладки зданий/исследований/возможностей, прокрутка и переход к экранам аддонов. План и смета остаются отдельным разделом. После постройки рынка показывается узел городского рынка; международные предложения появляются после требуемых торговых зданий.

## Установка и совместимость

Обновите клиентский `CraftoUI-Fabric-26.2-0.9.9.jar` и серверный `CraftoUI-Folia-26.2-0.9.9.jar`, убрав старые версии. Требуются Minecraft/Folia 26.2, Java 25, Fabric Loader 0.19.4, Fabric API 0.161.0+26.2. Клиентский мод остаётся необязательным для входа на сервер.

Для **новых правил строительства** в серверных `plugins/` замените исходный `NeverLandTownyBuilds-0.11.4.jar` из пакета NeverLandTownySuite 0.52.6 на `NeverLandTownyBuilds-0.11.4-CraftoTree.jar`. Не оставляйте оба JAR. Это тот же исполняемый аддон с заменённым встроенным `projects.yml`; класс и версия аддона не менялись. Сделайте резервную копию `plugins/NeverLandTownyBuilds/projects.yml` и данных города перед перезапуском. Старый файл без поля `requires` для здания наследует новые требования из обновлённого JAR, поэтому удалять его или терять изменённые цены не требуется. Явное поле `requires`, даже пустое, имеет приоритет у администратора. Для нового сервера пример полного файла — `addon-overrides/projects.yml`; на существующем сервере не перезаписывайте им свои настройки вслепую. Исследования берут собственные зависимости из `technologies.yml`; если Research отсутствует, дерево покажет только здания.

Для GML положите клиентский JAR в папку `mods` профиля NLT и удалите старый CraftoUI. Для Pterodactyl остановите сервер, обновите два серверных JAR в `plugins/`, затем запустите сервер. Отдельный API JAR нужен разработчикам для компиляции и не должен дублировать классы в `plugins/`.

## Проверка и ограничения

Gradle/JUnit проверили граф на 90 зданий, существование ссылок и отсутствие циклов, а также размер полного дерева в лимите протокола. Сверены входные и выходные JAR аддона: кроме `projects.yml`, все записи идентичны; ZIP целый. Knot действительно загрузил клиентский 0.9.9 с Fabric Loader 0.19.4 и MixinExtras 0.5.5 и преобразовал `ContainerEventHandler`. Это не игровой прогон: взаимодействия со складом, экономика и разрешения Towny на живом сервере пока не проверялись. UI сейчас показывает как условные возможности рынок и международную торговлю; другие функции аддонов требуют согласованных серверных правил доступа, чтобы закрытие ветки в UI нельзя было обойти прямой командой. Контроль доступа к строительству уже выполняет Builds через `requires`; UI только отображает его условия.
