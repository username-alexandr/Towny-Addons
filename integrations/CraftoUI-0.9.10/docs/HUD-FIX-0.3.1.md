# Исправление отсутствующей панели — сервер CraftoUI 0.3.1

## Причина

В сервере 0.3.0 `ContractHudBridge.bind()` принимал только строку версии **0.3.20**. Настоящий предоставленный JAR NeverLandTownyContracts **0.3.21** имеет совместимый формат сохранений, но отключался этой проверкой. Получался пустой HUD даже при обнаруженном клиенте и взятом заказе. Проблема воспроизведена на изолированном стенде. Версия на рабочем сервере пользователя пока не подтверждена его журналом или выводом команды.

Проверены оригинальные JAR 0.3.20 и 0.3.21: изменение касается отображения оплаченных шаблонов на доске. Формат `public-orders.yml`, модель Order и платёжный журнал не изменились. CraftoUI 0.3.1 допускает обе проверенные версии. Неизвестные версии по-прежнему требуют проверки адаптера.

SHA-256 исследованного `NeverLandTownyContracts-0.3.21.jar`:

```text
84036708e8dcf6c73791e8ab2175c88f3eb3ae4ea7dd9f704de52b40cdad3c26
```

Сторонний JAR и его декомпиляция в поставку CraftoUI не включены, код и данные Contracts не изменяются.

## Установка

1. Штатно остановить Folia.
2. Удалить предыдущий **CraftoUI-Folia** JAR из `plugins/`, установить `CraftoUI-Folia-26.2-0.3.1.jar`. Не оставлять две версии CraftoUI.
3. Запустить сервер и переподключиться.
4. Клиент **CraftoUI-Fabric-26.2-0.3.0.jar** подходит без обновления. Если в профиле GML ещё клиент 0.2.x, установить клиент 0.3.0 из комплекта и полностью перезапустить игру.
5. В игре выполнить `/orders mine`, убедиться, что есть личный активный заказ, затем закрыть чат/меню.

Конфиги и данные не удалять; `/reload` не использовать. Для HUD нужны Contracts 0.3.20 либо 0.3.21 и обычные зависимости аддона. Общие инструкции GML/Pterodactyl: [INSTALL.md](INSTALL.md).

## Диагностика

В **игре** выполнить `/craftoui status`. Команда показывает:

- версию серверного CraftoUI;
- обнаружение клиента и объявленную поддержку панели;
- состояние адаптера и версию Contracts;
- недостающее право из `craftoui.use`, `craftoui.contracts`, `neverland.orders.use`;
- ожидание отправки, устаревшие данные, отсутствие личных активных заказов либо число отправленных записей.

При сообщении «Отправлено заданий на панель» закрыть чат/меню и проверить включение HUD в настройках CraftoUI. H переключает видимость, F1 скрывает весь HUD. Сервер не может прочитать локальный переключатель H/F1, поэтому отправку не выдаёт за подтверждение фактической видимости. Если проблема остаётся, нужны полный вывод status, `/version NeverLandTownyContracts` и наличие заказов в `/orders mine`.

`release` завершилась `BUILD SUCCESSFUL`. Сводка JUnit: **32 теста, 0 ошибок, 0 пропусков**. По наборам: ProtocolTest 7, MenuSchemaTest 5, ContractHudStateTest 5, ConfigLoaderTest 4, AddonCatalogTest 4, PublicOrderReaderTest 7. Оригинальные XML и лог сборки приложены.

В логах присутствуют ограничения стенда: недоступные сервисы авторизации/Realms, аудиоустройство и сведения о системных процессах. Это не выдаётся за полностью чистые логи. Сторонняя экономика/награды, Windows, полный модпак пользователя, отсутствие мода и все остальные меню в этом целевом прогоне не перепроверялись. Исторические проверки 0.2.x/0.3.0 сохранены отдельно.

## Состав изменения

Сервер и API — 0.3.1, клиент — 0.3.0. Протокол и клиентская отрисовка не менялись. Панель по-прежнему показывает личные `/orders`; городские контракты в неё не входят. Подробные прежние ограничения: [LIMITATIONS.md](LIMITATIONS.md).
