# CraftoUI protocol 1

## Необязательные поля карточек заказов, 0.7.2

В строках ответа CIVIC (`op: view`, маршруты `orders` и `mine`) сервер может передавать `rarity`, `reward`, `kind`, `icon`. `rarity` — значение enum Contracts, `reward` — форматированная строка награды, `kind` — отображаемый тип, `icon` — идентификатор предмета Minecraft. Пример: `{"rarity":"EPIC","reward":"125.00","kind":"Рыбалка","icon":"minecraft:tropical_fish"}`. Они только описывают внешний вид; параметры действия и права клиент из них не выводит. Неизвестный значок безопасно пропускается, неизвестная редкость не получает выдуманное значение.

Фильтр CIVIC `sort` дополнен значением `rarity` (сначала высокая редкость). Существующие `reward`, `ready`, `title` сохранены. Номера сообщений, версия кадра и согласование не изменены. Старые клиенты игнорируют новые поля, новые клиенты допускают их отсутствие. `/orders` больше не преобразуется в CIVIC; обычный инвентарный протокол и NATIVE_MENU сохраняют исходные предметы.

---

Транспорт: custom payload / plugin messaging `craftoui:wire`, **PLAY**-фаза. Fabric регистрирует один кодек в `serverboundPlay()` и `clientboundPlay()`. Bukkit/Folia передаёт точно те же байты. Дополнительного `writeUTF`, VarInt или JSON-строки вокруг нашего кадра нет; длина самого Minecraft-пакета принадлежит транспортному слою.

## Кадр

| Смещение | Тип | Содержание |
|---|---|---|
| 0 | unsigned byte | Версия кадра: 1 |
| 1 | unsigned byte | Вид сообщения |
| 2–5 | int32 big-endian | Число байтов JSON |
| 6… | UTF-8 | Один JSON-объект |

Максимум полного кадра — 28 672 байта, включая заголовок. Сжатия и фрагментации в MVP нет. Разбивайте слишком большие меню на страницы. Кодек проверяет длину, UTF-8, глубину, количество полей и длину строк. Избыточный/повреждённый пакет игнорируется; CraftoUI не кикает за отсутствие мода или несовпадение версии.

## Сообщения

| Код | Имя | Направление | Поля |
|---|---|---|---|
| 0 | HELLO | C→S | `min`, `max`, опциональный массив `features` |
| 1 | WELCOME | S→C | `accepted`, `protocol`, `message`, `home` |
| 2 | REQUEST | C→S | `menu` |
| 3 | OPEN | S→C | `session`, `revision`, `screen`, `theme`, `data` |
| 4 | ACTION | C→S | `session`, `revision`, `sequence`, `component` |
| 5 | RESULT | S→C | `session`, `sequence`, `success`, `message`, `clientAction` |
| 6 | PATCH | S→C | `session`, `revision`, `data` |
| 7 | CLOSE | C↔S | `session`; от сервера также `message` |
| 8 | NATIVE_MENU | S→C | `title`, `slots`, `module`, `inventory`, `columns`, `width`, `height`, `theme` |
| 9 | CONTRACTS | S→C | `entries`: полный текущий список личных контрактов |
| 10 | BACK | C↔S | `navigation`; S→C дополнительно `slot` для штатной кнопки аддона |

HELLO начинается только на стороне клиента после обнаружения поддерживаемого сервером канала. Сервер не посылает UI обычным игрокам. Совместимость принимается, если версия 1 входит в диапазон клиента. Неизвестная версия заголовка не разбирается.

OPEN заменяет прежнюю сессию. `session` — случайный UUID, связанный на сервере с подключённым игроком и экраном. `revision` меняется при reload/изменении API-регистраций. `sequence` начинается с 1 для каждой сессии и монотонно растёт; повтор/уменьшение игнорируется. Срок сессии — 15 минут. Смена сервера/отключение очищает состояние клиента.

ACTION передаёт **идентификатор компонента**, а не имя команды, действие, цену, баланс или произвольные аргументы. Сервер заново находит экран/компонент, проверяет все родительские контейнеры, доступность, права экрана и действия, ревизию и последовательность. Аргументы берутся из серверного определения. `permission`, `action`, `arguments` исключаются из передаваемой схемы.

RESULT `clientAction` допускает только локальную настройку `settings`; произвольные команды, URL и скрипты клиент не выполняет. Навигация возвращает новый OPEN, а закрытие — CLOSE; отдельный RESULT для них не нужен. Обновления данных объединяются по ключам, применяются только к совпадающей сессии/ревизии.

Admission control применяется до EntityScheduler: ёмкость 15 сообщений, пополнение 8 в секунду; повторный HELLO — не чаще одного раза за 3 секунды. Клиент дополнительно ограничивает клики интервалом 150 мс. Эти значения описывают реализацию в `Protocol.java`, `RateGate.java` и `CraftoUIPlugin.java`.

Данные профиля собираются раз в 20 тиков **только при открытом меню** и отправляются лишь при изменении. Внешние providers вызываются при открытии и явном refresh, с таймаутом 3 секунды. Клиенты без мода не получают повторяющихся задач.

## Дополнение 0.3.0: HUD контрактов

Клиент добавляет `contracts-hud-v1` в HELLO `features`. Сообщение **9** отправляется только согласовавшим протокол клиентам с этой возможностью. Коды 0–8 и версия кадра 1 не меняются. Сервер не принимает CONTRACTS от клиента как действие и не принимает клиентский прогресс.

Пример тела (иллюстрация формата, не данные пользователя):

```json
{"entries":[{"id":"46da9ee2-f622-428f-a775-c60fca8ac628","title":"Поставка пшеницы","progress":24,"goal":64,"inventory":true,"status":"ACTIVE"}]}
```

`id` — UUID; `title` — непустая строка до 160 символов без управляющих символов; `progress`/`goal` — точные целые int32, `0 <= progress <= goal`, `goal > 0`; `inventory` — признак подсчёта предметов для поставки. Это полный снимок, независимый от сессии открытого меню. Чтение серверных сохранений выполняется одной асинхронной задачей раз в две секунды; чтения нет без согласовавших возможность клиентов. Инвентарь и права проверяются на EntityScheduler соответствующего игрока. Отправка выполняется при изменении или через восемь секунд для поддержания актуальности. Клиент скрывает снимок через 20 секунд без обновления и очищает его при отключении/сбросе согласования. Переключение страницы и H локальны; награды и сдача по-прежнему выполняются исходным аддоном.

## 0.6.0: commands-v1

Версия базового протокола остаётся 1. В конец enum добавлен `COMMANDS` (код 14); прежние коды не изменяются. Клиент объявляет `commands-v1` в HELLO, сервер — в WELCOME. Новые пакеты отправляются только клиентам, объявившим эту возможность. Старые клиенты продолжают работать; вход без мода не требует handshake.

Все сообщения `COMMANDS` содержат `op`; клиентские запросы имеют целочисленный `request`, который сервер возвращает. Клиент отбрасывает запоздалые ответы. `open` получает новую сессию; остальные операции передают её `token`, кроме `return`, запускающего только фиксированный разрешённый корневой переход из addons.json.

| Направление | op | Поля / назначение |
|---|---|---|
| C→S | open / list | module, query, page, size (1–24) |
| S→C | list | token, module, moduleLabel, page, pages, count, entries [{id,label,detail,type}] |
| C→S | form | id, token |
| S→C | form | id, token, module, form, usage |
| C→S | suggest | id, field (индекс), values, token |
| S→C | suggest | field, entries (до 24 строк), request |
| C→S | prepare | id, values, token |
| S→C | review | confirmation, command, label |
| C→S | confirm | confirmation, token; аргументы хранятся сервером |
| S→C | dispatched | Команда передана обработчику; это **не** сообщение об успехе бизнес-операции |
| S→C | error | message; без выполнения действия |
| C→S | cancel | token; отменяет текущий билет без закрытия формы |
| C→S | close | token; очищает сессию и подтверждение |
| C→S | return | module; фиксированный переход к корню известного аддона |
| S→C | show | открытие каталога по `/craftoui actions` |

Сессия: 5 минут. Подтверждение: 30 секунд, однократное, связано с соединением и снимком каталога. Reload/повторный HELLO/новая сессия инвалидируют билет. После проверки билета повторно проверяются текущие права, активность плагина и идентичность зарегистрированной команды. `confirm` не принимает клиентскую командную строку. Аргументы ограничены 512 символами, управляющие символы и переносы запрещены. При отсутствии ответа клиент снимает ожидание через 8 секунд и предлагает повторить запрос.

Ответы `list` и `form` содержат актуальную серверную `theme`; клиент применяет её с учётом локального выбора оформления.

## Дополнение 0.7.0: civic-v1

В конец enum добавлен `CIVIC` (ordinal 15); прежние значения и VERSION=1 сохранены. Пакеты этого вида отправляются только после согласования `civic-v1` в HELLO/WELCOME.

Запросы клиента: `open {route,request,size}`, `page {token,page}`, `back {token}`, `filter {token,type,rarity,minimum,sort,ready}`, `act {token,action}`, `confirm {token,confirmation}`, `poll`. `request` возвращается в ответе для отбрасывания устаревших результатов; `size` ограничен сервером диапазоном 1–12.

Ответ `view`: `token,title,route,id,notice,lines,rows,page,pages`. Строка содержит `title,detail,targetKey,action,reason`. `action` — непрозрачный ключ серверной таблицы, а не команда. `reason` отображается рядом с недоступным действием. Карта дополнительно передаёт `map {size,cx,cz,cells}`: каждая ячейка содержит координаты, статус, владельца и непрозрачный ключ действия.

`review` содержит заголовок, строки последствий и одноразовый `confirmation`. Возврат к странице отменяет прежний билет. `error` содержит понятную причину; `notification` показывает неблокирующую карточку; `refresh` предлагает обновить открытый экран; `show` открывает указанный раздел при разрешённом сервером переходе. `resume` возвращает клиента из исходного меню аддона к сохранённой странице Civic и запрашивает её актуальное состояние; предыдущая сессия обычного меню открывается заново, если сервер уже закрыл её.

Максимум пакета остаётся 28 KiB. Фильтры, страницы и координаты не являются основанием для разрешения изменения. Игрок, город, права, актуальное состояние заказа, регион и назначение подтверждения устанавливаются сервером.

## Building preview extension (0.8.0)

Protocol version remains 1. Clients opt in with `building-preview-v1` in HELLO. BUILD_PREVIEW is appended after CIVIC; existing kind ordinals are unchanged. Only opted-in clients receive it. The server chooses the project from the current Builds inventory holder; no client path, URL, model or placement action is accepted.

NATIVE_MENU contains `buildingPreviewKey`. Each BUILD_PREVIEW contains that key, view 0–3 and base64 PNG fragments (`chunks`, ≤4000 characters each). PNG ≤16000 bytes and 64–256 square pixels; typical output is 192×192. The existing 28KB packet and 4096-character string limits remain unchanged. An unavailable image returns `available:false`. Late results are discarded if the inventory changed; the client also checks the menu key and releases textures when closed.


## Placement controls (0.8.1)

Optional `placement-controls-v1` capability in HELLO and WELCOME. `PLACEMENT` is appended to the protocol-1 kind list; existing ordinals are unchanged. Servers send no placement packets to clients without this capability.

Server state: `active`, opaque session `key`, acknowledged `sequence`, held `slot`, `x/y/z`, `fixed`, `ready`. An active heartbeat refreshes state every second; the client expires it after three seconds. Inactive or fixed state disables controls. Client requests contain only `op: move`, `key`, positive integer `sequence`, and one action: `forward`, `back`, `left`, `right`, `up`, `down`. Coordinates, project identity and confirmation are never supplied by this input path.

Input is limited to four requests per second and four queued moves, discarded when a screen opens or the blueprint is no longer held. Builds validates the live player, town, blueprint, session, sequence and location on the player's owning region; it rejects replays and requests less than 180 ms apart. State includes the acknowledged sequence to resume safely after changing held items. Arrow direction uses server-known player facing. A separate menu confirmation retains the existing payment path.

## Финансы города 0.8.12

В `city` добавлено необязательное поле `finance`: `known`, `period`, `observedAt`, `metrics[]`, `action`, `reason`. Метрики — расходы, поступления и итог за одну текущую неделю TreasuryPlus (понедельник 00:00 UTC). Каждая содержит `label`, форматированное `value`, `hint`, `detail`, `icon` и `tone` (`neutral`, `positive`, `negative`, `warning`). Значения вычисляет сервер целыми сотыми; клиент только отображает готовые строки. `observedAt` — время получения снимка, не время последней транзакции. `known=false` отображается как отсутствие данных, без числового нуля.

Ключ `cf` выдаётся сервером только при разрешённом доступе к казне собственного города. Нажатие использует существующее `CIVIC act` с токеном страницы и ключом, а переход — существующий маршрут `treasury`. Команды, суммы и UUID города от клиента не принимаются. До и после асинхронного чтения применяются существующие проверки прав и членства. При отсутствии доступа суммы в финансовом блоке не отправляются.

Новые виды пакетов и обязательные capability не добавлены. Старый dashboard-клиент игнорирует `finance`, новый работает и без этого поля. Предел frame остаётся 28 КиБ; проверена максимальная страница с финансовым блоком.


## Дополнение 0.8.18: восстановление Civic

В согласованном `civic-v1` добавлены клиентские `refresh {request,size}` и `close {request}`. Версия frame 1 и ordinal CIVIC 15 не изменены. Обновлять мод и плагин совместно. Серверный `refresh` по-прежнему означает предложение клиенту обновить данные.

Клиентский `refresh` сбрасывает старые action keys, одноразовый ticket и generation текущей загрузки, сохраняет серверные route/id/page/history и получает новый `view`. Маршрут и ID из запроса не используются. `back` тоже не требует старый токен: это только переход по доверенному серверному стеку. Оба запроса повторно проверяют права и членство; передача данных использует те же проверки до/после асинхронного чтения.

`close` очищает actions/ticket/token/history и инвалидирует ожидающие загрузки. Он не требует прежних прав, не читает данные и не выполняет бизнес-действий; клиент закрывает окно немедленно, без ожидания ответа. Корневой «Назад» возвращает локального родителя; Esc/крестик закрывают Civic до мира. Возврат из подтверждения делает `refresh`, чтобы очистить ticket без изменения маршрута. `act`, `confirm`, `page`, `filter`, `section` сохраняют проверку текущего токена.

Клиентские `request` уникальны между экземплярами Civic; ответ принимается только ожидающим открытым окном. Старые результаты после закрытия или замены окна игнорируются. `canBack` определяет наличие серверной истории, а не название route. Прямо открытые history/mine/treasury не создают бесконечный переход на city.
