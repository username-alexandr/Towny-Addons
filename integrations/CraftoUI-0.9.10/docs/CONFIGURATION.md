## Обновление интеграций 0.8.20

Миграция дополняет `addons.json` точными классами девяти новых окон, а `command-ui.json` — новыми формами под зарегистрированные корни аддонов. `quick-actions.json` содержит стиль, вклад жителей, зарплаты, часы нападения и лагерь. Существующие ключи не заменяются. Пользовательские исключения владельцев, якорных классов, корней команд и пустые отключённые наборы форм сохраняются. Стандартные меню обновляются с резервной копией; выбранная тема сохраняется. Новая кнопка для своего меню: `action: "quick:city-style"`.

Подробности: [ADDONS-0.8.20.md](ADDONS-0.8.20.md).

# Плотность и страницы, 0.8.17

`paginate: true` вместе с `responsive: true` включает локальные страницы для `content`-сетки или списка. Действия и данные не удаляются, смена страницы не создаёт серверную сессию. `footerActions: true` закрепляет корневые кнопки с `layoutRole: actions` внизу; `shortText` задаёт короткую подпись, полная остаётся в подсказке. Роль `footer` создаётся клиентом при расчёте макета, вручную её задавать не нужно.

`minCellWidth` на сетке ограничивает минимальную ширину колонки при адаптации. Справка использует широкие информационные карточки, профиль — плотные строки. Стандартные навигационные сетки с ID `modules`/`sections` получают компактные ячейки и страницы также в старых конфигурациях. Неизвестные API-макеты и явный `responsive: false` сохраняют свою геометрию.

Примеры: актуальные `menus/profile.json`, `menus/society.json` и `menus/help.yml`. Миграция известных файлов 0.8.16 сохраняет резервные копии и выбор темы. [Установка и ограничения](DENSITY-0.8.17.md).

# Адаптивные меню, 0.8.16

`responsive: true` включает перестройку стандартного макета. На корневых компонентах `layoutRole` задаёт назначение: `aside` — декоративная панель с `children`, `content` — сетка/список с `children`, `description` — текст/уведомление, `actions` — отдельная кнопка под содержимым. Колонки ограничены заданным `columns` и доступной шириной; `rowHeight`, тексты и action ID сохраняются. При малой высоте декоративная панель скрывается. Без `responsive` пользовательская геометрия остаётся прежней. Примеры — актуальные `menus/*.json`.

`commands` в `actions.json` — серверное действие открытия каталога команд; проверяются объявленная клиентом возможность и `craftoui.commands`. В стандартном главном меню одна такая кнопка. Повторные фиксированные переходы внутри одного дерева меню объединяются; произвольные API-обработчики не объединяются. Настройки, обновление и закрытие имеют отдельные адреса.

Миграция меняет только известные неизменённые стандартные файлы, сохраняет выбранную тему и делает резервную копию. Изменённые вручную макеты и цвета сохраняются. [Обновление и ограничения](MINIMAL-0.8.16.md).

# Условие членства в городе, 0.8.3

`requiresTown: true` на меню, компоненте или действии требует настоящий город игрока по Towny API. Недоступные городские компоненты скрываются, сетки занимают освободившиеся ячейки. Действие также проверяется при выполнении. Штатные городские ID и команды распознаются в существующих файлах без перезаписи. Подробнее: [TOWN-MENUS-0.8.3.md](TOWN-MENUS-0.8.3.md).

# Меню, темы и действия

Один файл `.json`, `.yml` или `.yaml` в `menus/` задаёт один экран. `id` уникален. JSON и YAML используют одинаковые поля. После изменения выполнить `/craftoui reload`.

```json
{
  "id": "example",
  "title": "Мой экран",
  "theme": "dark",
  "permission": "craftoui.use",
  "width": 560,
  "height": 460,
  "footer": "Crafto",
  "components": [
    {"id":"hello","type":"text","x":24,"y":70,"w":512,"h":30,"text":"Привет, ${player.name}!"},
    {"id":"back","type":"button","x":24,"y":360,"w":512,"h":32,"text":"Назад","action":"main"}
  ]
}
```

`x/y/w/h` задаются в условных единицах дизайна. Экран целиком подстраивается под текущий GUI Scale и доступное место; клиентский масштаб ограничен размерами окна. Зарезервированы заголовок сверху и нижняя панель. Для стандартного экрана рабочая область: `x >= 12`, `y >= 54`, `x+w <= width-12`, `y+h <= height-40`. Вне области содержимое обрезается.

Поля компонента: `id`, `type`, геометрия, `enabled` (по умолчанию true), `permission`, `hideWhenDenied` (скрыть вместо блокировки), `tooltip`. Идентификаторы — строчные латинские буквы, цифры, `_ . : / -`, без `..`.

| Тип | Дополнительные поля |
|---|---|
| `button` | `text`, `icon` — ID ванильного предмета, `action`, `arguments` для API |
| `text` | `text`, `wrap`, `color` — ключ цвета темы |
| `image` | `texture` — ID текстуры в ресурсах |
| `avatar` | `mode: model` или `face`; текущий игрок |
| `progress` | `value` — число/подстановка от 0 до 1 |
| `panel` | `children` с относительными координатами |
| `grid` | `columns`, `gap`, `rowHeight`, `children`; позиции дочерних ячеек считаются автоматически |
| `list` | `rowHeight`, `gap`, `children`; прокрутка колесом мыши |
| `notification` | `text`, `wrap`; текстовая панель |
| `dialog` | `children`; затемнение предыдущего содержимого и собственные кнопки |

Для диалога размещайте его **последним** компонентом экрана. Диалог отображается постоянно, пока присутствует в схеме. Сложные подтверждения и условия выполняет серверное действие/отдельный экран. Это не автоматическая транзакционная система подтверждений.

В строках разрешены `${player.name}`, `${player.uuid}`, `${player.status}`, `${player.level}`, `${player.exp}`, `${player.health}`, `${player.food}`, `${player.world}`, `${player.gamemode}`, `${player.group}`. Внешний provider добавляет `${namespace.key}`. Неизвестное значение показывается как `—`. Подстановки не вычисляют выражения и не исполняют код.

## Действия

`actions.json` содержит именованные серверные действия:

```json
{
  "main": {"type":"open","menu":"main"},
  "example": {"type":"open","menu":"example"},
  "survival": {"type":"close"},
  "settings": {"type":"settings"},
  "refresh": {"type":"refresh"},
  "message": {"type":"message","message":"Готово."},
  "town_menu": {"type":"player-command","command":"town","permission":"towny.command.town"},
  "proxy_survival": {"type":"proxy","server":"survival","enabled":false}
}
```

Пример показывает поля; не заменяйте им рабочий `actions.json` без сохранения используемых `profile`, `help` и остальных действий.

`player-command` выполняется от самого игрока на его EntityScheduler. Для него обязательны `command` и `permission`. Не добавляйте Folia-несовместимые команды сторонних плагинов. Подстановок пользовательского текста и консольных команд нет. `proxy` посылает совместимый с BungeeCord запрос Connect; включать только после настройки и проверки своего прокси. Успешная отправка запроса не означает, что переход завершён.

Для внешних интеграций используйте действие с namespace, например `neverland:quests`. Пока его не зарегистрировал плагин, кнопка недоступна. Подключение интеграции не требует нового клиентского класса.

## Темы и ресурс-паки

Файлы в `themes/` содержат `id` и цвета формата `#AARRGGBB`: `background`, `panel`, `button`, `hover`, `border`, `text`, `muted`, `accent`, `disabled`, `shade`. Меню ссылается на `id` темы. Цвета, размеры, подписи и состав элементов меняются независимо от действий.

Клиент может переопределить цвета темы через `assets/craftoui/themes/<id>.json` в обычном ресурс-паке. Встроенная тёмная тема находится в `assets/craftoui/themes/dark.json`; локальный выбор тёмной темы имеет приоритет перед серверной. Для картинок:

```json
{"id":"banner","type":"image","x":20,"y":70,"w":240,"h":120,"texture":"craftoui:textures/gui/banner.png"}
```

Ресурс: `assets/craftoui/textures/gui/banner.png`. Используется стандартный менеджер ресурсов Minecraft; CraftoUI не скачивает URL и не читает произвольные файлы. После обновления ресурсов переоткройте меню. Шрифты можно менять стандартным ресурс-паком Minecraft; отдельного выбора шрифта для каждого компонента в MVP нет.

Ограничения схемы: до 128 компонентов на экран, до 128 файлов в каталоге меню/тем; полный OPEN должен укладываться в лимит протокола. Пределы проверяются при загрузке и перед отправкой. Для больших каталогов создавайте отдельные экраны.

## Категории NeverLand и меню аддонов

`hub.json` содержит главный экран; `town.json`, `economy.json`, `adventures.json`, `society.json`, `management.json` — отдельные категории. Они используют обычные компоненты API. Их координаты, тексты, иконки и тема редактируются без перекомпиляции. Зарезервированы автоматически создаваемые действия `hub:<id>` и `addons:<module-id>`.

Если загружен `hub` и действие `main` точно равно стандартному `{"type":"open","menu":"main"}`, загрузчик направляет это действие в `hub`. Пользовательское изменённое действие не подменяется. Явный запрос `/craftoui open main` открывает старый экран.

`addons.json` содержит разрешённые классы меню и фиксированные команды. Пример одного модуля:

```json
{
  "enabled": true,
  "theme": "dark",
  "columns": 3,
  "width": 620,
  "height": 420,
  "modules": [
    {
      "id": "contracts",
      "plugin": "NeverLandTownyContracts",
      "label": "Контракты",
      "command": "town contracts",
      "permission": "neverland.orders.use",
      "holders": ["ru.neverland.mintcontracts.gui.ContractMenuHolder"],
      "inventoryHolders": []
    }
  ]
}
```

Имена классов в примере необходимо сверять с поставляемым `addons.json`: он содержит точные классы обеих ветвей Contracts из проверенной версии. Не заменяйте рабочий каталог сокращённым примером. Команды не содержат пользовательских подстановок, слеша в начале или консольного исполнения. Права команд и состояние города дополнительно проверяет сам аддон.

- `columns`: 1–4; `width`: 480–900; `height`: 320–650. Положение карточек считается автоматически. Цвета задаются темой, содержимое — настоящими предметами аддона.
- `holders`: точные полные имена разрешённых конкретных классов InventoryHolder. Дополнительно проверяется плагин-владелец класса. Нет перехвата по одному заголовку.
- `inventoryHolders`: подмножество `holders`, для которого сразу включается привычная сетка предметов. Используется для складов и редакторов.
- `inventoryTitleWords`: дополнительные слова для выбора сетки **после** проверки класса и владельца. Нужны Camps, где один класс обслуживает и меню, и склад/редактор. Сравнение без учёта регистра.
- `enabled: false`: оставить все нативные меню без нового оформления. Для отдельных модулей можно очистить `holders`; запуск их команд через категории сохранится.
- `permission` и доступность `plugin` проверяются перед действием. Недоступные кнопки блокируются. `craftoui.admin.menus` ограничивает отдельный экран управления, а не выдаёт права на команды Control.

После `/craftoui reload` новое оформление инвентарного меню применяется при следующем открытии. Открытый нативный инвентарь принадлежит аддону: reload CraftoUI не переписывает его предметы и не перезапускает бизнес-действия.


## План развития, 0.9.0

В настраиваемом меню кнопка с `action: "ui:planner"` открывает план развития. Встроенное действие требует город, CraftoUI civic-v1, право craftoui.city и включённый Builds; право просмотра построек перепроверяет CivicWorkbench. Стандартный development.json уже содержит кнопку.

Можно определить собственное действие в actions.json, например:

```json
{"my-planner":{"type":"civic","route":"planner","permission":"craftoui.city","requiresTown":true,"requiredPlugin":"NeverLandTownyBuilds","discoverable":true}}
```

Допустимые входные route: planner, city, materials, inbox, map, goals, treasury, history. Записи и финансовые действия закупок выбираются только через выданные сервером action IDs, не через произвольную конфигурационную команду. Существующие методы API регистрации меню остаются совместимыми.


## Разделение главного меню, 0.9.2

`quick:orders` находится в `menus/economy.json`. В `menus/hub.json` и `menus/main.json` этого пункта нет. При обновлении точечно удаляется только эта кнопка из главных меню, включая изменённые вручную. Резервные копии — `backups/0.9.1/`; остальные изменения администратора сохраняются.

Действие `settings` открывает настройки клиента. Настройка панели контрактов из этого экрана имеет собственный возврат в настройки и не показывает вкладки города или сводки. Серверных пакетов для такого перехода не добавлено; протокол остаётся прежним.

## Создание города, 0.9.1

Встроенное ui:create-town открывает форму Towny/create-town. Кнопке можно задать requiresNoTown: true. Она скрывается после вступления в город. Для своих commands-действий form задаётся как Plugin/form-id; и форма, и оригинальная команда должны быть разрешены сервером.
