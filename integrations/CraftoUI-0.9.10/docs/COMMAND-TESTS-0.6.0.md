# Фактические проверки CraftoUI 0.6.0

Дата: 22 октября 2026 года. Доступность команды в каталоге и успешное выполнение всех её игровых ветвей — разные проверки. Ниже указано фактическое покрытие.

## Среда и сборка

- Настоящие Minecraft Java 26.2, Fabric Loader 0.19.4, Fabric API 0.161.0+26.2, Folia 26.2 DEV-14b7fee, Java Azul 25.0.2, Gradle 9.5.1.
- Локальный изолированный сервер, Towny 0.103.2.0 и 40 настоящих NeverLandTowny-плагинов из комплекта 0.41.0; Builds 0.8.28 и Contracts 0.3.21. Тестовые город, компания и игроки созданы специально для проверки. Экономического провайдера нет.
- Linux, Xvfb/Mesa, программный OpenGL, русский язык. Финальный UI проверен при 1600×1000 и 640×480, GUI Scale 2. Чёрная область на маленьких снимках — свободная часть виртуального рабочего стола.
- `release` успешно собрал клиент, сервер и API через документированный `-PdirectMinecraft` с настоящими Minecraft/Paper API. Обычный путь Loom в этой среде не объявляется проверенным.

Доказательства находятся в `validation/ui-0.6.0/`: `build.log`, `build-artifacts.json`, `unit-tests.json`, исходные JUnit XML, журналы и снимки. SHA-256 доставленных JAR — в `release/SHA256SUMS.txt`.

## Проверки на работающем Folia

Тестовый плагин вызвал настоящий CommandWorkbench на EntityScheduler тестового игрока. В финальном прогоне пройдены проверки:

- Все **54 из 54** зарегистрированных корней команд 40 аддонов доступны в каталоге для игрока с правами. Дополнительно доступен настроенный раздел Towny. Проверен обход всех страниц, а не только первая страница интерфейса.
- Поддельная команда другого владельца и недопустимая роль отклоняются.
- Права повторно проверяются после подготовки, непосредственно перед подтверждением.
- Отмена PlayerCommandPreprocessEvent соблюдается; отменённое подтверждение не исполняется повторно.
- Отправленные клиентом новые аргументы в `confirm` не заменяют подготовленную сервером команду.
- Повтор выполненного подтверждения, отменённый билет и чужой токен сессии отклоняются.
- Сохранённые назначение управляющего и назначение министра читаются из настоящих аддонов после перезапуска клиента и сервера.

Журнал `runtime/command-probe-checks.txt` содержит 110 успешных assertions, включая повторяющиеся проверки наличия ответа; это **не 110 независимых игровых сценариев**. Исходник проверки — `tools/runtime-command-probe/`. Тестовый плагин не входит в выпускные JAR и не предназначен для рабочего сервера.

## Действия в настоящем графическом клиенте

| Сценарий | Наблюдаемый результат |
|---|---|
| Пригласить UiInvite в компанию | Выбор игрока в форме, проверка команды, подтверждение; приглашение создано исходным Companies и сохранено |
| Назначить UiWorker управляющим | Выбрана роль MANAGER; роль записана в Companies |
| Назначить UiMinister министром экономики | Выбрана должность economy; назначение записано в Council |
| Принять приглашение другим игроком без OP | `/craftoui actions` → Компании → Мои приглашения → компания по названию → штатное подтверждение; UiInvite появился в members как WORKER, приглашение удалилось |
| Серверная тема classic | Каталог, формы, подтверждение и нативное меню компании отображаются в светлой теме |
| Маленькое окно | Поле игрока, страницы подсказок, подтверждение и кнопки навигации доступны при 640×480; текст подтверждения разбивается на страницы |
| Назад из подтверждения | Esc возвращает в форму и отменяет подготовленное выполнение |
| Переход из меню аддона | F7 открывает действия соответствующего модуля после штатного закрытия инвентаря |

`business-state.json` содержит проверенные сохранённые данные синтетической компании и совета. Приглашение, роль и министр первоначально проверялись на промежуточных JAR 0.6.0; после этого изменены только отступы текста подтверждения и передача серверной темы. Их сохранённое состояние перепроверено на финальном сервере. Принятие приглашения, светлая тема и маленькое окно проверены на финальных клиентском и серверном JAR; их хеши указаны в `harness-release.log` и `build-artifacts.json`.

Перед проверкой принятия приглашение обновлено обычной командой владельца тестовой компании, поскольку исходное приглашение истекло за время тестирования. Создание первоначального приглашения через форму проверено отдельно.

## Опциональность мода и плагина

Оба сценария повторены с финальными JAR 0.6.0:

- Настоящий vanilla-клиент без Fabric и CraftoUI подключился к серверу со всеми аддонами и открыл `/orders` обычным инвентарным меню. Снимки: `runtime/vanilla-without-mod.png`, `runtime/vanilla-orders.png`.
- Fabric-клиент с CraftoUI подключился к серверу с нулём плагинов. Нажатие M показало «На этом сервере CraftoUI недоступен», игрок остался в мире. Снимок: `runtime/fabric-without-server-plugin.png`.

В финальном журнале стенда есть `COMPATIBILITY COMPLETE` и штатное завершение. Суффикс `050` в именах двух тестовых профилей — историческое имя каталога; загружены финальные байты 0.6.0.

## Границы результата

Не проходились все экономические, боевые, административные и межрегиональные ветви всех 54 команд. Не проверялись реальные платежи, нагрузка, рабочий сервер пользователя, Windows, установка в GML/Pterodactyl, прокси и онлайн-авторизация. У команды без TabCompleter остаётся ручной ввод аргументов внутри UI.

Ранние итерации графического стенда включали неверные клики автоматизации, преждевременную проверку до назначения министра и таймаут ожидания загрузки шрифта клиента. Эти попытки не объявлены успешными; последующие завершённые сценарии и финальные журналы отделены от них. Предупреждения об отсутствующем аудиоустройстве, OSHI, недоступных Mojang/Realms и экономическом адаптере относятся к изолированной среде. Исторические отчёты прежних версий не означают их полного повторного прогона на 0.6.0.

В серверном журнале также сохранены ошибки фоновых задач Towny/Taxes без EconomyAdapter и предупреждение Folia Watchdog о задержке глобального региона. Стенд продолжил работу; производительность и фоновые экономические задачи не считаются проверенными этим прогоном.
