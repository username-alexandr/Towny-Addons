# Финансы города — CraftoUI 0.8.12

В экран города добавлены «Расходы города», «Поступления» и «Итог за неделю». Положительный итог выделяется зелёным, отрицательный — красным. Подпись явно показывает отчётный период. Нажатие на карточку открывает казну с суммами и понятными категориями расходов.

## Что именно считается

Используется **текущая отчётная неделя TreasuryPlus: с понедельника 00:00 UTC**. Если учёт города начат позже, в подробностях указано фактическое начало. В новой неделе итоги начинаются заново; предыдущая неделя не подставляется вместо текущей.

- Расходы — сумма фактически записанных списаний городского денежного счёта: содержание, строительство, налоги и другие операции.
- Поступления — записанные входящие платежи, включая взносы жителей и возвраты.
- Итог — поступления минус расходы за тот же период.
- Возвраты учитываются один раз. Категории бюджета не суммируются повторно с операциями. Перераспределение денег между статьями бюджета не является новым расходом.
- Расхождения между журналом и балансом показаны отдельно. При таких расхождениях или незавершённом списании выводится «Нужна сверка», без зелёного статуса благополучия.

Это **фактическое движение денег**, а не прогноз ежедневного содержания или будущей прибыли. Ресурсы склада не переводятся в деньги. Операции, не прошедшие через наблюдаемый счёт Towny, могут проявиться лишь как расхождение баланса; они не объявляются доходом/расходом без подтверждённой классификации.

Источник — публичный `TownyTreasuryApi.treasury(UUID)` и неизменяемые отчёты `CityLedger` / `Week`. Проверена структура настоящего `NeverLandTownyTreasuryPlus-0.1.18.jar` из Suite 0.43.0 и исходники коммита [f9e9caf](https://github.com/username-alexandr/Towny-Addons/commit/f9e9cafec75a6774577307ab24ef79d963810bab). Денежные значения обрабатываются целыми сотыми без преобразования через `double`.

## Доступность и права

Нужен установленный и работающий **NeverLandTownyTreasuryPlus** с указанным API. Дополнительно к `craftoui.use` / `craftoui.city` проверяются существующие права `neverlandtownytreasury.use` либо `neverlandtownytreasury.admin`. Показывается только собственный город игрока. Сервер повторно проверяет членство и права после асинхронного чтения.

Без права суммы не отправляются клиенту, переход недоступен. Если аддон отсутствует, учёт приостановлен, город ещё не учтён или формат данных не поддерживается, карточки показывают «Нет данных» и причину, а не нулевые расходы. Мод остаётся необязательным для входа на сервер.

Чтение выполняется через Folia AsyncScheduler при обновлении открытой городской страницы. Новый опрос каждого тика не добавлен. Код не вызывает списания, синхронизацию счёта, Vault, HTTP или БД; он только получает готовый снимок аддона. Данные могут отставать на интервал обновления казны и открытого экрана.

## Установка

Для этого обновления заменить **оба JAR CraftoUI**:

1. Полностью остановить Folia, заменить прежний серверный CraftoUI на `CraftoUI-Folia-26.2-0.8.12.jar` в `plugins/`, затем запустить сервер. Не использовать `/reload`.
2. В профиле NLT/GML заменить прежний мод на `CraftoUI-Fabric-26.2-0.8.12.jar`. Сохранить Minecraft 26.2, Java 25, Fabric API 0.161.0+26.2 и Fabric Loader **0.19.5+**. Полностью перезапустить игру.
3. Сохранить конфигурации и игровые данные. Для этой функции не требуется заменять остальные аддоны, если совместимый TreasuryPlus уже работает. Сам TreasuryPlus в комплект не входит.
4. Открыть «Экран города». Проверить период, суммы и переход в казну. Проверить отдельно игрока без права на просмотр казны.

Старый клиент игнорирует новый финансовый блок; для его отображения нужен новый мод. Новый клиент с прежним сервером продолжает показывать прежний экран. Протокол остаётся версии 1.

## Оформление

Блок располагается после основных показателей города. На широком окне карточки идут в ряд, на узком — друг под другом. Заголовок, «Назад» и нижние кнопки закреплены; колёсико прокручивает содержимое и страницы. Полные значения доступны в подсказках. В темах можно дополнительно задать цвета `positive`, `negative`, `warning` в формате `#AARRGGBB`; для существующих тем есть варианты по умолчанию с учётом светлого/тёмного текста.

## Реально выполненные проверки

- Сборка клиента, сервера и API: Java 25.0.2, Gradle 9.0.0, настоящие зависимости Minecraft/Fabric/Paper. Gradle Wrapper включён; сборка выполнена локальным Gradle через документированный `-PdirectMinecraft`.
- Сервер: 129 JUnit-тестов, включая 16 финансовых сценариев. Общий модуль: 81 тест. Ошибок, пропусков и падений нет. Общие тесты прошли при первом прогоне этого изменения; при финальной серверной пересборке задача была `UP-TO-DATE`.
- Финансовые проверки: возвраты, дефицит, нулевой поток, граница недели UTC, неполная неделя, отсутствие/ошибка API, переполнение, некорректные суммы, расхождения, ожидающий платёж, права и отсутствие утечки сумм, ограничение размера ответа.
- UI на настоящих классах с явными двойниками Minecraft/транспорта: 848 финансовых проверок и 48 изображений, две темы и четыре размера GUI. Проверены доступность карточек при прокрутке и фокусе, запрет повторного действия, переход по серверному идентификатору, разные состояния результата.
- Повторены существующие UI-проверки: 19 жизненного цикла, 95 городских страниц, 161 личных вкладок/форм, 110 колёсика/окна и 400 новых меню.
- Настоящий JAR TreasuryPlus проверен на наличие используемых публичных методов; исходники проверены на отсутствие записи/экономических вызовов в `treasury()`.
- Выпускные JAR и архив проверены на ZIP CRC, метаданные версии и отсутствие тестовых классов. Протокол и опциональность мода не изменены.

Логи, JUnit XML и изображения находятся в `validation/0.8.12/`. Числа на изображениях — тестовые примеры. **Графический Minecraft, Windows/GML и живой сервер с вашей экономикой в этом прогоне не запускались.** Поэтому сверка с реальными операциями после установки остаётся необходимой.
