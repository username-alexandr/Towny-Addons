## Реальный Folia с тестовыми игроками

Отдельный сервер Folia **26.2 build 7, 14b7fee** запущен на `127.0.0.1:25594`, без production-данных. Плагины: Towny **0.103.2.0**, Builds **0.8.29**, Contracts **0.3.23**, собранный CraftoUI **0.7.2**. Итог: **PASS 23 assertions**, сервер завершился с кодом 0.

Проверены:

1. Запуск CraftoUI и Contracts, открытие настоящего `PublicOrders.Board` кнопками главного меню и раздела работы.
2. Выдача подсказки нативного оформления вместо перехода в CIVIC.
3. Возврат «Назад» к главному меню без повторного выполнения `/orders`.
4. Отказ при потере разрешения и при неверном токене сессии.
5. Поиск ведёт в тот же `/orders`; отсутствующий аддон не предлагается; токен перехода расходуется.
6. `/orders` из события чат-команды не перехватывается ни для тестового клиента с поддержкой CIVIC, ни без мода.
7. Игрок без согласования протокола получает обычный инвентарь без custom payload.
8. Код навигации обращается к EntityScheduler игрока.

Лог, список проверок и результат: `validation/navigation-0.7.2/runtime/`. Хеши участников и тестового плагина: `validation/navigation-0.7.2/artifacts.json`. Исходник стенда: `tools/runtime-navigation-probe/`; собранный тестовый плагин не входит в комплект установки.

Player, InventoryView и EntityScheduler — явные тестовые объекты. Их задачи выполняются на глобальном планировщике Folia. Командный обработчик Contracts, создание доски, события инвентаря, декодирование пакетов, права, история и токены CraftoUI настоящие. Такой стенд не подтверждает потоковую безопасность для подключённого игрока и не заменяет проверку Minecraft-клиентом.

В журнале есть ошибка получения публичного ключа Mojang из-за недоступного DNS и предупреждения окружения. Стенд работает offline только на loopback; проверка online-аутентификации в него не входит. На предварительных прогонах были исправлены состав зависимостей стенда и отсутствующий метод тестового планировщика; результаты выше относятся к окончательному прогону.
