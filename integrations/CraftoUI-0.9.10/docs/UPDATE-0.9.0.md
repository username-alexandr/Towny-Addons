# CraftoUI 0.9.0 — UI для NeverLandTowny Suite 0.52.1

Собраны клиентский Fabric-мод и серверный Folia-плагин для Minecraft 26.2. База: выпущенная 0.8.20 и серверный планировщик 0.9.0-dev; исправления возврата, обновления, размещения, стилей зданий и совместимости Loader сохранены.

Целевой комплект аддонов — `NeverLandTownySuite-0.52.1-Ransom-Playtest-2026-10-30.zip`, исходный commit `45d4efeeee2aeba721b8ba44a46de1ee766df0d3`. Он остаётся playtest-комплектом. Этот выпуск обновляет CraftoUI и не меняет код аддонов.

## Что добавлено

- В «Город → Развитие города» появилась кнопка «План развития». Он также доступен из сводки города и поиска.
- План рассчитывает цепочку зависимостей для восьми выбранных целей: уровни зданий, общую стоимость, сданные материалы, склад, недостающее снабжение, участки, содержание и энергоснабжение. Источники — публичные API Builds/Upkeep/Power. Неполные данные явно помечаются.
- Из снабжения можно открыть закупки: котировка, подтверждение оплаты, публикация, сохранённые заявки, сверка состояния и отмена с возвратом. Количество, цена, город и ID выбираются сервером. Деньгами и SQLite управляют Contracts/TreasuryPlus.
- Подключено 21 новое окно аддонов: жители и районы, производственные партии, технологические лицензии, экология районов, мастерские заказы, лимитные заявки, квитанции казны, гости лагеря, реставрация, сценарии событий, общие стройки, главы летописи, сезонные обмены, заявления в гражданство, поручения и лимиты расходов, программы кандидатов, взаимопомощь, патрули, судебные материалы, тактика армии.
- Добавлены 32 готовые формы действий, всего 102 формы в 41 модуле. Включены выкуп за рейд, лимитная покупка/продажа, гости лагеря, предложение лицензии, поручения и ограничения расходов. Исходный обработчик аддона окончательно проверяет параметры и полномочия. Остальные зарегистрированные команды по-прежнему доступны через общую форму с подсказками.
- 30 быстрых ссылок для поиска/избранного, включая рыбалку, производство, лицензии, общие стройки, заявления, программы и новые военные разделы. Личные заказы по-прежнему ведут в `/orders`.
- В городской сводке четыре действия развития отделены от управления и событий. На широком GUI — четыре столбца; при увеличенном GUI Scale элементы перестраиваются. Заголовки и пиктограммы планировщика/закупок соответствуют разделу.
- Убрано пересечение подписи и полосы прогресса здания; лишний повтор статуса в карточке больше не рисуется.
- Сохранено чтение полного ID архитектуры и добавлена поддержка закреплённого набора чертежей Builds. Неизвестная схема или отсутствующий набор не заменяется другим зданием.

Новые нативные окна используют общий компактный рендерер, реальные предметы и слоты аддонов. Редкость предметов, правый клик, Shift, страницы и исходные подтверждения сохраняются. Для старых Builds оставлено распознавание `ContributionHolder`; в Builds 0.11.2 вклад жителей открывается через Chronicles.

## Установка в Crafto Launcher/GML и Pterodactyl

1. Закрыть игру и штатно остановить сервер. Сохранить папки настроек и данных.
2. В `plugins/` заменить прежний CraftoUI на `CraftoUI-Folia-26.2-0.9.0.jar`, оставить одну версию плагина.
3. В файлах клиентского профиля NLT в GML заменить мод на `CraftoUI-Fabric-26.2-0.9.0.jar`; пересчитать файловый манифест/контрольные суммы средствами вашей панели лаунчера. Fabric Loader оставить **0.19.4**, Java **25**. Проверка выполнялась с Fabric API **0.161.0+26.2**. Мод содержит исправленную MixinExtras 0.5.5; отдельный JAR MixinExtras устанавливать не требуется.
4. Если Suite 0.52.1 уже установлен, заменяются только обе части CraftoUI. Для планировщика/закупок нужны Builds 0.11.2, Contracts 0.8.1, TreasuryPlus 0.3.3; для новых форм выкупа — SiegesPlus 0.6.7. Отсутствующие необязательные аддоны не устанавливаются автоматически.
5. Существующую `plugins/CraftoUI/` сохранить. Стандартные конфиги обновляются автоматически с копией изменённых файлов в `backups/0.8.19/` или `backups/0.8.20/`. Существующие команды, подписи, темы, права и исключённые модули сохраняются. Если `menus/development.json` существенно изменён вручную, добавить кнопку с `action: "ui:planner"` по примеру из `config/menus/development.json`.
6. Запустить сервер и клиент. Открыть `/craftoui`, проверить развитие, снабжение, новые окна и действия из меню команд. Проверить Назад, Обновить, Esc, крестик и вход без CraftoUI. Для обычной перезагрузки конфигурации использовать `/craftoui reload`, не Bukkit `/reload`.

`CraftoUI-API-0.9.0.jar` нужен разработчикам интеграций; в папку plugins его устанавливать не нужно. Архив содержит оба рабочих JAR, API, исходники четырёх модулей, Gradle Wrapper, конфиги, темы, протокол и текущие результаты проверки. Аддоны, Minecraft, Fabric API, JDK и Gradle distribution в архив не включены.

Мод остаётся опциональным: без завершённого handshake сервер не отправляет команды CraftoUI и не подменяет меню игрока; обычные окна и команды аддонов продолжают работать. Новая настройка обязательного мода не вводится.

## Ограничения

- Полный графический Minecraft, вход реального игрока и живой Folia в этом прогоне не запускались. Bootstrap завершён намеренно до игрового окна. Работа на конкретной сборке сервера/лаунчера требует игрового прогона.
- Живой Vault-провайдер, реальные списания/возвраты и полный рестарт сервера в этом прогоне не тестировались. Исторические стендовые проверки ветки разработки сохранены в документации, но не включены в число текущих тестов.
- План персональный и хранится в сеансе; после выхода, смены города или перезапуска его нужно выбрать заново. Оплаченные закупки сохраняются аддонами независимо от плана.
- План показывает расчёт и открывает штатное управление зданием; автоматической очереди размещения/строительства нет. Закупки управляются действующим мэром с необходимыми правами. Прогнозы содержания и энергии зависят от наличия обновлённых Upkeep/Power и разрешений просмотра.
- При очень большом GUI Scale остаются страницы или локальная прокрутка; элементы управления Назад/Обновить/закрытие закреплены вне прокручиваемого содержимого.
- Точный текст, доступность и финансовые подтверждения новых нативных окон определяет аддон. Форма команды не обходит его проверки и может вернуть сообщение в чат. Этот выпуск не заменяет всю графику аддонов новыми изображениями.

## Сборка и исходники

Обычная сборка: `./gradlew :client:build :server:build :api:build :common:test` на JDK 25. Gradle Wrapper закреплён на 9.5.1 с проверкой SHA256. Клиент использует Fabric Loom 1.17.21.

На текущем хосте использована документированная сборка по официальному необфусцированному Minecraft 26.2: `python tools/prepare-direct-build.py <deps>`, затем `./gradlew -PdirectMinecraft=<deps> :client:build :server:build :api:build :common:test :server:writeUiTestClasspath`. Это реальные игровые классы и Fabric API; игровые классы не включаются в итоговый мод. Команда подготовки сверяет хеши Mojang. Точный вызов Gradle и журнал сохранены в проверке. В данном прогоне полный Loom build без directMinecraft не запускался.
