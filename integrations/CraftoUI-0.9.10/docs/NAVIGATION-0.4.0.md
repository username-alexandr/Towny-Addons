# CraftoUI 0.4.0: возврат и конкретные цели контрактов

Клиент и сервер обновляются вместе до **0.4.0**. Minecraft 26.2, Fabric Loader 0.19.4+, Fabric API 0.161.0+26.2, Java 25. Удалите старые CraftoUI JAR, установите новый серверный в `plugins/`, клиентский в `mods/` профиля GML и перезапустите сервер и игру. Существующие конфигурации не удаляйте: кнопка не требует дописывать её в каждый JSON.

## Поведение

- «Назад» в заголовке любого JSON-экрана CraftoUI, в карточках подключённых аддонов и рядом с предметной сеткой F6. **Backspace** выполняет тот же возврат; Esc закрывает. В настройках сохраняется собственная кнопка возврата к родительскому экрану.
- Общая история возвращает в предыдущий экран: например, Профиль → Город, либо Шаблоны контрактов → Городские контракты → Заработок. В корне показывается «В игру». Существующая нижняя кнопка «Назад» профиля тоже использует историю. «Все разделы» остаётся явным переходом на главный экран.
- Сервер связывает одноразовый токен перехода с игроком, текущим экраном и историей. Проверяются права, время жизни и живой инвентарь. Предмет на курсоре сначала нужно положить в ячейку. Право `neverlandtownybuilds.admin.editor` заново проверяется при возврате в редактор Builds.
- Штатная кнопка аддона вызывается обычным Minecraft container input. Если требуется запасной возврат, открывается прежний живой read-only Inventory. Предметы не копируются, команды покупки/принятия/выдачи не повторяются. Изменяемые склады и ресурсные редакторы старыми экземплярами не восстанавливаются.
- HUD берёт конкретную цель из сохранённого `target` личного `/orders`: «Сдать: Бутылочка мёда», «Добыть: Руда незерского кварца», «Победить: Утопленник», для рыбалки — «Поймать». Названия переводит Minecraft, длинная подпись переносится на две строки. Прогресс остаётся настоящим счётчиком аддона или количеством предметов в инвентаре для поставки.

## Выполненные автоматические проверки

**40 JUnit-тестов; 0 ошибок, 0 пропусков.** Протокол — 7, схема меню — 5, HUD — 8, конфиги — 4, каталог — 4, история — 4, чтение личных заказов — 8. Новые проверки охватывают возврат через разные виды экранов, обновление предка без циклов, ограничение истории, передачу цели/типа, старый формат HUD и сохранение всех четырёх типов цели. XML: `validation/navigation-0.4.0/junit/`.

**26 протокольных сценариев на настоящем Folia:** 15 прежних сетевых сценариев и 11 новых сценариев навигации. Проверены вход без UI-канала, несовместимый протокол без отключения от игры, поддельные сессии, повтор действий, реальные данные игрока, чужой и старый токен BACK, возврат в фактический родительский JSON-экран, закрытие корня, запрет возврата после потери прав и разрешённый возврат после восстановления прав. Отдельно выполнены открытие настоящего Builds Editor и запрет возврата в него после deop. Эти клиенты проверяют сетевое поведение; они не рисуют интерфейс.

Результаты: `validation/navigation-0.4.0/protocol/smoke-results.json` и `navigation-results.json`. Минимальный протокольный клиент требует отключённого сжатия; тестовый запуск временно ставит `network-compression-threshold=-1` и восстанавливает исходное значение. Это условие стенда, не требование CraftoUI.

Сборка `release` выполнена JDK 25 / Gradle 9.5.1 через `-PdirectMinecraft` с оригинальными классами Minecraft и Paper API. Проверены CRC каждого JAR, metadata 0.4.0, Loader ≥0.19.4, class major 69 и отсутствие ApiProbe в выпускных JAR. Контрольные суммы — `release/SHA256SUMS.txt`; журнал и машинные результаты — `validation/navigation-0.4.0/`.

## Графическая проверка выпускных JAR

На стенде установлены именно JAR с хешами из `jar-checks.json`. В `screenshots/` находятся реальные снимки клиента; это не макеты.

- Главное меню → Город → Профиль → новая «Назад» → Город.
- Заработок → Городские контракты → Шаблоны → F6 → новая кнопка рядом с инвентарём → Городские контракты → Заработок. Backspace возвращает на главный экран.
- Настройки → собственная кнопка «Назад» → исходный главный экран. «В игру» закрывает корень. Отдельно `/orders` → «В игру», без падения.
- Город → категории Builds → Управление → Ратуша → «Назад» → список → категории → Город. Штатные переходы Builds выполняются обычными container input.
- Склад из списка Builds: новая кнопка доступна в предметном режиме. При удержании предмета на курсоре окно не закрывается. 8 бутылочек мёда помещены в склад, выполнен возврат, склад снова открыт: все 8 в первой ячейке. Предметы затем возвращены в инвентарь; HUD снова показывает 8/32.
- Builds Editor → редактор Ратуши → ресурсы → «Назад» → редактор Ратуши → индекс редактора → игра. Для ресурсов проходит штатный `resource_back`, без сохранения изменений и без переоткрытия старого ресурсного инвентаря.
- Реальные активные личные заказы Contracts 0.3.21: мёд 8/32, кварцевая руда 0/48, утопленники 0/16. Подпись руды занимает две строки без пересечения с прогрессом. Заказы приняты штатными `/orders accept`, предметы выданы консолью только тестовому игроку. Добыча, убийства и выплаты в этом прогоне не выполнялись.

При проверке разрабатываемой версии найдено выбрасывание предмета на отпускании мыши над навигационной кнопкой. Выпускной AddonScreen поглощает нажатие, перетаскивание и отпускание этой кнопки; повторная проверка с предметом и сохранением склада пройдена. Снимок до исправления отдельно помечен `regression/development-before-release-fix.png` и не является результатом выпускного клиента.

## Границы проверки

Графическая среда: Linux, Xvfb/Mesa, Minecraft 26.2, Fabric Loader 0.19.4, Fabric API 0.161.0+26.2, Folia 26.2 build 7; Towny 0.103.2.0, Builds 0.8.27, Contracts 0.3.21. Окно 1280×900, русский язык, GUI Scale 2, размытие включено. Стенд изолированный и локальный, с тестовыми игроками и городом. Точные хеши: `environment.json` и `jar-checks.json`.

Все 54 класса и все бизнес-ветви 38 модулей в этом выпуске заново не проходились. Содержимое старого безопасного Inventory может обновляться только самим аддоном. Для неизвестного пути, требующего восстановления изменяемого редактора без штатного возврата, показывается просьба открыть редактор заново. После серверного reload нативное окно аддона нужно переоткрыть для новой истории. Не проверены боевой сервер, Windows/GML, ресурс-паки пользователя, выплаты и экономические транзакции.

HUD охватывает личные `/orders` Contracts 0.3.20/0.3.21, а не общий прогресс городских `/town contracts`. Фактический графический прогон этого выпуска использует 0.3.21. Проверка 0.3.20, vanilla-клиента и сервера без CraftoUI сохранена в исторических отчётах 0.3.0/0.2.1; это не повторная графическая проверка этих сочетаний на 0.4.0.

Итоговый клиент оставался подключённым до штатного завершения стенда. В журналах нет исключений CraftoUI, ошибочных payload или повторного blur. Ошибки недоступных внешних auth/Realms и отсутствие аудиоустройства относятся к изолированной среде; звук, online-auth и Realms не объявляются проверенными. Машинный перечень графических сценариев: `validation/navigation-0.4.0/graphical-results.json`.
