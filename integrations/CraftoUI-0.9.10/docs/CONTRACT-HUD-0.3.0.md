# Панель личных контрактов — CraftoUI 0.3.0

Панель выводит взятые личные заказы `/orders` из **NeverLandTownyContracts 0.3.20** справа по центру игрового экрана. Это работающий HUD Fabric с данными Folia. Примеры в `validation/hud-0.3.0/` — снимки настоящей игры.

## Поведение

- Название задания переносится на две строки; длинное продолжение сокращается многоточием.
- Поставка: количество подходящих предметов в основном инвентаре / цель. Охота, добыча и рыбалка: прогресс, сохранённый исходным аддоном / цель.
- Полоса прогресса и зелёное «Готово к сдаче» при достижении цели. Сдача выполняется штатными средствами `/orders`, автоматически предметы не списываются.
- Если аддон зарезервировал сдачу/награду, показывается статус обработки. Выплаченные, отменённые и закрытые заказы убираются.
- До трёх заданий на странице. **J** перелистывает; **H** показывает/скрывает. Клавиши можно переназначить. В настройках CraftoUI есть видимость и масштаб панели.
- При открытом меню или чате, F1, отсутствии заданий, отключении от сервера или устаревшем состоянии панель скрывается. Она не захватывает курсор и не вызывает размытие.

После обновления нужны **оба CraftoUI JAR 0.3.0**. Fabric Loader **0.19.4+**, Fabric API **0.161.0+26.2**, Minecraft/Folia **26.2**, Java **25**. Подробные шаги для GML и Pterodactyl: [INSTALL.md](INSTALL.md). Старые конфиги сохраняются, новые клиентские поля получают значения по умолчанию.

## Источник и безопасность данных

Установленный аддон 0.3.20 не предоставляет публичного метода снимка личных `/orders`. Его публичный API городских контрактов относится к другой модели. Поэтому используется отдельный адаптер **только для чтения** атомарных `public-orders.yml` и `order-payments/<UUID>.properties`. Версия аддона проверяется явно. JAR, данные и бизнес-логика аддона не изменяются; отражение приватных полей не используется.

Одна асинхронная задача раз в две секунды читает ограниченный снимок для всех согласовавших возможность клиентов. Без такой аудитории чтений нет. Основной файл ограничен 16 МиБ, одна запись платежа — 256 КиБ. После чтения права и инвентарь каждого игрока проверяются на его **EntityScheduler**. Очередь задач объединяется, повторный параллельный опрос исключён. Нет БД/HTTP и файлового ввода-вывода на игровом потоке.

Сервер проверяет `craftoui.use`, `craftoui.contracts` и `neverland.orders.use`. Игрок получает только собственные заказы. Для поставок используется тот же принцип сравнения ItemStack, что у исходного аддона: основной инвентарь, `isSimilar` обычному предмету целевого материала; броня, вторая рука и изменённые варианты не засчитываются.

Клиент объявляет `contracts-hud-v1`. Новое сообщение 9 отправляется только с этой возможностью, при изменении или раз в восемь секунд. Через 20 секунд без обновления клиент скрывает состояние. Формат описан в [PROTOCOL.md](PROTOCOL.md). Старые коды 0–8 не изменены; получение данных не даёт клиенту права увеличивать прогресс или выдавать награды.

Сборка произведена настоящими JDK Azul 25.0.2 и Gradle 9.5.1 с оригинальными библиотеками Minecraft 26.2, через документированный `-PdirectMinecraft`. Все три выпускных JAR созданы Gradle. Финальная задача `release` завершилась успешно; неизменившиеся задачи в сохранённом финальном логе имеют `UP-TO-DATE`. Хеши клиентского и серверного выпускных JAR совпадают с JAR, реально загруженными в этом графическом прогоне. Картинки проверены визуально; это не автоматическое распознавание пикселей. Harness требует отдельно подготовленных оригинальных runtime-зависимостей и не устанавливается на сервер.

В логах оставлены ограничения среды: нет аудиоустройства, не доступны сервисы авторизации/Realms, системная библиотека не получает сведения о процессах; при создании flat-world есть сообщение Minecraft `No key layers`. Клиент продолжал работать, стенд остановлен штатно. Эти сообщения не описываются как «полностью чистые логи».

## Границы проверки и выпуска

Экономический провайдер отсутствовал: настоящая выплата награды не проверена. Полные игровые цепочки добычи, охоты и рыбалки не проходились; чтение засчитанного числового прогресса проверено модульно. Пагинация J при более чем трёх заданиях и все масштабы/разрешения графически не проверялись. На стенде установлен штатный лимит аддона — три активных заказа.

HUD сейчас относится к личным `/orders`; городские `/town contracts` и контракты других модулей сюда не включены. Таймер, перемещение панели мышью и отдельные темы HUD отсутствуют. Неизвестная версия аддона отключает адаптер, а не подменяет данные.

Проверки vanilla/отсутствия серверного CraftoUI из 0.2.1 и исправления двойного размытия из 0.2.2 сохранены как исторические. Они не объявляются новым полным регрессионным прогоном на 0.3.0. Полный модпак пользователя, Windows/macOS, WAN/прокси, нагрузка, установленный LuckPerms с БД и реальные панели GML/Pterodactyl не проверены.

Оформление кнопок из предложенных пользователю визуальных вариантов в этот выпуск не включено: выбор стиля ещё не сделан.
