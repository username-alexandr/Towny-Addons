# Архитектура и потоки

`common` не зависит от Minecraft/Bukkit: кадр, схема UI, подстановки, admission control. `api` описывает контракт интеграции. `server` владеет регистрациями, данными, правами и сессиями. `client` рисует универсальный `MenuScreen` по переданной схеме и `AddonScreen` поверх исходного ChestMenu для известных меню аддонов.

Дизайн находится в menu/theme JSON/YAML и ресурсах. Серверное действие связано с `component.id` через его собственное определение. Смена координат, цветов, текстур или подписей не меняет серверную бизнес-логику. Новый экран из поддерживаемых компонентов не требует клиентского Java-класса.

| Работа | Исполнение |
|---|---|
| Чтение состояния игрока, права, открытие, payload, обработка клика | EntityScheduler игрока |
| Периодическое обновление открытого меню | EntityScheduler, раз в 20 тиков, отмена при закрытии/выходе |
| Перечитывание конфигов и внешние data providers | AsyncScheduler |
| Возврат async-результата | Снова EntityScheduler с проверкой сессии |
| Ответ в консоль из async reload | GlobalRegionScheduler |
| Изменение блоков/чужих регионов | В MVP отсутствует; интеграция использует RegionScheduler по координатам |

Протокольные входы допускаются через ограничитель до планирования. Конфиги после чтения публикуются одним объектом каталога; ошибка загрузки не заменяет рабочий каталог. API-регистрации и подключения хранятся в concurrent maps. Состояние конкретного открытого меню меняется на потоке его игрока.

Не используются `BukkitScheduler`, NMS на сервере, прямой OpenGL, повторяющиеся HTTP/БД-запросы, синхронные внешние запросы на игровых потоках. Для рендеринга используется Minecraft `GuiGraphicsExtractor` и стандартный рендер предметов/сущностей.

Первая версия ограничивает размер одного экрана вместо сетевой фрагментации. Это оставляет протокол простым и проверяемым; большие каталоги можно разделять на отдельные конфигурационные страницы. Развитие протокола должно менять согласуемую версию, если нарушается совместимость.

## Инвентарные меню NeverLandTowny

`AddonCatalog` — неизменяемый, проверяемый каталог владельцев/классов/команд. `AddonBridge` слушает InventoryOpenEvent на MONITOR без изменения события. Для разрешённого chest-инвентаря он отправляет разовую подсказку на следующем EntityScheduler-тикe игрока. Чужие региональные сущности и мир он не читает. Опрос каждого инвентаря каждый тик не нужен: слоты синхронизирует Minecraft.

Клиент заменяет только представление ContainerScreen и сохраняет исходный ChestMenu. Карточка хранит raw slot, поэтому фильтрация пустых наполнителей и клиентские страницы не меняют индекс серверного действия. Нативный режим сохраняет обработку drag, hotbar и предметных переносов базового ContainerScreen. Предмет на курсоре принудительно возвращает этот режим.

У моста нет hard-dependency на Towny/аддоны. Их меню и обработчики не копируются в CraftoUI. Это позволяет применять общую тему ко всем вкладкам поддержанного InventoryHolder, сохраняя обновления данных, оригинальные подтверждения и права. Смена внутреннего класса в будущей версии аддона требует обновления allowlist; неизвестный класс остаётся обычным меню.
