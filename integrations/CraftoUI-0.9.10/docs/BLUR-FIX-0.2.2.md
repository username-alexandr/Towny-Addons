# CraftoUI 0.2.2 — исправление падения меню при размытии

Клиент **0.2.2**, сервер/API **0.2.0**, Minecraft **26.2**, Fabric Loader **0.19.4+**, Fabric API **0.161.0+26.2**, Java **25**.

## Причина

В клиенте 0.2.1 при открытии `/orders` с включённым параметром CraftoUI `blur` возникало `IllegalStateException: Can only blur once per frame`. Стек указывал на `AddonScreen.extractRenderState`.

В Minecraft 26.2 метод `Screen.extractRenderStateWithTooltipAndSubtitles` последовательно вызывает `extractBackground`, затем `extractRenderState`. В режиме карточек AddonScreen запрашивал размытие в обоих методах. В результате второй вызов в том же кадре завершал игру. Ошибка воспроизведена на клиенте только с Fabric API и CraftoUI, без остальных модов пользовательской сборки. Она зависит от включённого размытия, поэтому первоначальная работа с настройкой по умолчанию `blur=false` могла проходить нормально.

## Исправление

- Размытие и затемнение выполняются только в `extractBackground`, один раз за кадр.
- Выбор режима карточек/ячеек перенесён до отрисовки фона, чтобы фон и содержимое использовали один режим в текущем кадре.
- Фон обычных ячеек рисуется только в режиме инвентаря; за карточками больше нет лишней сетки инвентаря.
- Автоматическое отображение переносимого предмета и возврат после отменённого аддоном клика сохранены.

Изменены `AddonScreen.java` и версия клиента. В сравнении JAR 0.2.1/0.2.2 отличаются только `AddonScreen.class` и `fabric.mod.json`. Серверный код, протокол и API не изменялись; серверный плагин обновлять не требуется.

## Проверка

Изолированный стенд: настоящий Minecraft 26.2, Fabric Loader 0.19.4, Fabric API 0.161.0+26.2, Folia 26.2 build 7, Linux/Xvfb/Mesa, JDK 25.0.2. Использован локальный offline mode; рабочий сервер не изменялся. Размытие Minecraft задано ненулевым (`menuBackgroundBlurriness:5`).

1. Контрольный запуск старого клиента 0.2.1: `/orders` при `blur=true` воспроизводит тот же краш с тем же стеком AddonScreen.
2. Клиент 0.2.2: `/orders` при `blur=true`, F6 в ячейки и обратно, клик по карточке и три повторных открытия.
3. Настоящее меню `/town builds` и вложенная категория при включённом размытии.
4. Тестовое меню: отменённый сервером обычный клик; журнал подтверждает `NATIVE_CLICK slot=0 click=LEFT owned=true`.
5. Тестовый склад: прямое открытие ячеек, F6 в карточки, подбор предмета и автоматический переход обратно в ячейки.
6. Инвентарь вне каталога CraftoUI остаётся обычным контейнером.
7. Главное конфигурационное меню M, переход в настройки, выключение размытия через интерфейс, возврат, `/orders` в карточках и ячейках при `blur=false`.
8. После всех действий клиент остаётся подключённым и выполняет `/list`.

Результаты и контрольная сумма проверенного JAR: `validation/blur-fix-0.2.2/results.json`. Там же находятся сценарий `blur_regression.py`, журнал сборки, журналы клиента/сервера, контрольный краш **старой** версии и снимки экранов. Наличие контрольного crash report в этом каталоге ожидаемо и не относится к 0.2.2. Сценарий привязан к локальному стенду и тестовому серверному ApiProbe; он не является установщиком. ApiProbe нельзя устанавливать на рабочий сервер.

Предыдущие проверки Loader и подключения без мода/без плагина относятся к 0.2.1: [COMPATIBILITY-0.2.1.md](COMPATIBILITY-0.2.1.md). Для 0.2.2 они целиком не повторялись: изменены только отрисовка AddonScreen и версия. Исторические модульные/сетевые проверки сохранены отдельно и не выдаются за новый прогон.

## Установка

1. Полностью закрыть игру.
2. Заменить старый клиентский CraftoUI в `mods/` на `CraftoUI-Fabric-26.2-0.2.2.jar`. Оставить только одну версию мода.
3. Если мод доставляется через GML, заменить файл профиля и синхронизировать клиент, затем перезапустить лаунчер/игру.
4. Размытие можно оставить включённым. Конфиги меню и серверный CraftoUI 0.2.0 сохраняются.

До установки исправления временный обход: при закрытой игре установить `"blur": false` в `config/craftoui.json`. Не требуется сбрасывать остальные настройки.

## Границы проверки

Не проверялась полная пользовательская сборка Windows с Iris/Sodium/OptiGUI/JourneyMap и голосовыми модами, её ресурс-пак и конкретный рабочий сервер. Исправление проверяет воспроизведённый сбой AddonScreen. Платежи, выполнение всех типов контрактов и все ветви бизнес-логики NeverLandTowny заново не проверялись. В стенде нет провайдера экономики; связанные с этим предупреждения аддонов сохранены в журнале. Клиентский журнал также содержит ошибки недоступного аудиоустройства и формы курсора X11 в виртуальном дисплее; игра продолжила работу, отчёта о краше 0.2.2 нет. Остальные ограничения: [LIMITATIONS.md](LIMITATIONS.md).
