# CraftoUI 0.8.13 — Fabric Loader 0.19.4

Минимальная версия Fabric Loader возвращена на **0.19.4**. Клиент пересобран с этой версией. Minecraft остаётся 26.2, Java — 25, Fabric API — 0.161.0+26.2. Финансы города и остальные функции 0.8.12 сохранены. Серверный плагин и API остаются **0.8.12**.

## Исправление MixinExtras без обновления Loader

CraftoUI включает официальный `mixinextras-fabric-0.5.5.jar` как вложенный JAR через стандартное поле `jars` в `fabric.mod.json`. Зависимость `mixinextras >=0.5.5` заставляет Fabric выбрать исправленную библиотеку вместо встроенной в Loader 0.19.4 версии 0.5.4. Отдельно ставить MixinExtras не требуется. Классы библиотеки не смешиваются с классами CraftoUI.

Это сохраняет исправление известной несовместимости `@Redirect`, скомпилированных с Fabric Mixin 0.17.4, не повышая требование к загрузчику. Изменение касается клиентской упаковки и зависимостей; классы CraftoUI сравниваются с выпуском 0.8.12 побайтно.

Официальные сведения:

- [Fabric: вложенные JAR](https://docs.fabricmc.net/develop/loader/fabric-mod-json)
- [MixinExtras 0.5.5: исправление Redirect](https://github.com/LlamaLad7/MixinExtras/releases/tag/0.5.5)

## Установка

1. Закрыть Minecraft.
2. В `mods/` профиля NLT удалить прежний **клиентский** CraftoUI и установить `CraftoUI-Fabric-26.2-0.8.13.jar`. Оставить только одну версию CraftoUI.
3. Fabric Loader **0.19.4** оставить. Fabric API, Minecraft и Java не менять. Сохранить пользовательские настройки.
4. Перезапустить игру. В журнале ожидаются `fabricloader 0.19.4`, `craftoui 0.8.13`, `mixinextras 0.5.5`.

Если сервер уже обновлён для финансов города, **CraftoUI-Folia-26.2-0.8.12.jar заменять не нужно**. Он включён в полный архив в неизменном виде. Если ещё стоит прежний сервер 0.8.5, для финансов требуется сервер 0.8.12 из предыдущей поставки/полного архива. Мод остаётся опциональным для подключения.

## Проверки и границы

Выполнено:

- Реальная сборка `:client:build :common:test` с Loader 0.19.4 на Java 25.0.2 / Gradle 9.0.0: `BUILD SUCCESSFUL`. Все 81 JUnit-тест общего модуля прошли.
- Настоящий Knot запущен с Minecraft 26.2, Loader 0.19.4, Fabric API 0.161.0+26.2 и выпускным CraftoUI 0.8.13. Проверено разрешение вложенной библиотеки и загрузка именно реализации MixinExtras 0.5.5.
- `ContainerEventHandler` загружен через `KnotClassLoader` без прежнего сбоя; проверка завершена до открытия игрового окна.
- На Loader 0.19.4 проверен преобразователь MixinExtras: старая 0.5.4 воспроизводит исключение на свежем `@Redirect`, встроенная 0.5.5 обрабатывает его. Проходят одиночные и массивные `@At`, `NEW` и несколько точек инъекции.
- Все классы клиента и общего модуля побайтно совпадают с выпуском 0.8.12. Изменены метаданные, добавлен официальный вложенный JAR; его SHA-256 сверена с официальным артефактом. Лицензия сохранена внутри библиотеки и в `docs/MIXINEXTRAS-LICENSE.txt`.
- Серверный JAR и API 0.8.12 сохранены побайтно. Выпускные архивы проверены на целостность и отсутствие тестового bootstrap-мода.

Текущие результаты находятся в `validation/0.8.13/`. Проверка загрузки использует настоящий Knot/Fabric Loader, Minecraft и Fabric API. Отдельный тестовый `preLaunch`-мод завершает процесс **до открытия игрового окна** после проверки версий и преобразования `ContainerEventHandler`. Этот тестовый мод не входит в выпускной JAR.

Дополнительно проверяется настоящий обработчик MixinExtras на `@Redirect`, скомпилированном против Fabric Mixin 0.17.4, контрольные суммы вложенной библиотеки и неизменность классов CraftoUI относительно 0.8.12. Общие JUnit-тесты запускаются при сборке.

Это не полный прогон игры с набором модов NLT пользователя. Графический запуск, игровой процесс и GML в Windows отдельно не проверены. Серверные и UI-проверки из `validation/0.8.12/` относятся к прошлому выпуску и не выдаются за новый прогон.
