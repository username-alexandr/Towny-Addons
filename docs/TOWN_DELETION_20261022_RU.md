# Удаление города: Control 0.4.7 и Builds 0.8.28

## Установка

1. Полностью остановите Folia. Сохраните резервную копию миров, `plugins/Towny`, `plugins/NeverLandTownyControl` и `plugins/NeverLandTownyBuilds`.
2. Замените старые JAR Control и Builds файлами из этого обновления. Не оставляйте две версии одного плагина. Остальные аддоны заменять не требуется.
3. Запустите сервер. Не используйте `/reload` или горячую подмену JAR для этой миграции.
4. Проверьте `/nltadmin towns` на тестовом городе. Существующие данные городов и зданий сохраняются.

**Изменение поведения Towny:** Control выключает во всех загруженных мирах штатные `revertunclaim`, удаление блоков при снятии привата и удаление сущностей при снятии привата. Исходные значения и остановленная очередь отката записываются в `NeverLandTownyControl/town-removal/worlds-before-protection.yml`. Обычное снятие участков с привата и автоматическое удаление города теперь сохраняют территорию. Откат выполняется только отдельным подтверждённым планом. При отключении Control старые разрушительные настройки автоматически не включаются.

Не включайте штатный откат параллельно этой системе: проверка перед удалением откажет в операции, если обнаружит включённые настройки. Чтобы откатить само обновление, сначала остановите сервер и разберите незавершённые операции; старые значения настроек можно восстановить вручную из сохранённого файла. Простая замена JAR назад не возвращает эти настройки.

## Команды и меню

| Действие | Команда / кнопка |
| --- | --- |
| Удаление мэром с предупреждением об откате базы | `/town delete` (также `/t delete`) |
| Административное меню | `/nltadmin` → «Удаление городов» → город |
| Сохранить обычные базы; убрать только зарегистрированные здания Builds | `/nltdelete <город> registered` |
| Удалить город с откатом территории к сохранённому снимку | `/nltdelete <город> full` |
| Подтвердить | Кнопка в чате или выданная командой строка `/nltdelete confirm <код>` |
| Отменить ожидающее подтверждение | `/nltdelete cancel` |
| Посмотреть результат / остановленную операцию | `/nltdelete status` |

`/town delete <город>` и `/townyadmin town <город> delete` также показывают предупреждение. Подтверждение действует 60 секунд, привязано к инициатору, мэру и набору участков. Перед фактическим удалением проверяются права, состав территории и весь план. Выход инициатора до завершения подготовки останавливает удаление. Повторное подтверждение не запускает вторую операцию.

Для администрации: OP либо `neverlandtownycontrol.towns.delete`. Общее право `neverlandtownycontrol.admin` включает новое право и доступ к меню. Отдельного права удаления достаточно для `/nltdelete`; для входа через `/nltadmin` необходимо также право самого меню. Мэр использует своё штатное право Towny `towny.command.town.delete`.

```text
/lp group admin permission set neverlandtownycontrol.admin true
# Или только команды удаления без полного меню:
/lp group moderator permission set neverlandtownycontrol.towns.delete true
```

## Что считается зданием из списка

Режим `registered` берёт сохранённые строительные площадки Builds, версию архитектуры, ориентацию и выполненный уровень. При незавершённом улучшении учитываются завершённый и целевой уровни. Удаляются только координаты блоков этих чертежей, находящиеся на территории удаляемого города, если их текущий материал совпадает с чертежом.

Весь прямоугольник здания, весь чанк или вертикальный столб не очищаются. Обычные базы вне списка, соседние города, изменённые игроком блоки другого материала и нижний слой мира сохраняются. У блока, перестроенного в том же месте из того же материала, нет отдельной истории происхождения: он всё ещё совпадает с чертежом. Если это важно для конкретной базы, сначала проверьте её границы и зарегистрированные площадки.

Контейнеры и другие `TileState` с дополнительными данными, сущности и системные блоки не удаляются этой операцией. Их содержимое не переносится и не восстанавливается из старого снимка. Поэтому после удаления чертежа могут остаться, например, сундуки и таблички. При отсутствии совместимого Builds режим `registered` отказывает до удаления города.

## Проверка полного отката

Для новых городов и новых участков Control сохраняет собственные полные снимки с UUID мира, города, временем привата и точной высотой мира. Для старых участков допускаются только полные снимки Towny версии 5, соответствующие текущей сетке и высоте. Отсутствующий, обрезанный, несовместимый снимок или неизвестное состояние блока останавливает подготовку: город и территория остаются на месте.

Снимок старого Towny не содержит надёжной истории всех владельцев. Полнота файла не доказывает правильность его содержимого. Для сомнительных старых участков используйте `registered`, предварительно сохранив резервную копию.

Параметры `plugins/NeverLandTownyControl/config.yml`:

```yaml
town-removal:
  maximum-plots: 256
  maximum-column-removals: 32
  maximum-changed-blocks: 1000000
```

Поддерживается сетка Towny 16×16. План с более чем 32 удаляемыми блоками в одном вертикальном столбце по умолчанию отклоняется. Это также может остановить легитимный демонтаж очень высокой постройки — сначала проверьте план и снимок, затем решите, менять ли ограничение. Порог проверяется до удаления города. Полоса из пяти столбцов до глубины мира не проходит такую проверку.

Если в Towny включены руины, план ожидает окончательного удаления. При восстановлении города из руин план отменяется. Казна, членство и прочие городские операции остаются ответственностью Towny.

## Рестарт и сверка

Планы и журнал сохраняются в `NeverLandTownyControl/town-removal/jobs/<ID>/`: `job.yml`, сжатые планы по участкам, контрольные суммы SHA-256. Каждый план содержит координаты и состояния блоков до/после. Они сохраняются до удаления города. Обработка идёт на региональном планировщике Folia порциями до 256 блоков.

После рестарта незавершённая подготовка отменяется. Подтверждённый план для уже удалённого города продолжается с сохранённого прогресса. Изменение применяется, только если блок всё ещё совпадает с зафиксированным состоянием «до». Уже выполненный шаг не повторяется; новая постройка другого состояния пропускается. Если участок занят другим городом, применение останавливается. На время активного плана штатные захват и освобождение его участков блокируются.

Состояние `REVIEW` означает остановку для проверки. Администратор проверяет журнал и мир, после чего выбирает:

```text
/nltdelete resume <ID>
/nltdelete abandon <ID>
```

`resume` допускается только при отсутствии удалённого города и наличии полного плана; контрольные суммы и владение участком проверяются повторно. `abandon` отменяет оставшиеся изменения, но не обращает уже выполненные. Команда `cancel` отменяет только ещё не подтверждённое предложение. Итоги доступны в отдельной категории «Удаление городов» административного журнала.

## Обнаруженное и границы исправления

Проверен исходный код Towny 0.103.2.0, соответствующий серверному стеку. Штатный `removeTownBlock` ставит весь участок в очередь отката и независимо может удалять перечисленные в конфигурации материалы. Штатный загрузчик снимка может вернуть неполный список блоков при EOF. Это опасные пути; обновление заменяет их проверяемым планом.

Точная причина уже наблюдавшейся полосы шириной пять блоков без серверных снимков, настроек мира и журнала удаления не установлена. Этот пакет не восстанавливает уже уничтоженную территорию: для неё нужна резервная копия или журнал изменений блоков. В Builds также добавлена проверка владельца при нормализации состояния блоков и пропуск записей удалённых городов при ремонте/миграции.

Результаты автоматических и серверных проверок находятся рядом, в `TOWN_DELETION_VALIDATION_20261022_RU.md`.
