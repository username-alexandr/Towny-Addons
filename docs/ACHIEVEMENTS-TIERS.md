# Ступени достижений города

В меню `/t achievements` добавлены разделы «Общие», «Торговля», «Производство», «Оборона» и «Культура». Есть отдельный список открытых наград. Каждая цель показывает ступень I–III, требование и лучший достигнутый результат. Направления доступны любому городу: менять специализацию для них не требуется.

Ступени — самостоятельные достижения с разными постоянными ID. Они проверяются автоматически; высокая ступень не требует сначала выбрать награду низкой. Если город уже подходит под несколько ступеней, он откроет их при ближайшей проверке. Последующее снижение показателей не отнимает достижения.

| Раздел | Ступень I | Ступень II | Ступень III |
| --- | --- | --- | --- |
| Общие: казна | 10 000 монет | 100 000 монет | Прежний «Первый миллион» |
| Общие: население | 100 | 500 | Прежнее «Население 1000» |
| Общие: отражённые набеги | 1 победа | 5 побед | Прежние «10 побед в рейдах» |
| Торговля | Рынок, склад, караван-сарай I | Все три здания III | Все три здания V |
| Производство | Кузница, лесопилка, каменоломня I | Все три здания III | Все три здания V |
| Оборона | Казармы, стража, оружейная I | Все три здания III | Все три здания V |
| Культура | Храм, музей, великая библиотека I | Все три здания III | Все три здания V |

Прежние достижения «Все здания V уровня» и «Первое чудо света» также остаются в общих целях. В стандартном каталоге 23 достижения: 5 прежних и 18 новых. Для профильной цели все указанные постройки должны одновременно иметь нужный уровень или выше. Проверки разных неполных наборов не складываются в завершённый набор.

## Награды и данные

Каждая новая цель открывает титул, частицы и узор знамени. Новые цели не выплачивают деньги и не дают дополнительного довольства. Прежний бонус чуда света сохраняется; прежнее общее ограничение довольства не меняется. Город выбирает один титул, игрок — один эффект частиц. Новые достижения не подменяют текущий выбор.

Данные остаются в `achievements-data.yml`, схема 1. Сохранённая копия определения, лучший прогресс, время открытия, награды, выбранный титул, косметика и административная пауза сохраняются. Старые записи без полей направления/ступени/уровня читаются с совместимыми значениями. Редактирование каталога не меняет уже закреплённое за городом определение. Чтобы изменить условия для существующих городов, создайте новый ID: удалять старые данные не требуется.

Недоступный, приостановленный или несовместимый поставщик данных не считается нулевым показателем: проверка соответствующей цели ждёт восстановления. Ранее открытые достижения и бонусы остаются. Эти изменения не вводят новые зависимости между модулями.

## Обновление конфигурации

Старый `achievements.yml` можно оставить. При `include-new-default-goals: true` (значение по умолчанию) в память добавляются только отсутствующие новые стандартные ID. Файл администратора не перезаписывается. Полностью существующий ID всегда имеет приоритет; отдельные пропущенные обязательные поля не подставляются молча. Удалённые из собственного каталога пять первоначальных ID автоматически не восстанавливаются.

Чтобы полностью управлять набором новых целей вручную, установите в `config.yml`:

```yaml
include-new-default-goals: false
```

и перенесите нужные записи из нового стандартного каталога. Уже закреплённые за городом цели продолжат учитываться из сохранённых данных; выключатель регулирует добавление определений, а не удаление наград.

Пример новой профильной цели:

```yaml
achievements:
  trade_tier_2:
    name: Торговый путь II
    description: Развивайте рынок, склад и караван-сарай до уровня 3 одновременно.
    icon: EMERALD
    kind: BUILDING_SET
    projects: [market, warehouse, caravanserai]
    minimum-level: 3
    track: TRADE
    tier: 2
    reward:
      title: Город торговцев II
      cosmetic: spark
      banner: wealth
      happiness: 0
```

`track`: `COMMON`, `TRADE`, `INDUSTRY`, `MILITARY`, `CULTURE`; `tier`: 1–3; `minimum-level`: 1–5 для `BUILDING_SET`. Размер списка построек задаёт цель; список должен быть непустым и без повторов. Для прежнего `ALL_BUILDINGS` уровень остаётся V, для `FIRST_WONDER` — I.

Команды: `/t achievements`, `/t achievements rewards`, `/t achievements track trade` (также `common`, `industry`, `military`, `culture`). Права прежние: `neverlandtownyachievements.use`, `.manage`, `.admin`. Административная перезагрузка: `/townyachievements reload`; пауза и повторная проверка остаются в административной панели. API `achievements` сохраняет старые поля и добавляет `track` и `tier`.

## Проверка

`AchievementsSmoke` проверяет прежние пороги, награды, сохранение, ошибки записи и запрет повторного открытия. `AchievementTiersSmoke` проверяет 23 определения, добавление новых ID в старый каталог, отказ от добавления, приоритет пользовательских определений, диапазоны ступеней, неполные наборы, отсутствие нового бонуса довольства, чтение старой схемы и сохранение наград/выборов после рестарта и редактирования каталога. Результаты запуска фиксируются отдельно в отчёте релиза; холодные проверки не заменяют запуск на Folia.

Проверено для 0.2.0: 68 новых и 33 прежних холодных утверждения; Folia 26.2 — 38 утверждений при первом запуске и 9 после полного рестарта. Native-проверка использует фактические API Towny/Builds/Achievements, меню, команды, сохранение и перезагрузку каталога. Уровни завершённых зданий внесены в настоящий DataStore как явные тестовые данные; игрок/окно/планировщик игрока — офлайн-заменители. Это не проверка реального строительства или отрисовки на клиенте. Точные SHA-256, условия и журналы: `docs/validation/city-systems-052/achievement-tiers/`.
