# Обновление 0.29.0 — преступность города

Добавлен **NeverLandTownyCrime 0.1.0**. В комплекте 32 отдельных плагина. Преступность связывает довольство населения, действующую стражу, торговлю и виртуальный склад.

## Игровое поведение

| Механика | Настройки по умолчанию |
| --- | --- |
| Преступность | От 0 до 100; новый город начинает с 0 |
| Расчёт | Раз в 10 минут, изменение не больше 5 пунктов за цикл |
| Стража | 20 эффективности за действующий уровень `guard`, ещё 5 за работника Jobs; максимум 100 |
| Целевой уровень | `(100 − довольство) × 0,8 + 20 − эффективность стражи × 0,6`, ограничен 0–100 |
| Потери лавки | От 0 до 25% выручки, пропорционально преступности |
| Происшествия | При преступности от 40: вероятность 15% за цикл, не чаще одного в час |
| Вымогательство | Ещё 10 процентных пунктов потерь лавки на 15 минут |
| Кража | 2% доступного количества одного виртуального ресурса, максимум 10 единиц |

Если здание стражи отключено содержанием или питанием, его работники не дают защиту. Отсутствующий Jobs не даёт бонуса работников. Установленный, но недоступный API не считается отсутствием стражи: расчёт приостанавливается. Время простоя сервера не отыгрывается серией расчётов; после запуска до следующего цикла даётся полный интервал.

Происшествия выбираются между кражей и вымогательством. Если Resources не установлен или в момент выбора нет доступного запаса, возникает вымогательство. По умолчанию воруют древесину, камень, металл или стройматериалы; еда, вода, знания и влияние исключены. Городские резервы и потребности населения защищаются самим API Resources. Физические предметы игроков и блоки мира не затрагиваются.

Жители получают сообщение после сохранённого применения происшествия. В меню видны текущие факторы, потери выручки и последнее происшествие. При высоком уровне преступности помогают жильё, рабочие места, снабжение, улучшение и содержание стражи, назначение работников через Jobs.

## Торговля и восстановление

Изменяется выручка **городской лавки торговой гильдии Builds**. Например, при цене 100 монет и преступности 80 покупатель платит 100, город получает 80; 20 — экономические потери. Сумма потерь округляется вниз до копейки. Общегородской доход, другие рынки и уже согласованные договоры этим коэффициентом не пересчитываются.

В `shop-orders.yml` до списания записываются исходная цена и отдельная сумма `seller-income`. После сбоя, перезапуска, изменения преступности или отсутствия Crime начатая покупка сохраняет эти суммы. Старые заказы без нового поля получают прежнюю полную выручку. Недоступность установленного Crime блокирует новые покупки, сохраняя обработку начатых.

Кража сначала сохраняется как `PLANNED` с неизменным UUID и количеством. Resources атомарно уменьшает свободный запас и сохраняет `HELD`; затем квитанция становится `CONSUMED`. Crime записывает `APPLIED` и только после этого удаляет квитанцию Resources и закрывает операцию. Потеря ответа на любом шаге приводит к сверке того же UUID. При отсутствии запаса операция отменяется без повторных попыток украсть позже.

Ошибка сохранения останавливает изменения соответствующего хранилища; повреждённая база не заменяется пустой. Исправьте причину и перезапустите плагин вместе с сервером. `/townycrime reload` обновляет настройки, но не снимает блокировку повреждённой базы. Журнал последнего происшествия хранится для каждого города; это не полная историческая летопись.

## Команды, оформление и API

`/t crime` и `/townycrime` открывают меню своего города. `/t crime help` показывает справку отдельными читаемыми строками. Администратор может выполнить `/townycrime town <город>` и `/townycrime reload`. Permissions: `neverlandtownycrime.use` (всем), `neverlandtownycrime.admin` (op). Меню применяет общий MenuStyle; цвет заголовка меняется в `menu-style.title-color`.

API v1 `TownyCrimeApi`: `crime(UUID)`, `towns()`, `shopIncomeBasisPoints(UUID)`. Снимки неизменяемы; живые запросы выполняются в основном потоке. Событие Bukkit `CrimeIncidentEvent` сообщает о сохранённом результате. Названия полей и ограничения: [README модуля](../modules/NeverLandTownyCrime/README.md).

PlaceholderAPI: `%townycrime_level%`, `%townycrime_happiness%`, `%townycrime_guard%`, `%townycrime_loss%`, `%townycrime_status%`. Значение потерь указано в процентах. Фоновые запросы численных показателей возвращают `—`, не обращаясь к Towny из неверного потока.

## Установка

1. Остановить сервер и сохранить резервную копию папки `plugins`, включая базы Towny и аддонов.
2. Заменить все 31 прежних JAR согласованными версиями из комплекта, удалив старые файлы, и добавить NeverLandTownyCrime. Общий код интеграции включён в каждый модуль.
3. Сохранить существующие папки данных. Конфигурация Crime создаётся при первом запуске.
4. Запустить сервер на Java 25 / Paper или Purpur 26.2 и проверить `/t crime` после первого расчёта.

Это обновление содержит отдельный плагин Crime и не требует объединения остальных модулей. Для отката восстановите согласованный комплект и резервные данные; не откатывайте только Builds с незавершёнными заказами новой версии.

## Проверки

Методика и фактические результаты стенда публикуются в [validation.json](validation/0.29.0/validation.json). Полный CI собирает каждый модуль штатным Gradle/Maven, запускает все найденные исполняемые тесты и проверяет совместимость публичных API. Нативный стенд — отдельный Purpur с искусственными городами, настоящими API и реальным перезапуском. Рабочий сервер пользователя и визуальная проверка с его ресурспаком в этот прогон не входят.
