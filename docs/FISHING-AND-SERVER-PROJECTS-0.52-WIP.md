# Рабочий этап 0.52: рыбалка, снабжение и гостевые права

Это инструкция к реализованной части рабочей ветки. Остальные одобренные доработки отслеживаются в CITY-SYSTEMS-IMPLEMENTATION.md; весь план ещё не выпущен.

## Рыбалка

При незавершённом личном или городском задании нужен открытый водоём. Одиночный блок воды и тесная рыболовная ферма не подходят. Проверка использует правила открытой воды самой установленной версии Minecraft.

Начальные настройки в `NeverLandTownyContracts/fishing.yml`: общий запас до 20 рыб в радиусе 24 блоков от поплавка; постепенное восстановление каждого вылова за 30 минут. Например, после быстрого полного вылова первый новый улов станет доступен примерно через полторы минуты, весь запас — за полчаса. Это параметры для плейтеста, их можно менять. Граница чанка, другой игрок и перезапуск не обнуляют вылов. Высота не создаёт отдельный запас над той же точкой.

`/orders fishing` объясняет правила и показывает запас около текущего поплавка, а без него — около игрока. На доске есть кнопка с правилами; описание рыболовного задания также содержит подсказку. Лодки и другой транспорт разрешены.

Без задания сохраняется обычная рыбалка. Чтобы распространить ограничение на всех, установите `apply-without-task: true`. При `enabled: false` проверка отключается. Если база недоступна, новые рыболовные задания не принимаются, незавершённые таймеры приостанавливаются, прогресс и готовые награды сохраняются. Другие типы заданий продолжают работать.

Не удаляйте `fishing-stock.db` и его WAL: это общий учёт вылова. При переносе остановите сервер и копируйте каталог целиком.

## Сметы серверных строек

Права просмотра: `neverland.orders.resources`; изменения: `neverland.orders.resources.manage`. OP и право `neverland.orders.admin` также подходят. Открытие: `/orders admin resources` или «Серверный склад» в разделе выплат `/nltadmin`.

Пример сметы и проверки:

```text
/orders admin resources plan spawn_square STONE=1000,OAK_LOG=256,GLASS=64 confirm Площадь спавна
/orders admin resources projects
/orders admin resources demand
/orders admin resources project-history spawn_square
```

Дефицит — сумма открытых смет минус доступный склад. Зарезервированные и использованные материалы не считаются свободными. В следующих личных подборках недостающий материал получает до пятикратного приоритета. Награда, редкость, количество, действующие задания и лимиты выплат не переписываются. Уже сохранённая доска остаётся прежней до следующего дня. Приоритет отключается через `orders.yml` → `server-demand.enabled: false` и перезапуск.

Когда всё собрано, резервируйте смету целиком:

```text
/orders admin resources reserve-project spawn_square confirm Начинаем строительство площади спавна
```

Команда выдаст ID. Если хотя бы одного материала не хватает, ничего не списывается. Повтор команды возвращает прежний резерв. После фактического использования материалов:

```text
/orders admin resources consume <ID> confirm Материалы использованы при строительстве площади
```

Если резерв не использовался, вместо `consume` выполните `return` с основанием. Использованные материалы вернуть повторно нельзя. До резерва смету можно закрыть:

```text
/orders admin resources cancel-project spawn_square confirm Строительство этой площади отменено
```

Эти операции ведут виртуальный серверный склад; физические предметы командами резерва не выдаются. Смета после резерва больше не привлекает новые заказы. Чтобы изменить состав уже сохранённой сметы, отмените её и создайте новую с другим ID. История действий хранится в базе, отдельная категория «Сметы серверных строек» доступна в журнале администрации.

База склада обновляется со схемы 1 до 2 с сохранением поставок и резервов. Для отката версии плагина нужна согласованная резервная копия до обновления; старый код намеренно не открывает новую схему как пустой склад.

## Гости лагеря

`/camp guests` открывает список с правами и оставшимся временем. Владелец приглашает игрока, уже известного серверу:

```text
/camp guest Player sleep,workbench 60
/camp guest Player storage 30
/camp guest Player remove
```

Права: `sleep` — сон, `workbench` — верстаки и столы обработки, `storage` — склад лагеря. Срок — от 1 минуты до 7 дней. Новая выдача заменяет прежний гостевой набор целиком. Гостевой доступ не разрешает телепортацию, управление лагерем или строительство. Для полного постоянного доступа остаётся `/camp trust`; прежний список доверенных сохраняется.

Окончание срока проверяется при действиях со складом, а открытое окно дополнительно закрывается при периодической проверке. Срок и отзыв сохраняются после перезапуска. Чтобы заменить постоянный полный доступ временным, сначала выполните `/camp untrust Player`.

## Проверка установки и копирование

На Linux перед запуском можно проверить фактически установленную папку:

```sh
python scripts/check_installation.py --plugins /srv/neverland/plugins --java 25 --matrix versions.yml
```

Проверяются внутренние имена JAR, дубликаты, обязательные зависимости, циклы загрузки, поддержка Folia, главный класс Java и синтаксис YAML. Проверка ничего не удаляет. Установленный Vault ещё не доказывает наличие зарегистрированного экономического провайдера — после запуска нужна диагностика экономики в админском меню.

Для согласованной копии остановите сервер:

```sh
python scripts/backup_addons.py --server /srv/neverland --output /srv/backups/neverland-before-052.zip
```

Включаются все данные плагинов, Towny, конфигурации сервера, базы с WAL, незавершённые операции и ключи подписей. Скрипт проверяет блокировки миров, отказывается перезаписывать архив и прекращает копирование при изменении файлов. Миры в архив не входят: сохраняйте их отдельно. Архив содержит закрытые данные сервера; его права на Linux — 0600.

## Проверки

Рыбалка: настоящий Folia 26.2 build 7 / Towny 0.103.2.0, 41 проверка первого запуска и 9 после рестарта. Проверены открытая вода, одиночный блок, отмена последующим обработчиком, повтор события, истощение, соседний чанк, другой участок, личный и городской прогресс, пауза таймера и восстановление. Стенд использует офлайн-актор CraftPlayer; полноценный сетевой клиент в этой проверке не участвовал. Сбой готовности хранилища в проверке таймера задан явно, реальные ошибки SQLite проверены отдельно.

Дополнительно: FishStockSmoke, прежние 76 проверок транспорта и оружия MountedOrdersSmoke, 18 проверок ServerProjectsSmoke, 18 проверок SnapshotPersistenceSmoke, 16 проверок GuestAccessSmoke, 9 тестов проверки установленного набора и 4 теста резервного копирования. На Folia дополнительно пройдены 13 проверок гостевых прав и двухэтапного отключения Chronicles, а также 4 после рестарта. Применялись офлайн-акторы и заменители InventoryView, полноценный графический клиент не запускался.
