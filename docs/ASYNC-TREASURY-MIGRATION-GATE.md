# Обязательная совместимость перед следующим полным релизом

Новый Treasury requestDebit/requestRefund подтверждает сохранённую операцию асинхронно по устойчивому ID. Старый spend возвращает boolean в том же вызове и не принимает ID. Его нельзя превращать в отложенное списание после возврата false: вызывающий аддон уже мог отменить покупку или вернуть ресурсы.

В рабочей ветке прежний spend временно отказывает до вызова банка. **Полный релиз с такой несовместимостью запрещён:** сначала все вызывающие стороны должны перейти на подтверждённый API и пройти проверку с установленным TreasuryPlus. Новый canSpend — только оценка по снимку, не обещание успешного платежа.

| Область | Вызывающие классы | Состояние |
|---|---|---|
| Builds | BuildService, ConstructionRefunds, CivicService | 0.11.1: cold48, Folia22+8 по оплате/возвратам/страхованию и Folia12+10 по старой архитектуре; прежние неизвестные внешние эффекты только на сверке, старый складской I/O остаётся отдельной задачей |
| Contracts | MunicipalBank, EconomyService | 0.8.1: cold18, Folia22+4+9; фактический автор новых ручных платежей, прежняя файловая запись остаётся синхронной |
| Espionage | EconomyService | Готово 0.2.1: cold 5, совместная Folia 33+11+4 |
| Ideologies | ReformBank | Готово 0.2.1: cold 3, Folia 19+11; полный пак ещё не проверен |
| Justice | JusticeBank | Готово 0.2.1: cold 5, совместная Folia 33+11+4 |
| Market | MarketGateway / MarketSettlement | 0.2.1: cold7, Folia24+8 с казной и складами, повторная проверка личных заявок22+11; неизвестные старые списания только на сверке, складской I/O ещё отдельно |
| SiegesPlus | RepairBank | 0.6.3: cold14, Folia12+10 с Builds0.11.1 на архитектуре2; проверка долга и ревизии закрывает бесплатное автовосстановление |
| Trade | SupplyGateway, EconomyService | 0.3.1: cold10, Folia17+5 с Treasury и Folia22+10 прежних караванов; точные списания/возвраты, неизвестные старые платежи только на сверке |
| Upkeep | CityBridge | Готово 0.2.3: cold 5, Folia 10+6; старые неизвестные оплаты только на сверке |

Проверять нужно весь вызов, а не замену имени метода: намерение до денег, отдельные подтверждения банка и состояния аддона, один UUID для повтора, отказ от слепого повторения неизвестного результата, возврат только реально удержанной суммы. Исторические операции сохраняют прежние условия. Закрытие требует тестов каждой ветки (успех, отказ, задержка, рестарт, сверка) и совместного Folia-стенда с TreasuryPlus.

Поиск для сверки: `rg -n 'TreasuryAccess.withdraw|invoke\("spend"' modules shared`. Не обходить ограничения бюджета прямым списанием Towny при установленном TreasuryPlus.

Все перечисленные активные потребители переведены на новый протокол и прошли адресные проверки. Совместная проверка полного набора, оставшийся старый I/O и окончательная публикация остаются открытыми. Оставшийся вызов `TreasuryAccess.withdraw` в RepairBank защищён запретом при установленной казне; старый метод EconomyService.withdraw в Trade не имеет активных вызывающих сторон.
