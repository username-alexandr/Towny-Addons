# Расчёт налогов и безопасные квитанции

Рабочая ветка 0.52: NeverLandTownyTaxes 0.2.0, Control 0.5.4. Старые политики, санкции, соглашения и журнал остаются в `data.yml`. Новые денежные квитанции, долги и серверный резерв хранятся в `payments.db`.

## Для игрока

`/mytaxes preview` показывает собственные применимые налоги без списания. Для процентных сборов по умолчанию берутся отдельные примеры дохода и входящего перевода по 100 монет. Можно задать свои значения: `/mytaxes preview 1000 250`. Это разные события; показанные налоги не следует складывать как одновременное списание за один доход.

Для каждого сбора показаны получатель, сумма до льгот, статус жителя, указы, санкции, скидка соглашения и итог. Фиксированный сбор содержит ближайший срок по Москве. Округление до копейки выполняется один раз в конце; сама выплата использует сохранённый результат этой же формулы. Например, 12,345 без дополнительных коэффициентов округляется до 12,35.

`/mytaxes receipts` показывает последние десять доступных личных квитанций: кому, сколько, на каком этапе и как рассчитана сумма. Вступать в город для просмотра не нужно. Сохраняется прежнее право `townytaxes.use` (по умолчанию доступно игрокам). Команды `/t taxes preview` и `/t taxes receipts` также работают.

Погашение долга принимается к обработке, затем результат появляется в квитанции. Сообщение о приёме заявки не означает, что деньги уже списаны. Пока банк или данные недоступны, новые сборы и погашение приостанавливаются без новых штрафов; пропущенные фиксированные сроки не взыскиваются задним числом.

## Как сохраняется перевод

До первого вызова банка записываются ID, стороны, сумма и формула. До каждого списания, зачисления или возврата сохраняется соответствующий этап. Запись выполняется ограниченной очередью SQLite с WAL/FULL; поток Folia не ждёт диск. Только после подтверждения записи вызывается банк на серверном планировщике.

Подтверждение проверяет счёт, направление, сумму и токен операции через наблюдатель Towny. Ответ об успехе без подтверждения или исключение без известного результата оставляет этап на сверке. Подтверждённый отказ получателя сохраняет удержанную сумму; её можно доставить позже или оформить возврат. Повторное выполнение одного этапа требует успешного атомарного перехода состояния, поэтому два обработчика не могут одновременно вызвать банк для одного намерения.

Серверный резерв и погашение долга меняются в одной транзакции с завершением квитанции. Неопределённый результат не создаёт дополнительную задолженность. Новый долг по настройке `taxes.failed-payment-debt` возможен только после определённого отказа списания обычного налога.

При отключении через `/nltmodules` сначала заканчивается запись. Ещё не начатый сбор отменяется без долга; удержанный перевод ставится на возврат. Неизвестный результат нельзя угадывать или автоматически возвращать: он остаётся для сверки. Уже завершённые налоги не отменяются. Включение аддона на Folia вступает в силу после полного перезапуска сервера.

## Для администратора

Право — `townytaxes.admin`, по умолчанию OP.

| Действие | Команда |
| --- | --- |
| Незавершённые переводы | `/townytaxes payments` |
| Полная квитанция по ID | `/townytaxes inspect <UUID>` |
| Подтвердить факт этапа | `/townytaxes resolve <UUID> <debit\|credit\|refund> applied confirm <основание>` |
| Подтвердить, что этап не произошёл | `/townytaxes resolve <UUID> <debit\|credit\|refund> missing confirm <основание>` |
| Вернуть удержанное | `/townytaxes return <UUID> confirm <причина>` |

`debit` — списание, `credit` — зачисление, `refund` — возврат. Перед `applied`/`missing` сверить банковские записи с токеном `[nlt-tax:<UUID>:<этап>]`. Основание записывается в административный журнал до изменения финансового этапа. Подтверждение зачисления не зачисляет деньги заново. Если зачисление уже точно завершено, команда возврата его не отменяет.

В `/nltadmin` → журнал → «Налоги» находятся суммы и формулы переводов, состояния ожидания/сверки и действия администратора. Основная квитанция сохраняется в SQLite независимо от общего журнала. Аудит записывается вне общей блокировки; при недоступном журнале денежное действие не повторяется, запись повторяется отдельно.

## Установка и миграция

1. Полностью остановить сервер и скопировать каталог плагинов с данными. Убрать старый JAR Taxes, установить новый; две версии одновременно не оставлять. Для новых подписей категорий обновить Control.
2. При первом запуске прежние долги и серверный резерв переносятся в SQLite одной транзакцией. Повторный запуск их не добавляет ещё раз.
3. После подтверждённого переноса `data.yml` получает `economy-storage-version: 2`. Прежние поля долгов/резерва в YAML остаются исходной копией, текущие суммы следует смотреть через API/команды. Старый JAR отклоняет новый маркер, а не продолжает работу с устаревшими деньгами.
4. Обязательно сохранять `payments.db` вместе с данными плагина. При копировании работающей SQLite нужны согласованные DB/WAL-файлы; для этого пакета предусмотрена офлайн-копия остановленного сервера. Если после переноса БД отсутствует или повреждена, новые списания закрываются. Пустая база из старого YAML автоматически не создаётся.
5. Откат возможен только из согласованной копии до миграции. Нельзя просто удалить `payments.db`, маркер или отдельные незавершённые квитанции.

В памяти находятся все незавершённые переводы (до 4096) и до 5000 последних завершённых; полная история остаётся в SQLite и доступна через `inspect`. Очередь записи — до 256 задач. Старые платежи не удаляются ради сброса ограничения или повторного начисления.

## Проверка

TaxCalculationSmoke — 12 проверок; TaxPaymentsSmoke — 31 проверка настоящей SQLite, включая отказ записи после банковского списания, перезапуск, потерянные подтверждения всех трёх этапов, возврат, перенос старых сумм и конкурирующие продолжения. Прежние 21 проверка недоступной экономики также проходят.

Folia 26.2 / Towny 0.103.2.0 — 13 проверок первого запуска и 7 после рестарта. Проверены реальные команды, наблюдатели счетов, SQLite, отключение через Control, отмена не начатого сбора без долга, отложенное включение после рестарта и сверка без повторного зачисления. Использованы явные заменители игрока и экономического провайдера, а потеря подтверждения после реального вызова Towny задана отдельно. Настоящий Vault/Reserve и графический клиент этим стендом не проверялись. Доказательства: `docs/validation/city-systems-052/taxes/`.
