# Проверка районных патрулей и судебных материалов

Folia 26.2 build 7 (`14b7fee`), Towny 0.103.2.0, Java 25.0.5. Три отдельных JVM: первый запуск — 37 проверок, перезапуск — 7, повреждённые optional-файлы — 6. Точные результаты: `first-checks.txt`, `restart-checks.txt`, `corrupt-checks.txt`; JAR и исходные входы сборки — `manifest.json`, полный перечень компонентов — `native-results.json`.

Проверены реальные службы Crime 0.2.0, Justice 0.2.0 и Districts 0.2.3. Поручение сохраняется до выдачи доступа; отчёт проверяет район и исполнителя. К делу прикрепляется подтверждённое историческое происшествие без нового наказания. Сведения закрыты от посторонних; апелляцию не может рассмотреть автор взыскания или его адресат. Физически задержанная запись не удерживает общую блокировку. После перезапуска сохраняются авторы, исходные ID, сумма, сроки и история. Неверная схема нового файла отключает новый раздел, сохраняя основной аддон и неизменный повреждённый файл.

Ограничения стенда: Player, InventoryView и EntityScheduler — явно заданные офлайн-заменители, направляющие действия в настоящий регион Folia. Историческое происшествие задано тестом. Реальная кража, сетевой клиент и денежный перевод здесь не проверялись. Основные старые журналы Crime/Justice остаются синхронными. В наборе использован проверенный Control 0.5.8; последующая разработка Control 0.6.0 не входит в этот результат. Все три JAR содержат AuditTrail из commit `9ab37fba`, до параллельного добавления перегрузки для неизменной квитанции; это зафиксировано в manifest.

Для повторения используются `scripts/crime-justice-runtime-probe/prepare.py`, `build.py`, `run.py`. Нужен новый loopback-стенд с маркером `ALLOW_DISPOSABLE_RAID_PROBE`. Выполняйте три последовательных foreground-запуска `run.py --phase first`, затем `--phase restart`, затем `--phase corrupt`. Последняя фаза намеренно портит только новые файлы в одноразовом стенде. На рабочем сервере этот тест не запускать.
