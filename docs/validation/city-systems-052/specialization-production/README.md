# Specialization 0.2.0: производственные партии и общие цели

Финальный прогон `folia-specialization-production-5`: **20 + 14 + 13 = 47 проверок**, три отдельных JVM и полностью foreground вызова инструмента. JAR SHA256: `ec006c7ca3d3488d6e9cc43f900657060222c644fca2f5773f667df4749344bf`.

- Первая фаза выпускает две реально обеспеченные партии, резервирует их в совместном проекте двух направлений, отменяет с точным возвратом, затем завершает новый проект с расходом этих же партий. Смена мэра после стабильного Contracts ACK не позволяет прежнему мэру выдать третью партию.
- Намеренный checkpoint перед первой остановкой: третья материальная смета Contracts — COMPLETED, локальный выпуск — FINISHING. Это сохранённая, ожидающая сверки операция, а не потерянная или выданная партия.
- Вторая фаза загружает ошибочный `production.yml`. Прежняя специализация, Contracts, Builds, Citizens, Control остаются включены. Новый действующий мэр сверяет прежнюю операцию: появляется ровно одна недостающая партия.
- Третья фаза запускается с восстановленным конфигом и повторяет сверку без второй выдачи. Прежние данные специализации остаются побайтово теми же.
- После каждого exit0 сохранены копии обеих SQLite. Проверяются integrity_check, точные количества материалов, состояния смет/проектов, городской остаток и пустая очередь неподтверждённого административного аудита. В финале 19 записей истории, все подтверждены общим журналом.
- Хеши main-файлов перед следующей JVM равны хешам после предыдущего выхода. WAL/SHM отсутствуют перед стартом и после завершения. `*-before-plugins.txt` снимаются в onLoad до запуска аддонов.

Нельзя подменять проверенные артефакты непроверенной сборкой: список хешей и исходников находится в `scripts/specialization-production-runtime-probe/validated-0.2.0.json`. Для воспроизведения используйте `prepare.py`, `build.py`, затем три отдельных запуска `run.py --phase first`, `--phase broken`, `--phase restart`. Каждый запуск ожидается до полного завершения, без фоновых shell-чтений той же среды.

Ограничения: реальная Folia/Towny и сервисы аддонов, но Player, InventoryView и EntityScheduler — явные офлайн-заменители. Работающее уникальное здание III уровня задано кешем; факт передачи предметов задан подтверждёнными квитанциями прежнего пути `/orders`. Прогон не доказывает сетевой рендеринг, строительство уникального здания, ручной крафт или работу внешнего банка.

`prior-runtime-anomaly.json` — не результат финального прогона. Он сохраняет появление прежних WAL/SHM между завершённым JVM и следующим tool-вызовом, ещё до старта следующего JVM. Причина не установлена. Код production не изменялся для обхода этой аномалии; WAL при запуске не удаляются. В окончательных полностью foreground вызовах аномалия не повторилась.
