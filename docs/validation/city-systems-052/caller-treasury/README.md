# Justice / Espionage Treasury caller verification

The release artifacts are identified by `build-manifest.json`; both embedded source-input maps match the current source files. Justice0.2.1 and Espionage0.2.1 each passed five cold test programs. New financial test suites contain 17 and 32 assertions respectively. The full source/dependency gate passed for 40 modules, 267 YAML files, 90 buildings and 11 wonders.

Fresh4 completed all three sequential native boots: first33, restart11 and corrupt4 assertions, all JVM exit codes0. `native-results.json`, phase logs, assertion files and immutable offline copies contain the exact evidence; `manifest.json` records the selected artifacts and scope. No production JAR changed between phases. `diagnostic-fixture3/` is retained as partial evidence: first33 and restart10 passed with normal JVM exit. Its corruption boot failed in probe setup because the preceding deliberate Treasury-disable test correctly persisted Control's module pause. The corrected probe invokes the ordinary admin enable command to authorize next-boot recovery after testing provider absence; it does not hot-enable plugins or rewrite financial state.

The native adapter uses actual Folia26.2/Towny Account and Observer, with a deterministic economy backend and offline actor proxies. It does not verify a real Vault implementation, an online client, GUI rendering, all combat/protection rules, or every historical synchronous financial path. Player authorization for accepted intents is frozen at acceptance; the probe intentionally completes accepted work while actors are offline.

Independent read-only review identified and rechecked the two recovery fixes: confirmed unpaid Justice refunds get a durable next-attempt identity, and an unexecuted paid Espionage mission with a deleted target receives a backed refund. Unknown outcomes retain their identity. Existing applied purchase receipts prevent a stale paid receipt from granting another level or receiving a refund. A subsequent read-only review also accepted the unpaid cancellation boundary: completed caller request, exact matching ABSENT operation, impossible target and common guard; the model forbids PAID → CANCELLED. This relies on the current gateway invoking the bank only after its durable PREPARED intent.

`ready-files.txt` lists the owned checkpoint scope. No Treasury, Control or shared source was modified by this caller migration.
