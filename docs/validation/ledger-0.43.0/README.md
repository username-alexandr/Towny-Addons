# Проверка Suite 0.43.0 — 26.10.2026

## Автоматическая сборка

Все 40 модулей собраны заново. Пройдены 144 исполняемые Java-тестовые программы, 13 Python-тестов сборочных инструментов, 41 контракт API и 7 проверок отказов хранилища. `suite-tests.json` содержит результаты по каждому модулю. После последних изменений затронутые модули были пересобраны и повторно проверены; в итоговом отчёте оставлен последний результат каждого модуля.

Новый `SuiteSchedulerSmoke`: 20 проверок реального межпоточного удержания блокировки с управляемыми очередями планировщиков — отсутствие ожидания, возврат в ту же очередь, отсутствие дублированных продолжений, отмена, устаревшие callback, пауза, исключения, вложенный guard и исчезновение сущности. Проверка Builds также подтвердила единую блокировку между изолированными загрузчиками JAR и сохранение межплагинных вызовов.

Матрица релиза: 40 JAR, 262 YAML, 90 зданий и 11 чудес; имена, версии, ресурсы и граф зависимостей проверены `verify_release.py`. Байткод плагинов рассчитан на Java 17; сервер запускается на Java 25.

## Живой Folia

Folia 26.2 build 7, commit `14b7fee`, Zulu Java 25.0.5, два региональных потока. SHA-256 серверного JAR: `128a634192261cd38bb4a5dc54075018a0f896fd6c6f529e37dca6e99e32b3b3`.

Зависимости стенда: Towny 0.103.2.0, VaultUnlocked 2.20.1, PlaceholderAPI 2.12.3 из официального release JAR, SiegeWar 3.7.0. Экономика Towny намеренно отключена для проверки недоступного провайдера. Только loopback, без подключённых игроков, телеметрия отключена.

Два полных запуска с сохранёнными между ними данными: `initial`, затем `restart`. На каждом — 111 успешных проверок общего набора и 20 проверок блокировки/Chronicles, ноль провалов, нормальное завершение, без watchdog-дампа. Все 40 аддонов включились и используют общую блокировку. Проверены:

- Global Region Scheduler продолжает тики, пока фоновый поток держит блокировку 120 тиков, приблизительно шесть секунд.
- Загрузка чанка и генерация его содержимого возвращают управление региону при занятой блокировке; отложенная работа выполняется на правильном планировщике.
- Разовая и периодическая задачи выполняются после освобождения ровно один раз; отменённая задача не выполняется.
- `/nltlock` отвечает во время занятой блокировки и показывает реального владельца со стеком.
- Владение двумя удалёнными регионами, изменения блоков, перенос сущности между регионами, индекс сущностей, очистка после удаления, пауза модуля и дедупликация командных наград.
- Ручная сверка Chronicles ставит города в очередь. Недоступная экономика не инициализирует счёт и не заменяет ранее сохранённый баланс 4321 на ноль; денежные достижения не начисляются. Автосохранение фиксирует баланс, а следующий полный запуск его сохраняет.

У каждого запуска уникальные идентификатор, пути результатов и ключи тестовых квитанций. Это исключает принятие оставшегося результата предыдущего запуска. `native-results.json` содержит идентификаторы и SHA-256 **каждого проверенного JAR**. Они сверены с файлами выдаваемого пакета.

На предварительном прогоне тест выявил дополнительные блокировки в Camps при загрузке чанка и Archaeology при генерации. Их исправления включены в окончательные JAR; результаты выше относятся к повторным успешным прогонам с проверкой этих путей.

Отдельный стенд с настоящим прежним Chronicles 0.1.18 и окончательным новым Control 0.4.14 подтвердил отказ частичного обновления: Control отключён до создания `modules.yml`. Результат — `mixed-protocol-result.txt`.

## Ограничения

Это проверка исполнения на настоящем Folia, но не нагрузочное испытание с игроками и не прохождение всех игровых механик. Реальные денежные операции конкретного сервера, клиентский CraftoUI и платные интеграции этим стендом не проверялись. Проверка API охватывает опубликованные контракты и совместимость, а не поведение сторонних плагинов.

В консоли остаются относящиеся к контейнеру предупреждения OSHI/сети и ошибка получения публичного ключа Mojang у изолированного offline-стенда. Предупреждения об отсутствии экономики ожидаемы в этом сценарии. Принудительно удерживаемая тестом блокировка даёт предусмотренную диагностическую запись NeverLand. Это не watchdog-дампы.

Исходный владелец блокировки из пользовательского инцидента не установлен: предоставлен только стек ожидающего потока. Прямые синхронные API/события и медленные операции внутри уже запущенной задачи всё ещё могут задерживать поток. Исправлен путь ожидания `SuiteScheduler` и обнаруженные обработчики загрузки; дальнейшие задержки следует разбирать по полному дампу и `/nltlock`.
