# Проверка Suite 0.43.1 — 27.10.2026

## Сборка и автоматические проверки

Все 40 модулей собраны заново. Пройдены 144 исполняемые Java-тестовые программы, 13 Python-тестов, 41 контракт API и 7 проверок отказов хранилища. Итоговые результаты по модулям находятся в `suite-tests.json`. `SuiteSchedulerSmoke` теперь содержит 31 проверку, включая остановку до постановки задачи, остановку уже ожидающей задачи, исчезновение сущности, гонку начала остановки и сохранение исключений при обычной работе. Проверено наличие нового shutdown-кода в `SuiteScheduler$Task` и `WorldTasks` каждого из 40 JAR.

`verify_release.py`: 40 JAR, 262 YAML, 90 зданий / 11 чудес; версии, имена, ресурсы и граф зависимостей согласованы.

## Воспроизведение исходной ошибки

На настоящих JAR пакета 0.43.0 создан частично выполненный рейд: один враг побеждён, один жив и один ожидает появления. При полной остановке воспроизведён **тот же** `NullPointerException` из `Events 0.4.11 → shutdown → cleanupRaidMobs → WorldTasks.eachEntityCleanup → SuiteScheduler.regionLater → FoliaRegionScheduler.scheduleInternalOnRegion`.

`baseline-expected-failure.json` содержит идентификатор запуска и SHA-256 старых JAR. `baseline-events-stack.txt` содержит стек, `baseline-shutdown-checks.txt` — проверки до ожидаемого сбоя. Код завершения процесса 0 не означает отсутствие ошибки плагина: отрицательный тест отдельно требует этот стек в консоли.

## Положительные прогоны

На исправленном комплекте выполнены два полных запуска и две штатные остановки Folia. На каждом: **109 общих проверок, 20 проверок блокировки/Chronicles и 18 проверок остановки/рейда; 0 провалов**. Все 40 модулей включились. Процессы завершились с кодом 0, без ошибок жизненного цикла плагинов и без watchdog-дампа.

Подтверждено сохранение прогресса (1 побеждённый враг), волны (1) и оставшихся врагов (2). Сохранённый живой враг возвращается в очередь один раз; новое поколение рейда удаляет прежнее тело после загрузки чанка. Посторонняя постоянная сущность сохраняется. Перед каждой остановкой в рейде снова присутствует живой моб. Во время реальной остановки новые региональные, глобальные задачи и задачи сущностей возвращают отменённый дескриптор; очистка мира не запускается.

У каждого запуска уникальные идентификатор и пути результатов. `native-results.json` связывает успешные проверки с SHA-256 каждого выдаваемого JAR. Данные Towny, Chronicles и активного рейда сохранялись между старой и новой сборками и между повторными запусками.

В этом сценарии FoliaProbe сохраняет Events включённым до настоящей остановки сервера. Его два заключительных теста административного отключения/включения Quests пропускаются, поскольку отключение зависимостей иначе заранее выключает Events. Остальные проверки паузы/продолжения модулей выполняются. Проверка полного административного отключения была выполнена в 0.43.0; здесь её повторно не заявляем.

## Среда и границы проверки

Folia 26.2 build 7, commit `14b7fee`, Zulu Java 25.0.5, два региональных потока. SHA-256 серверного JAR: `128a634192261cd38bb4a5dc54075018a0f896fd6c6f529e37dca6e99e32b3b3`. Towny 0.103.2.0, VaultUnlocked 2.20.1, PlaceholderAPI 2.12.3, SiegeWar 3.7.0. Только loopback, без игроков. Экономика Towny намеренно отключена для проверки недоступного провайдера.

Это не нагрузочное испытание и не прохождение всех игровых механик. Реальный экономический провайдер, клиентский интерфейс и платные интеграции не проверялись. Сроки событий и правила административной паузы не менялись. Отдельный тест несовместимого старого протокола из 0.43.0 не повторялся; протокол v2 в этом исправлении не менялся.

В консоли offline-стенда остаётся сетевая ошибка получения ключа Mojang. Предупреждения об отсутствующей экономике, удержании блокировки тестом и временно приостановленном расчёте населения относятся к намеренно создаваемым условиям проверки. Ошибки включения/отключения плагинов и watchdog-дампы в положительных прогонах запрещены.

Воспроизведение: `scripts/folia/ledger/README.md`. Тестовые плагины в игровой пакет не входят.
