# Проверка серверного склада — Suite 0.44.0

## Сборка и модульные проверки

Пересобраны Contracts 0.4.0 и Control 0.4.16. Все 9 исполняемых программ Contracts и 7 программ Control прошли; 13 Python-тестов сборочных инструментов также пройдены. Проверены прежний контракт API Contracts и новый ServerMaterialsApi. Общий API-инвентарь содержит 42 контракта; новая базовая сигнатура добавлена без изменения ранее опубликованных строк.

`ResourceDeliveriesSmoke` — 22 проверки с реальным SQLite и реальными файлами денежного журнала. Проверены передача в поток игрока, порядок сохранения/зачисления, повторный запрос, сбой сохранения игрока, отсутствие подтверждённого маркера после отката инвентаря, административное решение untouched, рестарт после подтверждения склада и до выпуска выплаты, банковская идемпотентность, отказ по лимиту и изменению допуска. SQLite-триггер принудительно вызывает ошибку после снятия предметов: транзакция не публикует частичный запас, а после исправления и рестарта квитанция завершается без второго списания.

`ServerMaterialsSmoke` — 23 проверки реального SQLite: 100 повторов одной квитанции дают одно пополнение; ID не может сменить материал; резерв сохраняет стоимость и проект; нехватка одного материала откатывает многокомпонентную операцию; параллельные резервы не превышают запас; возврат/расход идемпотентны и несовместимы друг с другом; CSV сохраняет атрибуцию и защищает формулы; рестарт сохраняет остатки; повреждённая база и неизвестная версия не заменяются пустым файлом.

Каталог — 215 проверок, включая 150 новых поставок, пять редкостей каждого материала, рост количества/награды, сохранение настроек 5000/500000, пользовательского размера доски и удалённых старых шаблонов. Прежние проверки охоты (135), зачёта в транспорте (76), выплат (38) и городских контрактов также проходят.

Остальные 38 JAR побайтово совпадают с пакетом 0.43.2 и не пересобирались. `artifact-provenance.json` фиксирует происхождение. Накопленный `suite-tests.json`: 147 программ для 40 текущих бинарников, включая свежие результаты двух изменённых модулей. Это не заявление о повторной сборке всех модулей в данном обновлении.

`verify_release.py`: 40 JAR, 262 YAML, 90 зданий / 11 чудес; версии, ресурсы и граф зависимостей согласованы.

## Настоящий Folia

Два полных запуска и две штатные остановки окончательного комплекта прошли с кодом 0, без ошибок жизненного цикла плагинов и watchdog-дампов. На каждом запуске: 109 общих проверок, 20 проверок блокировки/Chronicles, 18 проверок остановки с активным рейдом и 11 проверок серверных материалов. Во всех наборах ноль провалов. Уникальные идентификаторы и SHA-256 каждого проверенного JAR находятся в `native-results.json`; суммы сверены с выдаваемым архивом.

Стенд: Folia 26.2 build 7, commit 14b7fee, Zulu Java 25.0.5, два региональных потока. SHA-256 серверного JAR: `128a634192261cd38bb4a5dc54075018a0f896fd6c6f529e37dca6e99e32b3b3`. Towny 0.103.2.0, VaultUnlocked 2.20.1, PlaceholderAPI 2.12.3, SiegeWar 3.7.0. Только loopback; экономика намеренно выключена.

Отдельный ServerResourceProbe использует реальный зарегистрированный ServerMaterialsApi и настоящую базу плагина. Создаёт синтетическую поставку, проверяет прирост запаса, повторный резерв, расход, запрет возврата потраченного, повторный возврат неиспользованного и точный остаток. Во втором запуске сравнивает запас с предыдущим сохранённым результатом. Отдельно подтверждает миграцию установленного каталога v3 и сохранение настроенных лимитов 5000/500000.

Синтетический складской тест не подключает игрока и не выплачивает ему деньги. Поэтому его прямые тестовые квитанции помечаются урегулированными; реальный порядок инвентаря/денег проверен отдельным ResourceDeliveriesSmoke. Все пробные JAR исключены из выдаваемого пакета.

Данные сохраняются между запусками. Для повторения независимых проверок после длительной разработки срок специально простаивающего тестового рейда продлён в остановленном одноразовом стенде. Продуктовый код сроков рейда не изменялся. Как и в 0.43.1, два завершающих теста административного отключения/включения Quests пропускаются, чтобы Events оставался включённым до настоящей остановки.

## Ограничения

Подключённого клиента нет: фактическая сдача инвентаря игроком и визуальная проверка меню остаются ручным плейтестом. Нет нагрузки реального онлайна, реального экономического провайдера, клиентского CraftoUI и платных интеграций. Ошибка ключа Mojang на изолированном offline-стенде, предупреждения отсутствующей экономики, диагностика удерживаемой блокировки и предупреждение о приостановленном населении относятся к условиям проверки. Ошибки включения/отключения плагинов и watchdog-дампы в положительных прогонах запрещены.
