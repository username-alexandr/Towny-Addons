# 0.36.0 — административный аудит денег и ресурсов

Обновите JAR всего комплекта и полностью перезапустите сервер. Control 0.3.0 предоставляет `/nltaudit` (`/townyaudit`). Записи создаются автоматически; отдельная БД и включение в конфиге не требуются.

## Команды

```text
/nltaudit status
/nltaudit search town=Москва
/nltaudit search town=Москва intercity=true since=2026-09-17
/nltaudit search from=Москва to=Казань kind=MARKET_DEAL outcome=COMPLETE
/nltaudit search player=Alex since=2026-09-01 until=2026-09-17 page=2
/nltaudit search id=<полный UUID операции>
/nltaudit search module=Trade kind=CARAVAN_DEAL
/nltaudit export town=Москва since=2026-09-01 until=2026-09-17
```

`town`, `player`, `from`, `to` принимают имя или UUID; для удалённого города и прежнего имени используйте UUID либо `text=строка`. `from/to` разрешают имена городов; игрока задавайте UUID. `id` ищет точный ID записи или операции. Дополнительные фильтры: `kind`, `module`, `outcome`, `intercity=true|false`. Фильтры объединяются через И. Имена с пробелами задавайте UUID. Страница содержит 10 строк, доступны страницы 1–100. Для более глубокой выборки сузьте фильтры или используйте экспорт. Без дат поиск охватывает все доступные файлы; даты — UTC, `until` включает указанный день.

Просмотр: `neverlandtownycontrol.audit`; экспорт дополнительно требует `neverlandtownycontrol.audit.export`. Оба права по умолчанию только у операторов. CSV сохраняется в `plugins/NeverLandTownyControl/audit-exports/`; имя формируется сервером. Чтение/экспорт выполняются вне основного потока, одновременно максимум две задачи. Экспорт ограничен 100 000 строками; при превышении готовый файл не публикуется. Ячейки экранируются, формулы нейтрализуются.

## Записи

Строка содержит время наблюдения, модуль, тип/этап, ID записи и операции, инициатора, отправителя и получателя: тип счёта, UUID, имя и город на момент наблюдения. Также сохраняются предмет, количество, сумма и пояснение. Для предметов API хранится точный сериализованный образец с пользовательскими метаданными. Записанные имена/принадлежность не меняются вслед за переименованием или переходом игрока.

| Тип | Источник и смысл |
| --- | --- |
| `BANK_LEG` | Подтверждённое уведомление счёта Towny о списании (`DEBIT`) или зачислении (`CREDIT`), включая назначение. Счета городов, наций и жителей. |
| `BANK_TRANSFER` | Успешное `Account.payTo` Towny с обоими счетами. Отказ не помечается завершённым переводом. |
| `BANK_COMMAND` | Дополнительное событие команды банка с игроком, когда Towny его предоставляет. |
| `CARAVAN_DEAL` | Этапы каравана, стороны, товар, цена, полный резерв и пошлины. Инициатор принятия предложения записывается на `PREPARED`. |
| `TRADE_PAYMENT`, `TRADE_TARIFF`, `TRADE_REFUND` | Зачисление продавцу, каждому городу транзита и возврат. Строки связаны ID каравана. |
| `SUPPLY_AGREEMENT` | Предложение/подписание и управление регулярным договором с UUID игрока. Условия, не факт поставки. |
| `SUPPLY_DEAL` | Этапы каждой автоматической поставки с отдельным ID партии и ссылкой на договор. |
| `MARKET_DEAL`, `SHOP_DEAL` | Рынок и городские лавки: инициатор, товар, количество, цена и этап. Для лавки отдельно указана выручка после потерь. |
| `MARKET_DELIVERY`, `SHOP_DELIVERY` | Складская доставка/выдача. `PICKUP` означает ожидание игрока, `CLAIMED` — квитанцию выдачи. |
| `WAREHOUSE_TRADE`, `WAREHOUSE_LEG` | Межгородская поставка/возврат складского API, отдельное внесение/изъятие через Warehouse API. |
| `STORAGE_PLAYER` | Итоговое изменение по каждому точному предмету за сессию муниципального склада: кто внёс/забрал, включая shift-click и drag. Перекладывание внутри склада не считается передачей. |
| `COMPANY_PAYMENT`, `COMPANY_CONTRACT` | Взносы/выводы компании, налог/возврат городу, расчёт муниципального заказа. Компания — отдельный тип счёта. |
| `CONTRACT_PAYMENT`, `CONTRACT_DELIVERY` | Резерв/награда/возврат заказа и поставка предметов игроком в город. |
| `TAX_TRANSFER` | Налог с обеими сторонами и ID политики; без подтверждения — `UNCONFIRMED`. |

У сделок `from → to` — направление **товара**, `money` — договорная цена. На подготовительных/отменённых этапах это не сумма выполненного перевода. У банковских/платёжных строк направление относится к **деньгам**. Банковские строки, сделка и складская квитанция — разные свидетельства одной операции; их суммы нельзя складывать. Для подсчёта завершённых сделок выбирайте один тип и `outcome=COMPLETE`. Неизвестные стороны/инициаторы — `UNKNOWN`, автоматические действия — `SYSTEM`. Отдельные списания/зачисления не объединяются в доказанный перевод по совпадению суммы или текста.

`intercity=true` выбирает две известные и различающиеся принадлежности к городам. Неизвестный контрагент сюда не попадает. Цепочка через игрока автоматически не объявляется нарушением: сопоставляйте `player=UUID`, даты, предметы и соседние операции.

## Сохранение и границы покрытия

Файлы `plugins/<аддон>/audit/YYYY-MM.tsv` дописываются по месяцам, с экранированными полями и SHA-256 каждой строки. Они не очищаются вместе с короткой игровой историей, отменой задания или отключением модуля. Control читает и журналы отключённых аддонов. Работающие аддоны пишут собственный аудит без Control; нативное наблюдение банков требует Control. Автоматического срока хранения нет: включите журналы в резервные копии и контролируйте объём.

Устойчивый ID квитанции исключает повторную запись того же этапа после рестарта. Очистка завершённых квитанций каравана, автопоставки, рынка, лавки и складских перемещений откладывается, если итог не попал в аудит. Денежный вызов при этом не повторяется. Квитанции компаний и платежей муниципальных заказов остаются в собственных хранилищах. Первое наблюдение восстановленной квитанции получает текущую дату наблюдения, а не выдуманную дату старого расчёта.

Ошибка записи выводит `AUDIT GAP` в консоль. Оборванная строка или неверная контрольная сумма не удаляются и не игнорируются: журнал требует восстановления из проверенной копии. `/nltaudit status` проверяет читаемость и контрольные суммы, но не доказывает отсутствие пропущенных уведомлений. SHA-256 обнаруживает повреждение, но не защищает от администратора с доступом к диску.

Уведомление Towny и аудит не образуют общую транзакцию с Vault: при отказе диска или аварии между денежным эффектом и уведомлением возможен пробел. Он не компенсируется повторным переводом. Вся история до установки не восстанавливается. Не наблюдаются прямые операции сторонних плагинов через Vault в обход Towny, обычные сундуки, выброс/передача вещей между игроками и `/pay` другого плагина. Полное покрытие этих путей не заявляется.

Прежние безопасные остановки, нейтральные отмены и щит новичка сохранены. Журнал ничего не списывает, не начисляет штрафы и не меняет исходы заданий.
