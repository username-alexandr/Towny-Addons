# Обновление 0.7.8

## Установка и сохранённые данные

Остановите сервер, сохраните резервную копию мира и каталогов данных, замените установленные JAR аддонов из релиза, запустите сервер. Не удаляйте projects.yml, messages.yml, town-data.yml и данные экспедиций/событий. Новый raids.yml создаётся автоматически. Старые стандартные иконки и префикс исправляются при загрузке.

Архитектура 6 исправляет 26 из 37 импортированных моделей: 1937 дополнительных стеновых блоков, опоры до стадии крыши. Дополнены стеклянные фронтоны и порядок строительства обычных домов. Миграция дополняет готовые стадии только на территории их города и только на свободных/заменяемых блоках. Чужие твёрдые блоки не затираются: при необходимости уберите их и перезапустите проверку площадки. Исходный архив Models-0.1.0 остаётся историческим источником; поправки применяются генератором в JAR.

В каталоге 79 зданий и 11 чудес. Бюджеты автоматически соответствуют обновлённому объёму строительства. Таблица resource-balance.csv показывает стандартные значения всех 406 уровней.

## Экспедиции и LuckPerms

| Право | Действие | По умолчанию |
|---|---|---|
| neverlandtownyexpeditions.return | /expedition return и кнопка «Вернуться в лагерь» | false |
| neverlandtownyexpeditions.shield | Использование щита в области активной экспедиции | false |

Пример для существующей донатной группы vip (замените её на свою):

```text
/lp group vip permission set neverlandtownyexpeditions.return true
/lp group vip permission set neverlandtownyexpeditions.shield true
```

Права независимы. Автоматического возврата при завершении/отмене/провале нет даже у донатеров. Старый expeditions.return-on-complete игнорируется. Разрешён только ручной возврат к живому лагерю владельца вашей экспедиции. Кнопка появляется при наличии права и доступного возврата. После завершения expeditions.manual-return-window-seconds задаёт срок (по умолчанию 600 секунд); успешный возврат расходует сохранённый билет. Удалённый лагерь не является целью возврата.

Щит проверяется в обеих руках и при уже начавшемся блокировании. Вне области активной экспедиции это ограничение не действует.

## Рейды

Все стандартные набеги теперь состоят из 10 волн. Следующая волна ждёт зачистки предыдущей, затем паузу gameplay.raid-wave-interval-seconds (60 секунд). Лимит одновременно живых врагов задаёт gameplay.raid-max-alive-mobs-per-town, остальные ждут в очереди. /t events raidwave <город> сокращает паузу, но не пропускает живую волну.

| Моб | Очки |
|---|---:|
| Зомби | 1 |
| Кадавр, скелет | 2 |
| Разбойник с арбалетом | 3 |
| Поборник, ведьма | 4 |
| Разоритель | 7 |
| Главарь | 8 |

Засчитываются только убийства игроком и только один раз. Смерть от окружения освобождает место в волне без очков. Победа требует зачистить все 10 волн; очки убийств и поставок отображаются отдельно от прогресса волн. Защита города снижает здоровье/урон врагов. BossBar и меню показывают волну и число оставшихся врагов. PAPI: %mintevents_raid_wave%, %mintevents_raid_remaining%, %mintevents_points%. Для рейда %mintevents_progress% / %mintevents_goal% означают зачищенные волны / 10.

Прогресс сохраняется в events-data.yml. После штатного перезапуска продолжается текущая волна: пересоздаются только неубитые враги, прежние тела удаляются в том числе при загрузке их чанков. Старый рейд из версии до 0.2.0 начинает новую серию из 10 волн с сохранением очков и полным сроком на прохождение. Аварийная потеря ещё не записанного состояния сервера может вернуть последний несохранённый прогресс.

### Кастомные враги

Настраивайте mobs и waves в raids.yml; перезагрузка: /t events reload. Все 10 волн обязательны, в каждой 1–200 врагов. Встроенные стандартные волны работают без дополнительных плагинов.

```yaml
mobs:
  captain_custom:
    type: VINDICATOR
    name: "Капитан разбойников"
    points: 8
    health: 60
    damage: 7
    provider: modelengine
    model: bandit_captain
    equipment:
      hand: "itemsadder:raiders:captain_axe"
      chestplate: IRON_CHESTPLATE
# В существующую waves.'10'.mobs добавьте: captain_custom: 1
```

Для модели ItemsAdder используйте provider: itemsadder и model: "raiders:captain". type выбирает базового моба и его ИИ. Можно одновременно использовать модель ModelEngine и предметы ItemsAdder. Два провайдера внешнего вида на одном существе не смешиваются. Предметы задаются в слотах hand, offhand, helmet, chestplate, leggings, boots. Их выпадение отключено. Неизвестный ID или недоступный плагин вызывает предупреждение и повторную попытку: волна не считается зачищенной.

Интеграции используют публичные API: [ModelEngine — создание модели](https://wiki.mythiccraft.io/modelengine/API/Basic/Add-Remove-Model), [ItemsAdder — CustomEntity.convert](https://lonedev6.github.io/API-ItemsAdder/dev/lone/itemsadder/api/CustomEntity.html). Готовые пользовательские модели и ресурс-пак в этот релиз не входят. Их анимации, видимость и хитбоксы нужно проверить с установленными версиями этих плагинов на сервере.

## Штаб армии и возраст

Это отдельное здание army в разделе «Оборона», а не улучшение казарм. Физическая модель имеет пять стадий. По умолчанию каждый уровень открывает 10 мест; настройка army.soldiers-per-level. Армия хранит состав граждан-игроков Towny по UUID; NPC здесь не создаются.

| Команда / право | Назначение |
|---|---|
| /t army, /townyarmy | Состав и меню мобилизации |
| /t army mobilize <житель> | Мобилизовать гражданина своего города |
| /t army release <житель> | Демобилизовать гражданина |
| /townyarmy age <житель> <0..150> | Подтвердить возраст персонажа |
| /townyarmy age <житель> clear | Удалить локальное подтверждение |
| neverlandtownybuilds.army.use | Просмотр своего города, default true |
| neverlandtownybuilds.army.mobilize | Офицер своего города, default op; мэр может управлять без этого права |
| neverlandtownybuilds.army.age | Изменение подтверждённого возраста, default op |
| neverlandtownybuilds.army.soldier | Временное право действующего солдата; автоматически выдаётся/снимается, default false |

Проверяется возраст **персонажа** от 18 включительно; личный возраст игрока не собирается. Приоритет источников: зарегистрированный ResidentAgeProvider → настроенный army.age-placeholder через PlaceholderAPI → локально подтверждённый возраст. Если источник настроен, но не отвечает или возвращает неизвестное значение, мобилизация запрещена и статус службы приостановлен. Не подставляйте выдуманный placeholder: возьмите целочисленный возраст из своего плагина паспорта. Пустая настройка включает локальный способ /townyarmy age.

Мобилизация проверяет права мэра/офицера, готовый штаб, гражданство, возраст и свободные места. Повторные клики не создают дубликатов. Выход из города или исчезновение штаба снимают запись; недоступность паспорта приостанавливает действующий статус, сохраняя состав. Возраст, записи и статус пересматриваются каждые 10 секунд; команды проверяют их сразу. Данные хранятся в army-data.yml. Статус доступен другим плагинам через TownArmyApi в Bukkit ServicesManager.
