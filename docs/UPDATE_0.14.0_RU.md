# Обновление 0.14.0: специализация города

NeverLandTownySpecialization добавляет одно направление развития на город. Для выбора по умолчанию нужны **уровень города Towny III и физически завершённая ратуша III**. Используется `Town.getLevelNumber()` из настроенной лестницы Towny; численность NPC из Population не заменяет этот уровень. Понижение уровня после выбора не отнимает направление и базовые бонусы, но требования снова проверяются при смене.

## Установка

При остановленном сервере замените используемые Builds, Resources, Population, Districts, Logistics, Upkeep, Power, Research, Trade и Events версиями из комплекта 0.14.0; добавьте NeverLandTownySpecialization 0.1.0. Старые дубликаты JAR удалите. Мир, данные Towny и каталоги настроек аддонов сохраните. Платформа: Paper/Purpur 26.2, Towny 0.103.2.0, Java 25.

Обязательны Towny и Builds. Остальные городские системы подключаются по наличию: без Resources нет стратегического производства, без Research — исследований, без Population — довольства, без Trade — торговых маршрутов, без Logistics — NPC-курьеров. Обслуживание и энергия учитываются, когда соответствующие модули установлены. Отдельный плагин для `shared/specialization` не нужен.

Старые цены и строительные площадки сохраняются. Семь новых проектов и их профили подхватываются из значений по умолчанию, с сохранением пользовательских настроек существующих записей. Теперь в каталоге 90 зданий и 11 чудес, 461 строительный этап. В релизе есть CSV с расчётом ресурсов всех проектов.

## Выбор и смена

Откройте `/t specialization`, выберите карточку и нажмите «Подтвердить выбор». Меню показывает базовый бонус, максимум при уникальном здании V, требования и остаток ожидания. Перейти к нему можно из меню построек и ресурсов.

Выбирать может мэр, помощник или житель **своего** города с правом управления. Выбор и смена бесплатны. По умолчанию повторная смена доступна через 168 реальных часов: ожидание продолжается при выключенном сервере. Настройки и состояние города повторно проверяются при подтверждении; устаревшая карточка или второй одновременный выбор не перезаписывают новый результат.

При смене прежнее уникальное здание и его инвентарь остаются. Строительство, производство, вместимость и остальные преимущества этого здания приостанавливаются; оно не получает новых счетов и не запрашивает энергию. Уже начатые операции оплаты завершаются или сверяются по журналу Upkeep, ранее оплаченные периоды сохраняются. Возврат направления снова открывает здание. Выход из района или отсутствие обслуживания/энергии обрабатываются обычными правилами этих систем.

Если Specialization отсутствует, выключен либо недоступен, семь уникальных проектов остаются заблокированы. Обычные проекты используют прежние правила. Отключение отдельного направления в настройках также блокирует его уникальное здание и бонусы, сохраняя выбор и срок ожидания.

## Команды и права

| Команда | Действие |
|---|---|
| `/t specialization` | Меню своего города |
| `/t specialization info <id>` | Бонусы и условия направления |
| `/t specialization choose <id>` | Подготовить выбор на 60 секунд |
| `/t specialization confirm` | Подтвердить подготовленный выбор |
| `/townyspecialization reload` | Применить проверенные настройки; при ошибке сохранить прежние |
| `/townyspecialization town <город>` | Администратору: посмотреть город |
| `/townyspecialization set <город> <id>` | Администратору: подготовить выбор с обходом уровня и ожидания; затем `confirm` |

Основная команда `/townyspecialization` имеет алиасы `/nltspec` и `/cityspecialization`. Просмотр доступен с `neverlandtownyspecialization.use` (по умолчанию всем); `neverlandtownyspecialization.manage` по умолчанию никому; `neverlandtownyspecialization.admin` по умолчанию OP. Право управления действует только в собственном городе. Административное назначение подтверждается в игре; консоли доступен reload.

## Настройка и данные

В `config.yml`: `selection.minimum-town-level`, `selection.minimum-town-hall-level`, `selection.change-cooldown-hours`, `simulation.interval-seconds` (по умолчанию 10). В `specializations.yml`: имена, иконки, описание, включение, бонусы, список производств и минимальный рабочий уровень уникального здания.

ID семи направлений и связь с семью уникальными проектами фиксированы, чтобы настройкой нельзя было обойти строительные ограничения. Доли бонусов задаются десятичным числом (`0.1` = 10%), довольство — пунктами. Общий бонус вместе со зданием V ограничен 50% для долей и 20 пунктами для довольства. `trade_delay` означает снижение вероятности в процентных пунктах.

`specialization-data.yml` хранит выбор по UUID города, время выбора, следующий срок смены и ревизию. Сначала записывается файл, затем публикуются новые бонусы. Повреждённая база не перезаписывается. Переименование не меняет выбор; новый город с тем же именем и другим UUID не наследует старое направление. Бонусы здания пересчитываются раз в интервал симуляции, а запрет чужого направления применяется сразу после выбора.

Research 0.1.1 сохраняет дробную часть ускоренного прогресса. Старые записи без этого поля загружаются с нулём. Бонус скорости не снижает цену технологии; пауза инфраструктуры и выключенный сервер не дают прогресса.

## API и PlaceholderAPI

Сервис Bukkit `ru.neverland.townyspecialization.api.TownySpecializationApi` предоставляет `canUseBuilding`, `bonus`, `productionBonus`, снимки города и жителя, коллекцию городов. Снимки неизменяемые; чтение бонусов не вызывает загрузку чанков. Другие аддоны получают сервис динамически, чтобы избежать циклов загрузки плагинов.

Плейсхолдеры: `%nltspecialization_name%`, `%nltspecialization_id%`, `%nltspecialization_town_level%`, `%nltspecialization_hall_level%`, `%nltspecialization_building%`, `%nltspecialization_building_level%`, `%nltspecialization_cooldown%` (секунды), `%nltspecialization_status%`, `%nltspecialization_bonus_production%` и аналогично для остальных ключей эффектов. Бонус отображается с единицей измерения.

## Проверка

Локальные и CI-проверки охватывают правила выбора, ожидание и административный обход, повторные подтверждения, восстановление базы и отказ записи, отсутствие/отключение сервиса, совместную проверку обслуживания и питания, дробное ускорение науки, состав профилей и сборок. Геометрические проверки проверяют 35 новых этапов на сохранение предыдущих блоков, непрерывные стены/крыши и связь с фундаментом; общая проверка крыш охватывает все 461 этап.

Minecraft-сервер в рабочей среде не запускался. После установки на тестовом сервере проверьте выбор мэром, строительство проекта до III, эффект в подключённой системе, административную смену и перезапуск с сохранением города.
