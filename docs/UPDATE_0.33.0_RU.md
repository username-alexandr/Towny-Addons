# Обновление 0.33.0 — сезонная экономика

36 отдельных аддонов. Новое: NeverLandTownySeasons 0.1.0. Обновлены Events до 0.3.4 и Resources до 0.1.14; остальные версии сохранены. Paper/Purpur 26.2, Towny 0.103.2.0, Java 25.

## Что меняется

Сезон города определяется по миру домашнего участка Towny. На будущий выпуск стратегических ресурсов Resources накладывается отдельный сезонный коэффициент, после бонусов районов, профессий, исследований и политик. Он может быть меньше единицы. Запасы, вместимость складов, расходы производства и потребление жителей от смены сезона не меняются. Физические рецепты складов Builds и обычная скорость роста культур вне городского события этим модулем не меняются.

| Сезон | Аграрный выпуск | Вес наводнения | Вес засухи | Вес пожара |
|---|---:|---:|---:|---:|
| Весна | 120% | 3 | 0.25 | 0.75 |
| Лето | 110% | 0.5 | 3 | 1.5 |
| Осень | 125% | 1.25 | 0.5 | 0.75 |
| Зима | 60% | 0.25 | 0.1 | 1 |

Веса меняют выбор типа события среди настроенных событий. Общая вероятность проверки, лимит одновременных событий, требование присутствия жителей и перерыв для города остаются в Events. Это относительные веса, а не проценты вероятности. Нулевой вес исключает тип; если все веса нулевые, событие не начинается. Для неизвестных построек и остальных типов событий коэффициент равен 1. Настройки допускают выпуск 0.1..2 и веса 0..10. Пустой список `worlds` означает все обычные миры; Ад и Край всегда нейтральны.

## Календарь

`plugins/NeverLandTownySeasons/config.yml`:

- `calendar.mode: CUSTOM`: собственные сутки по реальному времени. По умолчанию 60 минут в сутках и 7 суток в сезоне; год — 28 часов. Отсчёт начинается при первой успешной загрузке. Простой сервера учитывается, пропущенные производственные циклы не начисляются.
- `MINECRAFT`: сутки — 24000 накопленных тиков мира (`World.getGameTime`). Сон и `/time set` не перематывают календарь. При лаге сутки длиннее по реальному времени; остановленный сервер не продвигает дату. Возраст существующего мира учитывается с начала мира.
- `REALISTIC_SEASONS`: читает текущий сезон через документированные `SeasonsAPI.getInstance()` и `getSeason(World)` отдельно для каждого мира. `FALL` соответствует осени. Дату и погоду стороннего плагина не меняет. День/год в меню не выдумываются, поскольку читается только сезон.

Начальный сезон — `calendar.first-season`; длина сезона — `days-per-season` (1..365), длина собственных суток — `day-minutes` (1..10080). Изменение длины или режима пересчитывает текущую дату относительно сохранённого начала/возраста мира. `calendar.yml` хранит начало и ручные фиксации по UUID мира через атомарную замену файла. После ошибки записи дальнейшие изменения и расчёты блокируются до исправления данных и перезапуска. Не удаляйте файл при обновлении. Reload проверяет новые настройки до замены действующих.

Ручная фиксация сохраняется при перезапуске, имеет приоритет над источником и действует только на экономику NeverLand. Resume возвращает к **текущей** дате источника; время на период фиксации не останавливается. Смена сезона сообщается игрокам соответствующего мира; `announce: false` отключает сообщения.

## Наводнение и засуха

Новый тип Events `FLOOD`: 40 минут, цель `200 + 35 × жителей`. По умолчанию мешает 60% попыток роста культур на земле города и снижает аграрный выпуск на 40%. Воду блоками не размещает, рельеф и постройки не разрушает. У существующих серверов отсутствующая запись `events.flood` подгружается из нового стандартного файла без перезаписи пользовательского `events.yml`. Для отключения этого дополнения: `seasonal.include-default-flood: false`; явно заданная запись сохраняет приоритет.

Защита на уровень: акведук 10%, ирригация 8%, Великий канал 25%, ратуша 2%; инфраструктурная идеология — 10%. Общий предел 80%. Учитываются действующие здания. Защита фиксируется в момент начала события и уменьшает потери по формуле `потеря × (1 − защита)`. Засуха теперь также снижает стратегический аграрный выпуск на 50%; её прежние правила роста культур остаются. Потери настраиваются в `seasonal.drought-output-loss` и `seasonal.flood-output-loss` (0..0.9). После завершения или истечения события коэффициент снова 1.

Вклады для наводнения: песок и гравий по 2 очка, губка 24, дубовые доски 3. Используются действующие меню и механизм вкладов `/t events`, журнал событий, история и репутация. Защита даёт существующий бонус к вкладам. Например, весной без защиты аграрный комплекс выпускает `1.2 × 0.6 = 72%` базы во время наводнения; расход воды не уменьшается. Точный выпуск виден в Resources.

## Команды и права

| Команда | Доступ |
|---|---|
| `/t seasons`, `/tseasons` | `neverlandtownyseasons.use`, по умолчанию все |
| `/tseasons menu [мир]` | Просмотр выбранного мира; без аргумента — мир города, для безгородного игрока текущий мир |
| `/tseasons set <мир> <spring\|summer\|autumn\|winter>` | `neverlandtownyseasons.admin`, по умолчанию op |
| `/tseasons resume <мир>` | То же право |
| `/tseasons status`, `/tseasons reload` | То же право |

Меню использует общий контрастный стиль, отдельные карточки сезонов, пояснение весов и возврат в фактическое предыдущее меню. Кнопки диагностики и команды администратора скрыты от обычного игрока; команды проверяют permission при выполнении. `menu-style.title-color` позволяет подстроить заголовок под ресурс-пак.

## API и зависимости

Seasons требует только Towny; RealisticSeasons — необязательная внешняя зависимость. Resources и Events читают новый API по версии и capabilities через ApiServices. Циклических обязательных зависимостей нет. Устанавливайте изменённые JAR комплектом: новый Resources требует capability `productionMultiplier` от установленного Events 0.3.4. Без установленного Seasons коэффициенты нейтральны; установленный, но недоступный или несовместимый API приостанавливает расчёт, не скрывая ошибку. Для внешнего режима отсутствие/отключение RealisticSeasons, несовместимые методы, неизвестный сезон мира или ошибка вызова имеют явную диагностику; автоматического перехода на другой календарь нет.

`ru.neverland.townyseasons.api.TownySeasonsApi`, версия 1:

- `calendar(UUID world)`, `townCalendar(UUID town)`: неизменяемый JDK-снимок с миром, названием, сезоном, источником, годом/днём, оставшимся временем, единицей времени и картами коэффициентов. Для внешнего/ручного режима неизвестная дата и остаток — 0, единица `UNKNOWN`; для отключённых миров сезон `NONE`.
- `productionMultiplier(UUID town, String building)`, `eventWeight(UUID town, String eventMode)`.
- `healthy()`: состояние хранилища; доступность внешнего источника проверяется при чтении конкретного мира. Ошибки не возвращаются как успешный нейтральный коэффициент.
- Унаследованные diagnostics/storageMetrics. Все методы требуют основного потока сервера. Нет денежных операций, списаний резервов или чтения внутренних классов соседних плагинов.

Events API v1 дополнен совместимым default-методом `productionMultiplier(UUID,String)`. Старые методы и сигнатуры сохранены.

Интеграция RealisticSeasons реализована по [официальному API](https://wiki.realisticseasons.com/developers/api). Сторонний плагин не включён в комплект. На собственном календаре и времени Minecraft модуль работает самостоятельно. Реальный экземпляр платного RealisticSeasons в серверном прогоне не использовался; проверен явный отказ при его отсутствии. Полная совместимость с конкретной установленной версией требует отдельного прогона.

## Проверки

Исполняемые тесты: границы сезонов и лет, тысячи игровых суток, сохранение начала и фиксации, resume, повреждение YAML, отказ атомарной записи, некорректные настройки, выбор событий по весам, снижение потерь защитой, зимнее производство и совместный сезон/событие. Обновлён ABI baseline без удаления старых сигнатур.

В `scripts/seasons-runtime-probe` находится воспроизводимый сценарий отдельного локального сервера с реальными Towny и аддонами, первым запуском и перезапуском. Он проверяет все API, выпуск и сохранение ресурсов, наводнение, рост культур, завершение вкладом, меню, permissions, ошибку провайдера и восстановление. Сценарий создаёт тестовый город и требует специальный маркер, loopback и JVM-флаг. На рабочем сервере его запускать нельзя. Подключённые клиенты, визуальный прогон с пользовательским ресурс-паком и многопользовательская нагрузка в сценарий не входят.

Кандидат прошёл 92 серверные проверки первого запуска и 96 после перезапуска (188 всего); все 36 аддонов и 38 API-контрактов загрузились. Обнаружено 118 исполняемых Java-тестов, локально пройдены тесты изменённых модулей и 9 тестов инструментария; полный набор запускается обязательным CI перед публикацией.
