# Обновление 0.38.0 — городские проекты

В набор добавлен **NeverLandTownyQuests 0.1.0**. Проект принадлежит UUID города: вклад жителей в здания и инфраструктуру учитывается совместно, а смена мэра, названия города или состава жителей не сбрасывает этапы. Удалённый и заново созданный город с другим UUID не наследует результаты.

## Цепочки

| Проект | Последовательность | Результат |
|---|---|---|
| Вода и санитария | Действующий акведук → вода в пяти районах 300 секунд → действующие бани | Санитарная реформа: +5 счастья, +10% содержания санитарных зданий |
| Городское здравоохранение | После санитарии: канализация → лечебница → вода в пяти районах 600 секунд | Общественное здравоохранение: +8 счастья, +20% содержания санитарных зданий |

Завершение открывает режим в категории **«Санитария и здоровье»** аддона Policies. Мэр принимает реформу отдельно через `/t policies`, с обычным подтверждением и ограничением частоты смены политики. Режимы заменяют друг друга. Повышенное содержание относится к баням, канализации, насосной и лечебнице. Начальный обычный режим нейтрален.

## Как засчитываются условия

- Здания должны быть завершены, работать по API Builds и целиком находиться на территории своего города. Уже построенные здания подходят.
- Пять районов — пять разных существующих районов Districts одновременно. Повторное наблюдение одного района не увеличивает счётчик.
- Все клетки каждого района должны соединяться с территорией акведука через соседние принадлежащие городу клетки в том же мире. Диагонали и неприсоединённые аванпосты не соединяют водную сеть. Используется размер клетки Towny, включая отрицательные координаты.
- Для водного этапа нужны работающие акведук, водонапорная башня, резервуар и насосная. Башня, резервуар и насосная также должны находиться на территории города. Resources должен сообщать полное водоснабжение и положительное население, связанное с Population.
- Вода пока рассчитывается Resources для всего города; Quests определяет снабжаемые районы по доступности акведука через городскую территорию. Прокладывать отдельные трубы не требуется.
- Засчитывается только наблюдаемое время работающего сервера. Дефицит воды или потеря нужного количества районов сбрасывает непрерывный отсчёт текущего этапа. Недоступность API, устаревшие данные, административная пауза и остановка сервера замораживают прогресс.
- Завершённый этап — сохранённое достижение. Изменение инфраструктуры позднее не отнимает уже засчитанный этап. Этапы проверяются последовательно, без пропуска.

## Команды и права

| Команда | Назначение |
|---|---|
| `/t quests` или `/townyquests` | Проекты своего города, этапы, условия и результаты |
| `/t quests info sanitation` | Подробности первой цепочки |
| `/t quests start sanitation` | Начать или продолжить первую цепочку |
| `/t quests start public_health` | Начать следующую цепочку после завершения санитарии |
| `/townyquests reload` | Проверить и применить новые настройки |
| `/nltadmin Quests list` | Найти ID текущего проекта |
| `/nltadmin Quests status <ID>` | Условия и состояние проекта |
| `/nltadmin Quests pause\|resume\|restart\|cancel <ID>` | Управление текущим проектом |

Просмотр: `neverlandtownyquests.use` (выдан по умолчанию). Начало и продолжение: мэр либо житель **своего** города с `neverlandtownyquests.manage`. Администрирование: OP или `neverlandtownyquests.admin`. Общее право `neverlandtownycontrol.admin` включает административное право Quests.

В `/nltadmin` проект доступен в категориях паузы, перезапуска и отмены. Кнопка журналов содержит отдельную категорию **«Городские проекты»**; управление администратором остаётся в **«Действиях администрации»**.

## Сохранение и отключение

В городе допускается один текущий проект, включая поставленный на паузу. Отмена освобождает это место, сохраняет этапы и не создаёт провал. Отменённый проект можно продолжить, когда нет другого текущего. Перезапуск сбрасывает только непрерывный отсчёт текущего этапа, сохраняя этапы и состояние паузы. Завершённый проект не перезапускается и не выдаёт повторный результат.

`quests-data.yml` содержит прогресс и снимок определения каждой начатой цепочки. Изменение или удаление её из `quests.yml` не подменяет условия действующего проекта и не отнимает завершённый результат. Новые определения применяются к ещё не начатым проектам. Повреждённая база не перезаписывается. Ошибка записи запрещает дальнейшую запись до успешной загрузки базы; результат не открывается до сохранения завершённого проекта.

`/nltmodules plan Quests` показывает группу остановки. `/nltmodules disable Quests` использует общий механизм безопасного отключения с зависимыми аддонами. При отсутствии Quests выбранная санитарная политика не даёт ни бонуса, ни дополнительной стоимости; заработанное открытие остаётся в базе. Для восстановления после включения требуется штатный перезапуск сервера.

## Настройки и API

`quests.yml` поддерживает последовательные этапы `BUILDING` (ID здания, уровень 1–5) и `WATER_DISTRICTS` (число районов), поле `hold-seconds`, зависимости `requires`, результат `unlock` и описание `reward`. Проверяются циклы зависимостей, уникальность результатов, целые положительные цели и допустимые интервалы. В `config.yml` задаются частота наблюдения и максимальный возраст расчёта ресурсов. При нестандартном длинном цикле Resources увеличьте допустимый возраст соответственно.

`TownyQuestsApi` v1 предоставляет `unlocked(UUID, String)` и неизменяемые снимки `quests(UUID)`. Вызывать в основном потоке сервера через Bukkit ServicesManager / ApiServices. Строковое описание результата само по себе не создаёт игровой эффект: встроенные ключи `sanitation_reform` и `public_health` использует Policies, собственные ключи должен обрабатывать потребитель API.

## Установка

Набор содержит 38 JAR. Обновите весь комплект вместе, удалив старые версии JAR, и полностью перезапустите сервер. Пользовательские конфиги сохраняются; новая категория политик подхватывается из встроенных значений по умолчанию. Для обеих встроенных цепочек нужны Builds, Districts, Resources и Population; для применения реформ — Policies и Upkeep. Платформа: Paper/Purpur 26.2, Towny 0.103.2.0, Java 25.
