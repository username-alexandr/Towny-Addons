# Оценка назначения и связи районов — Districts 0.2.0

Справочный планировщик показывает подходящие здания, доступность городских служб и связь с центральным участком. Он не назначает новые бонусы/штрафы, не меняет цены или запасы и не записывает оценку в базу. Существующие районы, фермы, производственные формулы и старые условия получения бонусов сохранены.

## Игроку

- `/t district assess` — все районы своего города.
- `/t district assess <id>` — выбранный район.
- В списке и карточке района добавлена одна кнопка «Оценка». Возврат и обновление находятся внизу; большой список имеет страницы.
- Доступ: прежнее `neverlandtownydistricts.use`. Изменять районы и выдавать себе права это действие не позволяет.

Карточка показывает, сколько участков остаётся за городом, сколько соединено с центральным участком и длину кратчайшей цепочки до него. Подходящие и другие работающие здания, неработающие/ещё не готовые площадки, пересечение границы и неучтённые определения перечисляются отдельно. Уже работающий текущий I уровень считается зданием для **оценки назначения**, даже если проект допускает последующие уровни. Условия производственного бонуса по-прежнему смотрятся в основной карточке района.

Для служб показывается покрытие в участках и ближайшие действительно найденные источники. Стандартные группы: жильё — вода/медицина/рынок; промышленность — склад/источники энергии; сельское хозяйство — орошение/склад; торговля и порт — склад/транспорт; военный район — снабжение/медицина; администрация — вода/связь и документы.

Это **географическая доступность для планирования**, а не обещание питания энергосетью, доставки груза или перемещения NPC. Реальные расходы, маршруты и работа сетей остаются в соответствующих аддонах. Если сам источник данных недоступен, карточка пишет «пока неизвестно»; неизвестное не превращается в нехватку службы или наказание игрокам.

## Как считается

- Используются участки Towny из метаданных. Центральный участок — Towny home block, он может отличаться от физической площадки ратуши.
- Путь проходит только через участки этого города, соприкасающиеся сторонами в одном мире. Диагонали, дикие промежутки, чужая земля и другой мир не создают связь. Геометрия дорог из блоков мира не сканируется.
- Служба обслуживает участок в пределах `assessment.service-range-cells` шагов по такому пути. Она может обслуживать самостоятельный удалённый район даже при отсутствии связи с городским центром.
- Источники — опубликованный API `Builds.buildingFootprints` и текущий работающий уровень `BuildingOperations`. Площадка должна целиком оставаться за городом. Учитывается полная закреплённая площадка проекта из API, включая пространство дальнейших уровней; сам планировщик схему не перечитывает и блоки не загружает.
- Для профиля здание должно целиком находиться в одном районе. Пересечение границы считается отдельно. Текущий работающий уровень должен быть положительным; код старого производственного расчёта не изменён.
- Проверка земель и центра отражает текущую метаинформацию Towny; площадки берутся из последнего опубликованного снимка Districts, обычно обновляемого раз в пять секунд. Московская дата относится к завершённой оценке. Неизвестный центр/незагруженный мир помечаются явно.

## Производительность и остановка

На вызывающем потоке захватываются только неизменяемые метаданные. Сам граф рассчитывает отдельный CPU-исполнитель: без Bukkit, Towny, чтения мира, диска и общей блокировки SuiteState. Первая просьба возвращает «готовится»; кнопка обновления получает готовый результат. Равные данные используют кеш; смена центра, районов, площадок, уровня, земли или настроек требует новой оценки. Пока старый расчёт выполняется, новые входные данные ждут его завершения и затем пересчитываются; устаревший результат не объявляется текущим.

Один исполнитель, очередь 16 задач, один незавершённый запрос на город, кеш до 128 городов. До 20 000 участков, 128 районов, 1024 площадок, 65 536 суммарных клеток площадок, 8 групп служб на тип и 8 альтернатив зданий на группу. Превышение даёт явную недоступность оценки; исходная механика города продолжает работать. Поиск ближайших служб выполняется многоточечным обходом, а не повторным поиском от каждого здания для каждого района. Даты и кеш не записываются в данные игроков.

При выключении новые запросы закрываются, производная очередь отменяется, CPU-обход прерывается, завершение ожидается вне SuiteState до закрытия загрузчика классов. Незавершённый производный отчёт можно пересчитать; он не содержит платежа, принятого вклада или другого несохранённого игрового действия.

## Конфигурация и API

```
assessment:
  enabled: true
  service-range-cells: 8
  # Необязательно; если задано, заменяет все стандартные группы целиком.
  services:
    residential:
      water:
        title: Водоснабжение
        buildings: [aqueduct, water_tower, reservoir]
```

Радиус — 0–64. Проекты служб должны быть определены в `projects.yml`. Неверная новая настройка отключает только оценку с предупреждением в журнале, оставляя прежние районы и эффекты. `assessment.enabled: false` также не меняет существующие данные/бонусы. Перезагрузка — прежняя `/districts reload` с административным правом.

Необязательная возможность API `assessment(UUID town)` возвращает только JDK-контейнеры, строки, числа и флаги: `available`, `pending`, `issue`, `checkedAt`, `sourceAt`, `homeKnown`, `claimed`, `reached`, `range`, `rows`. У каждого района — количество земель/связей/типов зданий и `services` с отдельным `known`, покрытием и ID ближайших источников. Потребитель обязан учитывать недоступность и неизвестные поля. Вызывать получение снимка следует с серверного/согласованного планировщика; только сам расчёт выполняется отдельно.

Формат `districts-data.yml` не меняется. **Старый DistrictRepository и очистка постоянных районов пока используют прежнюю синхронную запись при изменении**; этот общий пункт I/O остаётся открытым. Новая команда оценки не запускает прежний `refresh()` и сама не чистит/переписывает районы.

## Проверка

- DistrictAssessmentSmoke: 26 проверок и 1000 перестановок источников: границы радиуса, разрывы, разные миры, отрицательные/крайние координаты, I уровень, неполные площадки, неизвестные источники, неизменяемость и настройки.
- DistrictPlannerSmoke: 11 проверок кеша, очереди, ошибок и остановки. Настоящий непустой граф заканчивается, пока другой поток намеренно удерживает SuiteState.
- Прежние DistrictsSmoke / MobFarmPolicySmoke и 46 программ Builds прошли.
- Folia 26.2 build 7 / Towny 0.103.2.0: 15 проверок первого запуска и 5 после перезапуска. Реальные земли, центр, API Builds, команды и нативные карточки; отдельная база районов не меняется просмотром, прежний бонус кузницы 1.35 сохраняется при выключении/ошибке оценки и рестарте. Работающая мастерская I и промышленные здания V — явно сохранённые площадки стенда, реальное строительство/оплата не заявляются. Игрок/окно/EntityScheduler — явные офлайн-заменители с настоящим планировщиком региона; графического клиента нет.

Результаты: `docs/validation/city-systems-052/districts/`. Подготовленный первый стенд не запускался из-за конфликта имени District в исходнике пробы; итоговый второй собран и проверен на окончательных JAR. Ни один существующий серверный каталог не перезаписывался.

## Дополнение 0.2.1

Оценка формата 2 включает согласованный `assignments` — физическое соответствие всей принадлежащей городу площадки району, независимо от карты производственных бонусов. Пересекающая границы площадка не назначается; двойное назначение отклоняет снимок. Получатель проверяет `available` и `format` перед использованием. Выполнение общего ограниченного CPU-кеша выделено в DerivedViewCache; он предназначен только для производных данных. Повторная проверка на Folia: 16 + 5, включая действительную привязку мастерской I уровня; 27 проверок модели + 1000 перестановок, прежние 11 очереди. Точные артефакты и проверки — `docs/validation/city-systems-052/districts-021/`.
