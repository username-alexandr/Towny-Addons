# Проверка 0.22.1

Дата: 12 сентября 2026 года. Стенд: Purpur 26.2 build 2632, Temurin 25.0.4.1, Towny 0.103.2.0, Vault 1.7.3, EssentialsX 2.22.0 и все 27 аддонов.

## Подтверждённые результаты

- Проверка структуры исходников: 27 модулей, 98 исходных YAML, 90 зданий и 11 чудес.
- Полная сборка в GitHub Actions прошла для всех 27 модулей; выполнены все **89 исполняемых тестовых классов**. Производственный код собирается с целевым bytecode 17 на Java 25.
- Три новых класса проверяют 47 условий: реальные ошибки записи журнала, потерю ответа банка, восстановление наград, частичные выплаты каравана, возврат и миграцию.
- Все 28 скомпилированных публичных API прошли проверку объявленных игровых возможностей.
- Семь репозиториев прошли проверки отказа замены файла, сохранения блокировки после восстановления пути, повторной загрузки и сохранности повреждённого файла.
- Сервер: **54 проверки до принудительного завершения JVM и 50 после запуска с теми же данными**. Подтверждены удаление завершённых наград из очереди и сохранность результата после загрузки, нативное сохранение предметов, остановка скрытого отказа `saveData()`, отсутствие повторного списания покупателя, сохранность складского резерва, доставка и однократные выплаты после сверки.

Заключительный серверный сценарий использовал **неизменённые JAR из успешного [Verify №85](https://github.com/username-alexandr/Towny-Addons/actions/runs/34724301791)** для коммита `c4d067405090dda75febb55fc7d2232cea82bd77`. Перед запуском проверены SHA-256 архива CI, совпадение всех 27 JAR и чистое исходное состояние стенда. [Контрольные суммы JAR](validation-0.22.1/tested-jars-sha256.txt), [происхождение комплекта](validation-0.22.1/provenance.json), [отчёт всех тестов](validation-0.22.1/suite-tests.json). После этого менялись только документация и файлы подтверждений; выпуск заново собирает и проверяет те же производственные исходники. Его собственный `suite-tests.json` также публикуется среди файлов релиза.

## Время записи журнала

Каждый образец включает два полных сохранения журнала (`PENDING` → `DONE`) с синхронизацией файла. Три прогревочных образца отброшены, далее 20 измерений для каждого размера.

| Начальных записей | Медиана, мс | p95, мс | Максимум, мс |
|---:|---:|---:|---:|
| 1 | 1,210 | 1,423 | 1,435 |
| 100 | 5,295 | 6,126 | 8,168 |
| 1000 | 24,819 | 39,391 | 74,222 |

[Исходные измерения](validation-0.22.1/journal-latency.csv). Это замер локального файлового слоя при одном управляемом акторе, а не нагрузочное тестирование TPS. Несколько больших операций за тик могут создавать задержку; показатели нужно повторить на диске рабочего сервера перед изменением модели ввода-вывода.

## Границы проверки

Сетевой клиент заменён актором с настоящими нативными инвентарём и файлом игрока. Для положительной проверки мостов зданий кратковременно подставляются ответы обслуживания и питания; остальные операции используют реальные провайдеры. Клиентские меню, ItemsAdder/ModelEngine, длительная нагрузка и отключение питания машины этим сценарием не проверялись.

В журнале есть ожидаемые ошибки внедрённых отказов, сообщения недоступных внешних проверок обновлений/ключей Mojang и предупреждения сторонних плагинов при завершении. Успех означает прохождение перечисленных утверждений, а не отсутствие всех предупреждений в консоли.
