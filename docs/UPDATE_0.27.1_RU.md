# Обновление 0.27.1 — проверка публичных API

Комплект сохраняет 31 отдельный плагин. Все получают новую patch-версию, поскольку `ApiServices` включается в каждый JAR. Форматы игровых данных не меняются.

## Исправления

- **Market → Builds:** удалено требование несуществующей возможности `release`; проверяются `refund` и полный набор операций склада. Торговля больше не отклоняет совместимый Builds.
- **Companies ↔ Contracts:** вызовы идут через зарегистрированные публичные API с проверкой версии и возможностей. В `MintTownyContractsApi` добавлены `companyOffers`, `companyActiveCount`, `takeCompanyContract`, `releaseCompanyContract`. Прежние методы и точки входа сохранены.
- **Сохранённые соединения:** перед вызовом проверяются основной поток, включённый плагин и идентичность зарегистрированного сервиса. Отключение, отсутствие регистрации, несовместимость и ошибка выполнения имеют отдельные состояния диагностики. Бизнес-метод должен быть объявлен в `capabilities`; общие методы диагностики доступны отдельно.
- **Прямые вызовы:** Builds/CivicEffects, Contracts, Events и Chronicles отклоняют проверенные обращения к живым данным и мутации из рабочего потока до доступа к данным. API со специально предусмотренными снимками или переносом вызова в основной поток сохраняют своё поведение.

## Проверки

Общий запуск: `python scripts/build_suite.py --stage dist/plugins`. Команда применяется и в Verify, и при публикации. Gradle `smokeTest` использует тот же разбор Java и запуск каждого теста в отдельной JVM.

Java разбирается синтаксическим деревом: комментарий с `main()` не становится тестом; перестановка модификаторов, `String args[]` и varargs поддерживаются. Неизвестное имя модуля вызывает ошибку, частичный отчёт предыдущего запуска очищается.

Статическая проверка охватывает 33 контракта, 55 мест подключения и 88 разрешённых наборов требований. Динамический параметр `CompaniesBridge.allow` отдельно испытывается на настоящем сервере: проверены отрицательные ответы реального сервиса и положительные ответы подменённого поставщика для всех трёх методов. Настраиваемые имена поставщиков статически проверяются по значениям по умолчанию.

Файл `scripts/api-v1-baseline.tsv` снят с JAR опубликованного 0.27.0 после проверки SHA-256 ZIP. Он фиксирует 739 сигнатур, возможностей, default-методов, компонентов возвращаемых записей и значений перечислений. Несовместимое изменение или удаление прежнего контракта останавливает сборку; добавленные методы Contracts сохраняют API v1.

Локально прошли 100 исполняемых тестов всех 31 модулей, 7 проверок самого инструмента, сверка 33 скомпилированных API и отдельный Gradle `jar smokeTest` для Contracts. Нативный прогон: **226 проверок первого запуска + 224 после перезапуска**. Проверены регистрация и чтение всех API, требования потребителей, возврат и сохранность товара Market, восстановление после замены сервиса и запрет проверенных мутаций из рабочего потока. Подробности: [отчёт](validation/0.27.1/report.json), [первый запуск](validation/0.27.1/first-checks.txt), [перезапуск](validation/0.27.1/restart-checks.txt).

Это проверка совместимости на отдельном сервере. Она не заменяет нагрузочные замеры, визуальный осмотр клиентского ресурс-пака или проверку каждой игровой комбинации. Expeditions, Logistics и Stick не объявляют отдельного сервисного API; их код и тесты входят в общий запуск.

## Установка

1. Остановить сервер и сохранить резервную копию данных.
2. Заменить все 31 JAR из архива `NeverLandTownySuite-0.27.1-plugins.zip`; удалить старые версии этих JAR из `plugins`.
3. Запустить сервер на Paper/Purpur 26.2, Java 25 и Towny 0.103.2.0. Проверить загрузку аддонов и диагностику интеграций.

Нативный проверочный плагин намеренно не включён в релиз. Его инструкции находятся в `scripts/api-runtime-probe/README.md`.
