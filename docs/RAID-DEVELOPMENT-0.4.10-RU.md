# NeverLandTownyEvents 0.4.10 — набеги и развитие города

Чем больше в городе завершённых зданий и чем выше их уровни, тем сильнее новый набег. Врагов становится больше, у них растут здоровье и урон. Защитные постройки продолжают помогать городу.

## Правила для игроков

- Учитываются уже построенные здания. Если здание II уровня улучшается до III, до окончания стройки учитывается II уровень.
- Остановка производства не уменьшает развитие. Население, баланс казны и число игроков онлайн в этом расчёте не участвуют.
- Сила определяется при начале набега. Изменение зданий во время боя, пауза и перезапуск сервера не пересчитывают начавшийся рейд.
- Победа по-прежнему требует пройти десять волн. Уже побеждённые враги после рестарта не возвращаются.
- В `/t events` добавлена карточка «Сила набега»: обычный, усиленный, тяжёлый или осадный. В описании показано усиление врагов. Названия — удобные подписи; сам рост плавный.
- Рейды, начавшиеся до обновления, продолжаются с прежней сложностью.

## Начальные настройки баланса

Один завершённый уровень обычного здания даёт 1 очко развития. Чудо света по умолчанию даёт 10 очков за свой единственный уровень. Например, десять обычных зданий V уровня дают 50 очков. Вес каждого проекта можно изменить отдельно; нулевой вес исключает его из усиления.

`Доля усиления = min(очки развития / 200, 1)`.

Каждый множитель вычисляется как `1 + (максимальный множитель − 1) × доля усиления`.

| Очки развития | Число обычных врагов | Здоровье | Урон | Враги в первой стандартной волне |
|---:|---:|---:|---:|---:|
| 0 | ×1,00 | ×1,00 | ×1,00 | 4 |
| 50 | ×1,375 | ×1,25 | ×1,125 | 6 |
| 100 | ×1,75 | ×1,50 | ×1,25 | 7 |
| 200 и больше | ×2,50 | ×2,00 | ×1,50 | 10 |

Число добавленных врагов округляется до целого. Исходные враги каждой волны сохраняются, дополнительные добавляются по её составу. Капитан по умолчанию остаётся один; его здоровье и урон усиливаются. В последней стандартной волне при максимальном развитии 41 враг вместо 17, появляющихся с учётом одновременного лимита.

Это множители к прежним параметрам соответствующей волны, до применения городской защиты. Поздние волны сохраняют собственное усиление. Базовые награды, очки за каждого противника и правила выплаты не изменены; поскольку врагов больше, потенциальных очков за убийства тоже больше.

## Настройка администратора

При первом запуске автоматически создаётся `plugins/NeverLandTownyEvents/raid-scaling.yml`.

| Параметр | По умолчанию | Значение |
|---|---:|---|
| `enabled` | `true` | Усиливать новые набеги по развитию города |
| `full-strength-score` | `200` | Развитие, при котором достигается максимум |
| `maximum.count` | `2.5` | Максимальное увеличение числа обычных врагов |
| `maximum.health` | `2.0` | Максимальное увеличение здоровья |
| `maximum.damage` | `1.5` | Максимальное увеличение урона |
| `maximum.wave-size` | `60` | Предел размера волны после добавления врагов |
| `fixed-count-mobs` | `[captain]` | Противники, количество которых не увеличивается |
| `project-weights` | 1 для обычных, 10 для чудес | Вес уровня каждого проекта |

Волну, которую администратор уже настроил больше `maximum.wave-size`, плагин не сокращает. Общий предел количества врагов в определении волны — 200. Прежний предел одновременно живых мобов `gameplay.raid-max-alive-mobs-per-town` в `config.yml` сохранён (по умолчанию 18).

После редактирования: `/townyevents reload`. Новые значения применяются к следующим набегам. `enabled: false` возвращает обычную силу для новых рейдов, без поражений и штрафов. Для нейтральной отмены текущего события используйте `/townyevents cancel <город>`.

Административная диагностика: `/townyevents status <город>`. При активном набеге показывается сохранённая сила; если событий нет — расчёт для следующего набега. Доступ: OP или `mintevents.admin`.

Тестовый запуск: `/townyevents start raid <город>`. На городе под щитом новичка можно явно добавить `--force`. Используйте тестовый город: это запускает настоящих противников.

## Установка и данные

1. Остановите сервер и сохраните резервную копию папки `plugins/NeverLandTownyEvents`.
2. Уберите старый JAR Events из `plugins` и положите `NeverLandTownyEvents-0.4.10.jar`. В папке должен остаться один JAR этого плагина.
3. Существующую папку данных, `events-data.yml`, `events.yml`, `raids.yml`, `messages.yml` и `config.yml` сохраните. Удалять или заменять их не нужно.
4. Запустите сервер; настройте новый `raid-scaling.yml` при необходимости.

Обновляется только Events. Для этой функции не нужны новые Builds, Control или CraftoUI. Проверенная связка: Java 25, Folia 26.2 build 7 (`14b7fee`), Towny 0.103.2.0, Builds 0.8.34. Предыдущие возможности Events, включая ремонт пожара через меню, сохранены.

Уровни читаются через публичный API Builds. При отключённом/приостановленном модуле или недоступном совместимом API новые набеги используют обычную сложность, а диагностика показывает отсутствие данных. Сохранённые планы уже начавшихся рейдов не зависят от последующей доступности Builds.

В `events-data.yml` у новых набегов добавлены `plan-version`, `development` и `planned-waves`. Старые записи без плана читаются как прежние рейды. Сохраняются профиль развития, состав всех десяти волн и множители здоровья/урона. Базовые определения противников (модель, снаряжение, базовые характеристики) по-прежнему берутся из `raids.yml`: не удаляйте используемые типы и не меняйте их во время активного рейда, если хотите сохранить его баланс полностью.

После появления новых планов откат на старый JAR следует делать с резервной копией данных либо после завершения/нейтральной отмены активных рейдов: старый код не знает о сохранённом усилении.

## Проверки

В комплекте `validation` приведены результаты десяти исполняемых тестов Events и двух запусков отдельного тестового сервера Folia. Проверяются плавное усиление и пределы, сохранение состава волн, старые сохранения, отбраковка повреждённого плана и однократный учёт погибших врагов.

Проверка на Folia использует реальные Towny/Builds, создание городского рейда и настоящих мобов. Контролируются завершённые уровни зданий, резервная обычная сложность, атрибуты здоровья/урона, предел одновременных врагов, изменение зданий после старта, административный рестарт, пауза и повторный запуск сервера. Исходник тестового плагина: `scripts/raid-scaling-runtime-probe`.

Это автоматическая интеграционная проверка в отдельном мире, без игроков и сторонних моделей мобов. Массовые бои, отображение клиентского CraftoUI и баланс при живых игроках требуют плейтеста. Общая сборка всех модулей этим точечным обновлением не выполнялась.
