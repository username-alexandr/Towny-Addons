# Обновление 0.22.1

Плагины остаются отдельными. Выпуск продолжает унификацию денежных операций, API, сохранения данных и запуска проверок после 0.22.0.

## Исправления

- Завершение экспедиции и очередь наград сохраняются до выплаты. Деньги и каждая стопка предметов получают отдельные квитанции. Неопределённый результат не повторяется автоматически, полный инвентарь сохраняет предметы в очереди.
- Разовые караваны сохраняют намерение до резерва груза и списания. Складские операции используют неизменяемый UUID; груз и квитанция записываются вместе. Выплаты продавцу, транзитным городам и возврат покупателю имеют отдельные записи журнала.
- Лавка, получение рыночных товаров, муниципальные поставки и награды проверяют фактическое сохранение инвентаря. `Player.saveData()` может скрыть ошибку записи: подтверждением служат изменение файла, проверка GZIP и `force(true)`. Учтено расположение данных Paper/Purpur 26.2: `getWorldFolder()` указывает на измерение, а файл игрока находится в `<мир>/players/data`. Сохраняется поддержка прежнего `<мир>/playerdata`.
- Trade, Expeditions, Espionage и Chronicles используют публичный API Builds вместо приватного `dataStore`. Общий слой различает отсутствие плагина, отключение, несовместимость API и ошибку вызова.
- Исправлены возможности `BuildingStorageApi`, `TownyResourcesApi` и метаданные `MarketApi`. Скомпилированные контракты проверяются против реальных игровых методов; общие методы диагностики не входят в список игровых возможностей.
- Репозитории используют общий атомарный файловый слой. Governance, Reputation, Events, Ideologies, Chronicles, Taxes и Espionage перестали скрывать ошибки записи и пропускать повреждённые основные записи. Ошибка блокирует изменения до восстановления и корректной загрузки.
- Локальный `smokeTest` и общий раннер автоматически обнаруживают исполняемые тесты. Устранены дубли Maven build-helper в пяти POM. Удалены 14 устаревших JAR из Git; архив исходников исключает результаты сборки и кэши.

## Установка и сверка

1. Остановите сервер и сохраните резервную копию миров, Towny и каталогов аддонов.
2. Скачайте [релиз 0.22.1](https://github.com/username-alexandr/Towny-Addons/releases/tag/v0.22.1). Замените JAR используемых аддонов и удалите прежние версии. Среда: Java 25, Paper/Purpur 26.2, Towny 0.103.2.0.
3. Проверьте `/townybuilds diagnostics`, `/townyexpeditions payments`, `/townytrade list`, `/townytrade payments`.
4. Сохраните `reward-effects.yml`, `caravan-effects.yml` и складские квитанции внутри `town-data.yml`. Удаление журналов может разрешить повторную операцию.

Старый формат наград не позволяет доказать, была ли выполнена выплата перед сбоем. Старая очередь переносится в состояние сверки. После проверки банка и инвентаря:

```text
/townyexpeditions resolve <UUID операции> received confirm
/townyexpeditions resolve <UUID операции> not-received confirm
```

`received` подтверждает уже полученное. `not-received` разрешает попытку после подтверждения отсутствия выплаты/выдачи. Затем игрок использует `/expedition claim`. Решения сохраняются и записываются в журнал сервера.

Старые разовые караваны останавливаются в `LEGACY_REVIEW`. После сверки склада и счетов:

```text
/townytrade legacy <ID каравана> legacy-active confirm
/townytrade legacy <ID каравана> legacy-delivered confirm
/townytrade legacy <ID каравана> legacy-complete confirm
```

- `legacy-active`: товар зарезервирован и оплачен покупателем, но ещё не разгружен.
- `legacy-delivered`: товар разгружен, выплаты продавцу и транзитным городам требуют отдельной сверки.
- `legacy-complete`: подтверждены разгрузка и все выплаты; повторных действий не требуется.

Для неопределённых платежей караванов и старых отложенных зачислений:

```text
/townytrade payments
/townytrade resolve-payment <UUID операции> received confirm
/townytrade resolve-payment <UUID операции> not-received confirm
```

Если установлен Treasury+, сверьте также его зависший платёж. Подтверждение одного журнала не заменяет сверку другого. Регулярные договоры сохраняют существующую команду `/townytrade resolve`.

После файловой ошибки восстановите корректную копию и перезапустите сервер. Не удаляйте журнал спорных операций для обхода блокировки.

## Проверки

```bash
python scripts/verify_release.py --source-only
python scripts/build_suite.py --stage dist/plugins
python scripts/verify_release.py
python scripts/package_release.py --output dist/release
```

Сценарий аварийного восстановления находится в `scripts/reliability-runtime-probe`. Требуется отдельный стенд с адресом `127.0.0.1` и файлом `ALLOW_DISPOSABLE_RELIABILITY_PROBE`. **Не устанавливайте проверочный плагин на рабочий сервер:** первая фаза намеренно завершает JVM без штатного сохранения.

Сценарий использует реальные Towny/Vault, склад, нативный инвентарь и файл игрока. Сетевой клиент заменён управляемым актором. Только положительная проверка мостов зданий кратковременно подменяет ответы обслуживания и питания; реальные провайдеры восстанавливаются сразу после неё. Это не проверка полного цикла Upkeep/Power или клиентских меню.

Фактические результаты и ограничения: [отчёт](VALIDATION_0.22.1_RU.md).
