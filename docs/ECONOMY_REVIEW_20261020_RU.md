# Повторная проверка экономики — 20 октября 2026

Проверена ветка `feat/economy-mvp-20261020`, база `b8843d2638173851088f48d940ca4e5cd6e1303b`: новые публичные заказы, зарплаты, общий платёжный журнал, изменения Control и связанные проверки Towny/Vault, прав и планировщиков. Это проверка экономического MVP и его интеграций, а не полный аудит всех остальных аддонов.

## Найдено и исправлено

| Проблема | Последствие до исправления | Исправление |
|---|---|---|
| Отменённая смерть моба учитывалась публичными заказами и зарплатой стражника | Другой плагин мог отменить смерть и воскресить моба, а заработок уже засчитывался | `ActionGuard` отвергает отменённое событие; оба обработчика пропускают его и повторно проверяют окончательное состояние на планировщике игрока |
| Очередь каждый раз начинала с первых ожидающих записей | Недоступные получатели в начале очереди могли бесконечно задерживать остальных | Индекс только ожидающих записей с обходом по кругу; ошибка готовности одного получателя не прекращает обработку остальных; ошибки диска по-прежнему останавливают выплаты |
| Перед сдачей ресурсов проверялась только активность Towny | При неработающем Vault-провайдере ресурсы могли изыматься, а выплата оставалась ждать | Полная проверка готовности провайдера и получателя до работы с инвентарём; чтение исходной квитанции сохранения перенесено до создания HELD |
| Control создавал счета новых жителей, городов и наций без проверки экономики | При отсутствующем адаптере повторялся путь к предупреждению Towny о `economy == null` | Создание наблюдаемого счёта только после `TownyEconomyHandler.isActive()`; после восстановления экономики счета подхватит обычное сканирование |
| Уже открытая доска принимала заказ после отзыва права | Запрет команды не закрывал путь через старое меню | Право проверяется в самом действии принятия заказа |

Исходники изменений: `PublicOrders.java`, `WageService.java`, `RewardLedger.java`, `IncomeRuntime.java`, `ActionGuard.java`, `BankAudit.java`.

## Ограничения результата

Для платёжных проверок использован одноразовый провайдер `EconomyFixture`, а для проверки текста команд — ограниченный тестовый объект игрока. Это не проверка вашего рабочего экономического провайдера и не игровой проход настоящим клиентом через все профессии и покупку здания.

Сохраняются ранее описанные ограничения: автоматизация игрового клиента, сторонние откаты/WorldEdit и происхождение блоков до установки защиты требуют отдельных мер. Файловые сохранения остаются синхронными под общим замком: производительность с накопленной историей и реальным онлайном этим прогоном не подтверждена. Сценарии полной игровой приёмки — в `ECONOMY_ACCEPTANCE_RU.md`.

## Установка

1. Остановить сервер и сохранить резервную копию папок трёх аддонов.
2. Удалить прежние JAR Contracts, Jobs и Control; установить из пакета Contracts 0.3.17, Jobs 0.1.16 и Control 0.4.6.
3. Сохранить существующие папки данных и конфигурации. Формат журнала начислений не меняется; индекс очереди восстанавливается в памяти при загрузке.
4. Запустить сервер. Проверить `/orders admin status`, `/jobpay admin status`, затем `/orders` и `/orders mine`.

Тестовые плагины EconomyFixture/EconomyProbe в пакет установки не входят.
