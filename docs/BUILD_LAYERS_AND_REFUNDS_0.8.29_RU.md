# Слои строительства и отмена с возвратом

Обновление от 23 октября 2026: Builds **0.8.29**, Control **0.4.9**, Archaeology **0.1.21**. Это обновление трёх аддонов поверх набора 0.42.0; остальные JAR менять не требуется.

## Как строить

На площадке видны уменьшенные блоки-подсказки только первого незавершённого горизонтального слоя. Поставили все нужные блоки — открывается следующий слой. Подсказка показывает номер слоя, готовые блоки и оставшиеся материалы. Уже поставленные блоки не подсвечиваются. Если сломать нижний слой, подсказки вернутся к нему.

Подсказки — личные временные BlockDisplay, видимые соответствующему жителю города; они не заменяют настоящие блоки и не сохраняются в мире. Уход с площадки, телепорт, выход, завершение, пауза и выключение модуля убирают их. Это визуальное сопровождение: ставить настоящие блоки выше текущего слоя не запрещено. Ресурсы, цены и правила завершения зданий не изменены.

## Как отменить

**Мэр или уполномоченный советом строитель:** `/t builds` → строящееся здание → **«Отменить строительство»**. Перед подтверждением видно, сколько денег и каких ресурсов получит город.

По умолчанию комиссия **10% оплаченных денег и ресурсов**. Деньги возвращаются в **казну города**, ресурсы — на **городской склад**. Целые предметы и копейки округляются вниз: из 11 предметов при комиссии 10% вернутся 9. Неиспользованный излишек фонда возвращается полностью, без комиссии.

**Администратор:** `/nltadmin` → **«Отмена без провала»** → **Builds** → нужная стройка → подтверждение. Возврат **100%**, без комиссии. Администратор также получает полный возврат через меню здания своего города.

Отменяется только незавершённый этап. При отмене улучшения предыдущий уровень здания остаётся. Для новых строек сохраняются исходные блоки участка, поэтому можно восстановить землю, затронутую подготовкой площадки. Проверяются только конкретные клетки, записанные для этой стройки. Посторонние блоки и заполненные контейнеры останавливают разбор; сначала нужно освободить контейнер или проверить изменённую клетку. Если участок перестал принадлежать городу, разбор ждёт возврата территории. Частичный разбор продолжается после перезапуска.

Деньги и ресурсы выдаются после успешного разбора. Заполненный склад не приводит к потере: не поместившаяся часть остаётся в квитанции и поступает при освобождении места. Пока открыт склад, автоматическое пополнение ждёт его закрытия. Повторный клик не создаёт повторную выплату. Новая покупка того же проекта ждёт завершения возврата.

Музейные артефакты, оплаченные за отменяемое чудо света, возвращаются предметами на городской склад; их можно вновь передать музею. Для безопасного сохранения списания требуется Archaeology 0.1.21. При установленной старой/выключенной археологии новая платная стройка чуда не начинается и не списывает средства. Бесплатное размещение ранее открытого чуда имеет нулевую квитанцию и не создаёт денежный возврат.

## Установка

1. Остановите сервер и сделайте резервную копию миров, данных Towny, экономики и папок трёх аддонов.
2. Уберите старые JAR Builds, Control и Archaeology; поставьте новые из архива. Если Archaeology не использовался, устанавливать его впервые необязательно.
3. Сохраните существующие папки конфигурации и данных. Ничего из `town-data.yml` и базы музея удалять не нужно.
4. Запустите сервер. Новые настройки работают со значениями по умолчанию даже в старом `config.yml`. При желании добавьте их внутрь существующего раздела `settings.construction`:

```yaml
settings:
  construction:
    cancel-fee-percent: 10
    preview-enabled: true
    preview-interval-ticks: 10
    preview-distance: 64
    preview-max-blocks-per-player: 512
    preview-max-blocks-total: 4096
    preview-block-scale: 0.85
```

Не добавляйте второй раздел `settings`, если он уже есть. Комиссия допускает значения 0–100. Лимиты подсказок ограничивают число сущностей; если слой больше лимита, сначала видны ближайшие подсказки, остальные появляются по мере строительства. Площадка проверяется только в загруженных чанках и принадлежащем текущему потоку регионе Folia; подойдите к площадке, если подсказки недоступны. Очень большие чертежи на границе отдельных регионов могут ждать доступности всей площадки. Принудительной загрузки чужих чанков нет.

## Права и журнал

OP имеет доступ по умолчанию. Для администратора без OP:

```text
/lp user НИК permission set neverlandtownycontrol.admin true
/lp user НИК permission set neverlandtownybuilds.admin true
```

Право `neverlandtownybuilds.admin` включает `neverlandtownybuilds.admin.cancel`. Последнее отдельно разрешает полный возврат в меню собственного города; для команд сверки нужно также основное право Builds. Обычному игроку административные права не выдавайте: отмена зависит от его должности в городе.

В `/nltadmin` → журнал операций добавлен раздел **«Стройки и возвраты»**: покупка, запрос отмены, возврат денег, завершённый возврат и решения при сверке. В квитанции сохраняются уникальный номер операции, фактически оплаченные суммы и шаблоны предметов.

## Стройки, начатые до обновления

Старые версии не сохраняли квитанцию оплаты и исходный рельеф. Поэтому нельзя достоверно вычислить историческую стоимость по сегодняшнему конфигу. Существующие стройки продолжают работать; перед первой отменой старой стройки администратор сверяет её стоимость:

```text
/townybuilds refund legacy <город|UUID> <проект>
/townybuilds refund legacy <город|UUID> <проект> confirm <фактически_списанная_сумма>
```

Первая команда только показывает текущие требования. Если состав ресурсов менялся, перед подтверждением восстановите исторические требования этого проекта в конфиге и перечитайте настройки. После подтверждения доступна обычная отмена. Для старой стройки можно убрать зарегистрированные блоки текущего этапа и сохранить предыдущий уровень; восстановить неизвестный исходный ландшафт невозможно.

## Сверка после сбоя экономики

```text
/townybuilds refund list
/townybuilds refund resolve <город|UUID> <проект> <номер_квитанции> <решение>
```

Если сервер остановился между банковской операцией и записью подтверждения, повторная выплата/списание автоматически не выполняется. Сверьте журнал экономики по метке `[nlt-build:<номер>:debit]` или `[nlt-build:<номер>:refund]` и только после этого укажите результат:

| Состояние | Решение после проверки |
| --- | --- |
| `DEBIT_PENDING` | `paid` — деньги списаны; `not-paid` — не списаны |
| `DEBIT_CONFIRMED` | `paid` — подтверждённую оплату вернуть при отмене |
| `ARTIFACT_PENDING` | `artifacts-paid` — музей списал артефакты; `artifacts-not-paid` — не списал |
| `REFUND_PAYING` | `paid` — возврат уже поступил; `not-paid` — возврата не было |

Решение привязано к точному номеру квитанции и записывается в журнал. Нельзя выбирать `not-paid` без проверки: неверное ручное решение может вызвать повторную выплату. После ошибки записи данных модуль прекращает изменения; сначала исправьте причину и перезапустите сервер.

## Проверка

Сборка и исполняемые тесты: `python scripts/build_suite.py Builds Control Archaeology`. В отчёте — 49 тестовых программ трёх модулей, включая проверки первого незавершённого слоя, личных BlockDisplay, региональных ограничений, комиссии, переполненного склада, повторной отмены и ошибок записи до/после банковской операции. Совместимость существующих API проверяется отдельно при сборке.

На отдельном **Folia 26.2 build 7 / 14b7fee**, Java 25, Towny 0.103.2.0 выполнено **17 проверок за два запуска**: настоящие блоки и BlockDisplay, безопасный разбор, сохранение содержимого контейнеров, продолжение пакетного удаления и квитанции после рестарта. Исходники воспроизводимого теста: `scripts/construction-runtime-probe`; результаты: `docs/verification/construction-0.8.29`.

Не проверено клиентом Minecraft: внешний вид подсказок и клики меню. Не выполнен сквозной игровой сценарий оплаты через конкретный Vault-провайдер пользователя. Для первого плейтеста проверьте небольшую стройку, её улучшение, отмену мэром/администратором и заполненный склад на копии сервера.
