# План строительства и сохранение больших требований

Builds 0.11.0 предоставляет API `BuildingPlanningApi.development(town, goals)` для планировщика CraftoUI. План содержит до восьми целей, зависимости и каждый недостроенный уровень в порядке строительства. Общая зависимость, фонд конкретного уровня и один городской склад учитываются по одному разу. Уже удовлетворённые зависимости не раскрывают устаревшие требования предыдущих построек.

Расчёт не списывает деньги, не расходует материалы и не резервирует площадку. Открытый склад, активная стройка или невыясненная оплата обозначаются как требующие уточнения. Неизвестный город и циклические зависимости не получают частичную подтверждённую смету. Очередь ограничена двумя вычислениями; ответ завершается вне общей блокировки. Содержание и энергия доступны через отдельные API Upkeep/Power.

## Исправление количества материалов

На настоящей Folia найдено: редактор пытался сохранить требование на 120/272 предмета как один игровой стак. Ошибка сериализации приводила к пропуску ресурса в custom-projects.yml. Теперь количество свыше 99 сохраняется отдельно от образца из одного предмета: `nlt-counted-v1:<amount>:<base64>`. Название, компоненты и другие свойства образца сохраняются. Прежние base64-записи читаются без изменения.

Если ресурс не читается, проект закрывается до исправления настроек; цена не уменьшается молча. Ошибочная пользовательская запись запрещает сохранение всего custom-projects.yml до успешной перезагрузки каталога, поэтому редактирование другого здания не уничтожает её. Файл заменяется атомарно. Редактор и основной DataStore ещё относятся к незавершённой общей миграции записи без удержания SuiteState.

Перед обновлением сохраните копию projects.yml, custom-projects.yml и данных плагина. Старые версии Builds не читают новый counted-формат: для отката нужна соответствующая резервная копия. Ресурсы, уже потерянные старой версией из цены, автоматически восстановить нельзя; их следует восстановить из своей копии или в редакторе.

## Проверка

47 холодных программ проходят; DevelopmentPlanSmoke — 1027 проверок, включая перестановки целей. Нативная Folia 26.2/Java 25: 30 проверок первого запуска и 30 после полного перезапуска. Проверены настоящие ItemStack, сохранённые требования 272/120/80, пользовательские свойства, отказ неверных количеств/ресурсов, запрет перезаписи ошибочного каталога, фонды и склад без расхода, очередь, завершение вне SuiteState, удовлетворённая устаревшая зависимость и цикл.

Доказательства: `validation/city-systems-052/building-planning/`. Копии логов отличаются от исходных только удалением пробелов в конце строк. Это проверка API и сохранения на сервере; работа сетевого клиента и реальное строительство этим стендом не заявляются.
