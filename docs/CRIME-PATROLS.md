# Районные патрули и журнал происшествий

Новый раздел Crime хранит назначения жителям, их отчёты и подтверждённые городские происшествия. Патруль — поручение игроку, а не автоматически появляющийся NPC. Нахождение AFK не создаёт отчёта или выплаты. Назначение и сообщение не меняют прежние показатели преступности, кражи, резервы ресурсов и цены лавки.

## Игрокам

В `/t crime` добавлена кнопка «Районные патрули»; внутри можно переключиться на происшествия. Сначала показываются действующие задания, затем последние закрытые записи. Кнопка обновления не изменяет сохранённые данные.

| Команда | Назначение |
| --- | --- |
| `/t crime patrols` | Задания и отчёты города |
| `/t crime incidents` | Подтверждённые происшествия |
| `/t crime patrol <район> <житель>` | Назначить жителя в существующий район своего города |
| `/t crime report <UUID патруля> <текст>` | Сдать отчёт длиной 5–300 символов |
| `/t crime cancelpatrol <UUID патруля> <причина>` | Отменить назначение без штрафов |
| `/justice evidence <ID дела> incident <UUID происшествия>` | Прикрепить подтверждённое происшествие к существующему делу через Justice |

Назначает и отменяет мэр, администратор или участник совета с полномочием `justice`. Дополнительно требуется `neverlandtownycrime.manage` (по умолчанию true), а обычный просмотр — `neverlandtownycrime.use`. Один житель имеет не более одного действующего патруля в городе. Исполнитель должен оставаться жителем города. Для своего отчёта он приходит в назначенный район; уполномоченный управляющий может записать отчёт от своего имени. Смена исполнителя задним числом запрещена: старое поручение отменяют и создают новое.

Отчёт сохраняет автора и время закрытия. Он подтверждает только сообщение участника и проверенное присутствие при самостоятельной сдаче, а не посещение каждого участка или виновность другого игрока. Если район удалён, житель вышел из города или Districts временно недоступен, задание не проваливается автоматически. Управляющий может отменить его с причиной; при недоступном Districts отмена остаётся доступной.

## Происшествия и доказательства

В архив попадают только подтверждённые исходным движком `APPLIED`/`CLOSED` происшествия. `PLANNED`, предотвращённые и пропущенные события доказательствами не становятся. Сохраняются исходный ID, город, вид, виртуальный ресурс, точное количество и время. Ключ источника — `crime:<UUID>`; повтор после восстановления не создаёт другую запись.

Существующий движок создаёт происшествие для всего города. У него нет определённых координат, района и подозреваемого; новый журнал их не придумывает. Связь с делом Justice сама по себе не назначает штраф, розыск или виновного. Объём ресурса в API указан в тысячных долях; меню показывает обычные единицы. В `incidentEvidence(UUID)` поле `phase=APPLIED` обозначает подтверждённый факт применения, а не текущую фазу исходного происшествия.

## Хранение и совместимость

Отдельный `patrol-data.yml` schema 1 записывается асинхронно через атомарную замену. Новый отчёт, назначение или источник публикуются только после подтверждённой записи. Основной `crime-data.yml`, его schema 1, ресурсные резервирования, сроки и формула преступности не меняются. Прежнее основное сохранение Crime остаётся синхронным: перенос всего движка на асинхронное хранение не заявляется.

`patrols.enabled: false`, неверный тип этой настройки или повреждение нового журнала отключают только новый раздел; симуляция преступности продолжает работать. Старые данные и повреждённый файл не перезаписываются. Журнал ограничен 32 МиБ, 10 000 поручений и 20 000 происшествий; на город допускается до 256 действующих поручений. При заполнении новые записи отклоняются, существующая история не удаляется. Передача из текущего основного события повторяется после перезапуска; кратковременная очередь новых источников ограничена 512. Событие не объявляется доступным доказательством до подтверждения архива; при длительном отказе нового хранилища полная история исходной симуляции не гарантируется.

Для назначения и отчёта используется `Districts.patrolLayout(UUID)` — готовая геометрия с границами, размером участков Towny и временем публикации. Чтение не вызывает обновление районов или запись файлов. Изменённый, повреждённый или старше 15 секунд снимок считается недоступным; перед записью поручения/отчёта принадлежность участков проверяется по метаданным Towny, без чтения блоков мира.

Публичный API `patrols(UUID town)` отдаёт ограниченный неизменный снимок, а `incidentEvidence(UUID id)` — необязательный неизменный подтверждённый источник. Чтение не ждёт общий монитор и не вызывает Towny. Меню запрашивает обновление; фоновый пересчёт затрагивает только недавно запрошенные города (до 128 снимков, актуальность две минуты). Меню показывает до 256 последних записей каждого вида.

## Проверка

Сборка на закреплённом Folia API / Java 25: Crime 0.2.0 — PASS четырёх проверочных программ, включая новый `CrimePatrolsSmoke` (**25 проверок**) и прежние CrimeEngine/CrimeRepository/TheftRecovery. Проверены неизменность поручения, отчёт вместо пустого присутствия, строгие источники, дедупликация, физически задержанная запись, завершение при остановке, перезапуск и повреждение файла. Districts 0.2.3 — PASS шести программ, включая `PatrolLayoutSmoke` (**12 проверок**) готовой геометрии, неизменности, границы 15 секунд, dirty/ошибки источника и чужой земли.

Объединённая нативная проверка Crime + Justice + Districts на настоящей Folia 26.2: **37 + 7 + 6 = 50 проверок** на первом запуске, полном перезапуске и старте с повреждёнными optional-журналами. Поручения, авторы, ID происшествий, исходные дела, сроки и отдельные материалы сохранены; повреждение патрулей/апелляций не выключает исходные аддоны. Стенд явно использует офлайн-заменители Player/InventoryView/EntityScheduler и заданное историческое происшествие; настоящая кража и движение денег не заявляются. Хеши JAR, перечни проверок и ограничения: `validation/city-systems-052/crime-justice/`.
