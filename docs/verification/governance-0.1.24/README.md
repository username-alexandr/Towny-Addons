# Governance 0.1.24: объединение меню и прав

Сборка объединяет изменения ветки `codex/governance-council-buttons` (commit `5c1ff0106954ad71eae19a5533b6db39a5aae147`) с проверками `CouncilAccess.check` из `feat/mayor-access-controls`.

Сравнение с приложенным `NeverLandTownyGovernance-0.1.23(2).jar`: отсутствующих файлов нет, все классы меню совпадают побайтно. Отличия: номер версии, общий `CouncilAccess`, `GovernanceService` и его вложенные классы; в сервисе сохранена новая проверка полномочий на предложение законов. Ресурсы конфигурации и формат данных не менялись. Хеши и перечень отличий: `jar-comparison.json`.

Проверки:

- Java 25 / Gradle 9: 4 исполняемых smoke-теста, включая 14 проверок подтверждения и одноразового действия меню; 13 Python-проверок сборки прошли.
- API v1: 27 сигнатур/возможностей совместимы; проверка отказов репозитория пройдена.
- Folia 26.2 build 7 (`14b7fee`), Towny 0.103.2.0, Council 0.1.14: 33 проверки меню, назначения/снятия, страниц, офлайн-жителей, повторного клика, устаревшего подтверждения, отозванного доступа, закрытого инвентаря и ушедшего жителя.
- В том же прогоне подтверждено: назначенный казначей может предлагать налоговые законы; личный запрет мэра блокирует действие; разрешение и сброс настройки восстанавливают соответствующий доступ.
- После полного перезапуска: 4 проверки загрузки плагина, города, назначения и истории.

Ограничения: игрок, InventoryView и EntityScheduler представлены тестовыми объектами; события, инвентари, Towny, Governance и сохранение настоящие. Проверка пользовательского клиента CraftoUI и полноценный сетевой плейтест не выполнялись. Citizens/Elections не установлены на стенде, их ограничения оставлены в общем сервисе. В логах возможны внешние ошибки получения ключей Mojang у изолированного offline-mode сервера; они не являются ошибками Governance.

Другие JAR пакета не изменялись. Их прежние результаты находятся в `access-farms-20261024`.
