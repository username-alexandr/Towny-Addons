# Армейские специальности, приказы и полевые комплекты

Army 0.3.0 добавляет специальности и снаряжение поверх существующей службы. Звания, подразделения, присяга, обучение, гарнизон и снабжение осадного лагеря сохраняются. Control 0.6.4 добавляет отдельную категорию журнала армии.

## Для игроков

В `/army` появилась кнопка «Специальности, комплекты и приказы». Можно также использовать `/army tactics`, `/army orders` и `/army kit`.

Комплект получают после присяги на военной базе своего города. Сначала открывается окно с составом и стоимостью. Затем игрок отдельно подтверждает выдачу. Требуется место для всего комплекта. Стоимость списывается из военных запасов города; деньги не создаются. Обычная экипировка сохраняет обычные свойства Minecraft.

| Специальность | Стандартный комплект | Стоимость в военных запасах |
| --- | --- | --- |
| Боец | Железные меч, шлем и нагрудник, щит, 8 хлеба | 13 металла, 6 древесины, 8 еды |
| Сапёр | Железная кирка, огниво, 4 TNT | 4 металла, 2 древесины, 20 материалов |
| Медик | 4 взрывных зелья лечения I, 8 хлеба | 8 знаний, 4 воды, 8 еды, 4 материала |
| Снабженец | 32 хлеба, 32 стрелы | 32 еды, 8 древесины, 8 материалов |

По умолчанию разрешено до двух комплектов на игрока за скользящие 24 часа, с перерывом не менее часа. Переход в другой город не обнуляет ограничение. Завершённая отмена без выдачи освобождает лимит. Неясный результат выдачи блокирует новые комплекты до сверки.

Специальность определяет комплект, не меняет звание и подразделение. Для нового бойца используется «Боец». Роль привязана к городу. Сапёр не получает дополнительных прав обходить ограничения TNT; лечебные зелья действуют по обычным правилам сервера.

## Для командования

- `/army specialty <игрок>` — выбор специальности в меню.
- `/army specialty <игрок> <soldier|sapper|medic|supplier>` — назначение. Нужны полномочия капитана; назначать старшему по званию может только мэр или уполномоченный руководитель.
- `/army order <rally|attack|defend|supply> <all|infantry|cavalry|navy|air> <описание>` — приказ в текущую точку командира. Нужны полномочия лейтенанта.
- `/army orders` — список приказов. Боец подтверждает получение и отдельно прибытие к точке. Прибытие проверяется по миру и расстоянию. Завершение задачи отмечает командир.

По умолчанию приказ действует 30 минут, радиус прибытия — 16 блоков, одновременно открыто до восьми приказов на город. Условия сохраняются при создании: изменение конфигурации не меняет уже выданный приказ. Отмена и истечение срока не штрафуют игроков и не создают награды. Это координация отряда, а не автоматическое доказательство победы или доставки припасов.

Город, присяга, гражданство, RP-возраст и действующие полномочия проверяются повторно при действии. Изменение прав после открытия окна не позволяет выполнить старое действие.

## Сверка администратора

В `/nltadmin logs` находится категория «Армия: специальности, приказы, комплекты». В записях сохраняются автор, получатель, город, ID операции, этап выдачи и первоначальная стоимость. Основной армейский журнал кадровых приказов остаётся доступен отдельно.

Для неизвестного результата сначала игрок нажимает «Проверить сохранение игрока» в окне комплекта. Если в `player.dat` найдена квитанция именно этой операции, выдача подтверждается без повторной выдачи предметов.

Если автоматическое подтверждение невозможно, администратор сверяет фактическое состояние и открывает отдельное подтверждение:

```
/army kitreview <UUID> delivered <причина>
/army kitreview <UUID> return <причина>
```

`delivered` отмечает уже полученное снаряжение. `return` используется только после подтверждения, что снаряжение не было получено: возвращает первоначальную стоимость в военные запасы. Возврат не изымает уже полученные предметы. Решение, причина и действительный администратор записываются в журнал. Повторное подтверждение завершённой квитанции не создаёт предметов или запасов.

Права LuckPerms:

- `neverlandtownyarmy.use` — меню армии; по умолчанию всем.
- `neverlandtownyarmy.kit` — получение комплектов; по умолчанию всем, с обязательными условиями службы и базы.
- `neverlandtownyarmy.manage` — разрешает проверять полномочия командования; само право не делает игрока командиром.
- `neverlandtownyarmy.admin` — сверка выдач; по умолчанию OP.
- `neverlandtownyarmy.specialty.soldier`, `.sapper`, `.medic`, `.supplier` — выдаваемые модулем признаки текущей специальности, не самостоятельное разрешение на выдачу.

## Конфигурация и установка

Обновляются Army до 0.3.0 и Control до 0.6.4. Для лагерного снабжения нужен SiegesPlus не ниже 0.6.4 с подтверждаемым API Army. В каталоге `plugins` должен оставаться один JAR каждого плагина. Замена выполняется при остановленном сервере.

Существующий `army-data.yml` сохраняет состав и запасы. Дополнительные роли, приказы и квитанции хранятся в `army-tactics.yml`. Старый конфиг не нужно удалять: отсутствующие параметры получают значения из стандартного конфига JAR.

Настройки находятся в `tactics`: `enabled`, `kits-per-24h`, `kit-cooldown-seconds`, `order-duration-seconds`, `arrival-radius`, `max-active-orders`, `kits.<специальность>.cost` и `.items`. В `cost` используются обычные единицы стратегических ресурсов, допускается точность до 0,001. Идентификаторы предметов — точные прописные имена Bukkit; лечебное зелье обозначено `SPLASH_POTION_HEALING`. Комплект ограничен 16 стопками. Для изменения комплекта задаются оба раздела, `cost` и `items`.

`/army reload` проверяет конфигурацию до замены настроек. Занятая выдача сначала должна закончиться. `tactics.enabled: false` останавливает новые действия раздела; восстановление уже принятых выдач и отправка аудита продолжаются, если основной модуль доступен. Повреждённый дополнительный файл сохраняется для ремонта и не отключает основной состав армии. После исправления файла требуется перезапуск сервера.

Перед обновлением сохраните согласованную резервную копию плагинных данных и данных игроков. После первой новой выдачи основной файл может содержать этапы `KIT_SPENT` и `KIT_RETURNED`, неизвестные старой версии Army. Обратная замена одного JAR на 0.2.x не поддерживается: восстановление старой версии требует сверки всех новых выдач и согласованных данных, чтобы не вернуть расходы поверх уже выданных предметов.

## Гарантии и ограничения

Порядок: сохранение намерения → подтверждённый расход запасов → сохранённое разрешение выдать → изменение инвентаря в потоке игрока → проверка точной квитанции в `player.dat` → подтверждение завершения. Нативное сохранение игрока выполняется без общей блокировки аддонов; чтение файла для проверки — в ограниченной фоновой очереди.

До изменения инвентаря выдачу можно отменить с точным возвратом. После начала внешнего эффекта отсутствие подтверждения означает сверку, а не автоматическую повторную выдачу или возврат. При остановке принятые операции завершают сохранение либо оставляют квитанцию для восстановления. При административной паузе не начисляются штрафы.

Журналы ограничены по объёму. Достижение предела останавливает новые изменения, а не удаляет квитанции неизвестных выдач. Старый внешний I/O Resources, миграция старого состава и файловый журнал осадного снабжения остаются отдельной задачей; эта версия не объявляет весь набор аддонов свободным от синхронного I/O.
