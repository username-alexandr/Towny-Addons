# Ремонт после пожара — обновление 25.10.2026

Обновлены Events 0.4.9, Builds 0.8.31 и Control 0.4.11.

## Для игроков

1. Дождитесь окончания пожара.
2. Почините или перестройте пострадавший участок на свой вкус. Можно использовать другие материалы.
3. Откройте `/t events repairs` → выберите участок → нажмите **«Ремонт завершён»**.

Кнопка закрывает ремонт только выбранного участка. Она не ставит блоки, не меняет их направление и не забирает вещи или деньги. Это подтверждение на доверии: плагин не проверяет, действительно ли игрок восстановил постройку.

Подтвердить ремонт может владелец участка или мэр. Управляющему можно отдельно выдать `mintevents.repair.manage` — только для его собственного города. Обычный житель не может закрыть ремонт чужого участка. `/t events repair` тоже открывает выбор участка и ничего сразу не подтверждает.

После подтверждения ремонт исчезает из списка. Повреждения других участков остаются. Незавершённый ремонт препятствует стройке лишь на затронутых участках, а новый пожар в городе по-прежнему не запускается до завершения всего ремонта. Штатное обслуживание и улучшение зарегистрированных процедурных зданий Builds сохраняется.

## Для администратора

`/nltadmin` → **«Ремонт после пожара»** → город → участок → **«Ремонт завершён»**.

Администратору не нужно состоять в городе. Доступ: OP или `neverlandtownycontrol.admin`; отдельное управление событиями — `mintevents.admin` и `/townyevents repairmenu`.

Журнал: `/nltadmin` → «Журналы операций» → **«Ремонт после пожара»**. Он показывает автора, город, участок и результат. Исходные записи хранятся в `NeverLandTownyEvents/audit/`. Подготовленная запись без итоговой требует сверки с `fire-damage.yml`, например после аварийного выключения между сохранением ремонта и итоговой записью журнала.

Пока пожар активен или поставлен на паузу, закрывать ремонт нельзя. Для завершения аварийного события используйте существующую отмену без провала, затем подтвердите нужные участки. Отключённый модуль не удаляет записи ремонта.

## Установка и сохранность данных

1. Остановите сервер и сохраните резервную копию папок плагинов.
2. Удалите старые JAR только Events, Builds и Control; установите новые версии. Не оставляйте две версии одного плагина в `plugins/`.
3. Папки данных и конфиги оставьте. Особенно не удаляйте `fire-damage.yml`: существующие повреждения автоматически появляются в новом меню по участкам.
4. Запустите сервер. Обновление не меняет цены зданий, ресурсы или счета.

Права `mintevents.use` и `mintevents.repair` по умолчанию доступны игрокам, но подтверждение ограничено владением участком или полномочиями мэра. `mintevents.repair.manage` по умолчанию выключено.

Пример назначения управляющего: `/lp user ИМЯ permission set mintevents.repair.manage true`.
