# Население города — Suite 0.7.9

Новый аддон **NeverLandTownyPopulation 0.1.0** добавляет городское население, прирост, жильё, довольство, занятость, еду и воду. **NeverLandTownyBuilds 0.7.7** добавляет жилой квартал. В наборе теперь 15 аддонов, 80 зданий и 11 чудес.

## Установка

1. Остановите сервер и сохраните резервную копию мира и данных плагинов.
2. Замените старый Builds на `NeverLandTownyBuilds-0.7.7.jar`; добавьте `NeverLandTownyPopulation-0.1.0.jar`. Остальные 13 аддонов не изменились.
3. Запустите Paper/Purpur 26.2 на Java 25 с Towny 0.103.2.0. Population требует Towny и Builds; PlaceholderAPI необязателен.
4. Откройте `/t population`. Новые и существующие города автоматически получают стартовое население. Жилой квартал появится в инфраструктуре `/t builds`, в том числе со старым `projects.yml`.

Старые постройки и ресурсы сохраняются. Установленные пользовательские значения конфигурации не перезаписываются.

## Как рассчитывается население

Это числовое население поселения. Оно существует отдельно от списка игроков Towny, возраста персонажей и состава армии. Аддон не создаёт сущности жителей и не меняет гражданство игроков.

Цикл по умолчанию длится **1200 секунд работающего сервера**. Исходное население — **10**, базовое жильё, еда и вода рассчитаны на **20**, стартовых рабочих мест — **12**. Данные рассчитываются и для городов, участники которых сейчас не в игре.

| Показатель | Правило |
|---|---|
| Жильё | Базовые места плюс вклад законченных жилых зданий |
| Трудоспособные | Население × 60%, с округлением вверх |
| Безработица | Доля трудоспособных, которым не хватило рабочих мест |
| Еда и вода | Суммарное снабжение / потребность жителей, до 100% |
| Довольство | База 70 + городские удобства − штрафы, в пределах 0–100 |
| Рост | Полное снабжение, свободное жильё и довольство от 55% |
| Убыль | Снабжение ниже 75%, нехватка жилья или довольство ниже 25% |

Довольство теряет до 30 пунктов от безработицы, до 40 от нехватки жилья и до 60 за каждый вид дефицита снабжения. Штраф пропорционален недостатку. Удобства дают постоянную прибавку к довольству.

При благоприятных условиях прирост за цикл равен `max(1, население × 0.05) × довольство / 100`. Он ограничен свободным жильём, обеспечением едой и водой и общим пределом из настроек. Дробный прирост накапливается между циклами.

При критическом дефиците убыль равна `max(1, население × 0.10 × тяжесть дефицита)`, но не больше текущего населения. Тяжесть — наибольшая доля нехватки жилья, критически недостающего снабжения или падения довольства относительно порога убыли. Отсутствие части жилья вызывает постепенную убыль. При смене роста на убыль прежний дробный остаток сбрасывается. Нулевые коэффициенты роста или убыли отключают соответствующее изменение.

Если снабжения хватает на 75–99% жителей, рост останавливается; другие причины, например очень низкое довольство, по-прежнему могут вызвать убыль. После восстановления условий население снова растёт, даже если сократилось до нуля.

Еда и вода здесь — **возобновляемая мощность снабжения**, а не предметы в сундуке: аддон не забирает хлеб, пшеницу или вёдра из инвентарей. Рабочие места влияют на безработицу и довольство; нехватка работников не отключает производство.

## Вклад зданий

По умолчанию здания начинают обеспечивать население **только после V этапа**, чудеса — после I. Незаконченный фундамент не даёт жильё или снабжение. Завершённые этапы читаются через публичный API Builds; ручное разрушение блоков без изменения состояния проекта в Builds не считается сносом в Population.

| Здание | Жильё | Еда | Вода | Работа | Довольство |
|---|---:|---:|---:|---:|---:|
| Жилой квартал | 120 | 0 | 0 | 6 | 0 |
| Приют | 40 | 0 | 0 | 6 | +3 |
| Таверна и постоялый двор | 20 | 20 | 0 | 12 | +4 |
| Аграрный комплекс | 0 | 200 | 0 | 30 | 0 |
| Пекарня | 0 | 80 | 0 | 12 | 0 |
| Мельница | 0 | 60 | 0 | 10 | 0 |
| Водонапорная башня | 0 | 0 | 200 | 6 | 0 |
| Резервуар | 0 | 0 | 150 | 6 | 0 |
| Акведук | 0 | 0 | 120 | 12 | 0 |
| Ирригационная станция | 0 | 40 | 40 | 12 | 0 |
| Лазарет | 0 | 0 | 0 | 15 | +6 |
| Канализация | 0 | 0 | 0 | 10 | +6 |

Полный список всех 91 проектов доступен в `/t population buildings` и в `plugins/NeverLandTownyPopulation/buildings.yml`. У каждого проекта задаются название, иконка, минимальный и максимальный активный уровень и мощности. Вклад равен мощности, умноженной на число завершённых уровней между этими границами. Значения по умолчанию включаются однократно после завершения здания. Можно добавлять ID из `custom-projects.yml`; чтобы отключить вклад существующего здания, укажите нулевые мощности.

## Команды и права

| Команда | Доступ |
|---|---|
| `/t population` | Меню своего города |
| `/t population info` | Сводка и причины остановки роста в чате |
| `/t population buildings` | Страницы вклада зданий |
| `/townypopulation info <город>` | Администратор; также консоль |
| `/townypopulation buildings <город>` | Администратор, меню чужого города |
| `/townypopulation set <город> <число>` | Администратор; число от 0 до заданного максимума |
| `/townypopulation reload` | Администратор; перечитать настройки без сброса населения |

Прямая команда `/townypopulation` и её псевдонимы `/population`, `/nltpopulation` доступны независимо от регистрации подкоманды Towny. Право `neverlandtownypopulation.use` включено всем; `neverlandtownypopulation.admin` — операторам. Обычные игроки видят свой город. Права и гражданство повторно проверяются при работе с меню.

## Настройки, сохранение и интеграции

* `config.yml` — период, начальное население, общий предел, потребности, занятость, пороги и штрафы.
* `buildings.yml` — вклад зданий и чудес, включая пользовательские проекты.
* `messages.yml` — сообщения и префикс `NeverLand • Население`.
* `population-data.yml` — записи по UUID города: население, дробный остаток, прошлое изменение и время расчёта.

База сохраняется после изменений и при остановке через временный файл и замену. Повреждённая база блокирует запуск аддона, сохраняя исходный файл. Неверные настройки при `/reload` не заменяют действующие параметры. При перезапуске начинается новый полный цикл; время выключенного сервера не догоняется. Дробный остаток сохраняется. При недоступности API Builds симуляция приостанавливается до восстановления, чтобы ошибка зависимости не вызвала массовую убыль. Удалённые города очищаются из базы; переименование сохраняет население благодаря UUID.

Показатели обновляются с интервалом до 10 секунд; открытие меню обновляет их сразу. Нажатие «Обновить» не ускоряет симуляцию. Смена длительности цикла применяется к уже прошедшему времени текущего цикла.

PlaceholderAPI использует `%nltpopulation_<поле>%`:

| Поле | Значение |
|---|---|
| `population`, `housing`, `jobs` | Население, жильё, рабочие места |
| `employed`, `unemployed` | Работающие и безработные |
| `unemployment`, `happiness`, `food`, `water` | Проценты без знака `%` |
| `growth` | Прогноз изменения за цикл; при паузе 0 |
| `last_change` | Изменение за последний цикл |
| `paused` | `да` или `нет` |

Для игрока без города возвращается пустая строка. Публичный `TownyPopulationApi` зарегистрирован в Bukkit ServicesManager; его неизменяемые снимки можно читать из асинхронных интеграций. Пример: `population(townUUID)` или `residentPopulation(residentUUID)`.

Проверки расчётов, сохранения и генерации зданий выполняются автоматически. Интерактивное меню и игровой вид жилого квартала следует дополнительно проверить на рабочей сборке сервера; визуальная проверка в Minecraft в этой среде не выполнялась.
