# Проверяемая локальная сборка

`scripts/build_pinned_folia.py` компилирует код против настоящих библиотек подготовленного Folia и указанных JAR Towny/PlaceholderAPI. Это дополнительный офлайн-путь проверки; API-заглушки не используются.

Готовый JAR появляется только после успешной компиляции и всех обнаруженных исполняемых smoke-проверок модуля. До и после упаковки сравниваются отпечатки исходников, ресурсов, тестов и сценария сборки. При изменениях требуется новая сборка; прежний проверенный JAR сохраняется. Замена выполняется атомарно. Одновременная сборка одного модуля запрещена файловым замком, поскольку компиляторы иначе делили бы каталог классов.

Внутри JAR находится `META-INF/neverland-build.json`: версия модуля, перечень и отпечатки входных исходников, список прошедших проверок и целевая платформа. Это не подпись издателя и не доказательство проверки графического клиента или конкретного экономического провайдера. Хеш точного JAR отдельно фиксируется нативным стендом. Перед подготовкой такого стенда нужно дождаться завершения сборки; копирование старого одноимённого JAR во время компиляции не доказывает проверку нового кода.

Проверки сценария охватывают изменение и добавление исходника, сохранение старого JAR при отказе, выход за корень проекта, метаданные и взаимное исключение компиляторов.

Общий аудит теперь использует отдельный замок журнала вместо одного монитора класса для всех путей. `AuditPathIsolationSmoke` действительно блокирует один журнал и проверяет продолжение работы другого под общей блокировкой SuiteState. Медленный диск одного журнала всё ещё может задержать его собственных синхронных вызывающих: это частичный шаг, не завершение общей миграции хранилищ.
