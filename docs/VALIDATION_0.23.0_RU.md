# Проверка 0.23.0 — 13 сентября 2026

Проверены неизменённые JAR из [CI для 990c594](https://github.com/username-alexandr/Towny-Addons/actions/runs/34727726477), включая исправление пустого списка покупок. Контрольные суммы установленного комплекта совпали с артефактом CI.

## Сборка и структура

- 27 модулей собраны по единому сценарию; выполнены 93 тестовых класса.
- Проверены 28 публичных API-контрактов и 7 репозиториев с имитацией ошибок хранения.
- Проверены 98 YAML-файлов, матрица версий, 27 JAR, 90 зданий и 11 чудес.
- Согласованы версии plugin.yml, Gradle и Maven. Все места создания меню используют общий MenuStyle; инвентарь игрока и складские предметы не изменяются.

## Сервер

Изолированный Purpur 26.2-2632, Towny 0.103.2.0, Vault 1.7.3, EssentialsX 2.22.0, Java 25. Все 27 аддонов включились. Сценарий работает только на явно отмеченном одноразовом сервере с адресом 127.0.0.1 и флагом `neverland.runtimeProbe`.

Использованы настоящие Bukkit-инвентари, блоки мира, казна Towny и данные нативного ServerPlayer. Открытый экран и сообщения отсутствующего клиента перехватывались тестовым адаптером. Клиент с пользовательским ресурспаком не подключался; расположение текста на его фактических текстурах и шрифтах, а также нагрузка массовых открытий меню не измерялись.

Первая часть: **123 проверки**. Затем процесс аварийно завершён через `Runtime.halt(23)`. После нового запуска: **39 проверок**.

Проверены:

- 29 окон: основные меню всех 25 аддонов с GUI и дополнительные окна построек, армии, покупок и ремонта. Названия и описания не содержат тёмных цветов или включённого курсива. Заголовки и переносы отдельно проверены MenuStyleSmoke.
- Колокол торгового центра, понятный пустой список покупок, справка логистики с отдельными полными командами.
- Возврат казны к ранее открытому меню, закрытие при открытии командой, переход отчёт → недели → обзор.
- Скрытие CSV без права, отказ команды без права, отзыв права после открытия окна и фактическое создание CSV после выдачи права на неделе с поступлением денег.
- Визуальный очаг сохраняет дерево; частицы создаются без ошибки. Тушение водой добавляет прогресс защиты.
- Камень, сундуки, бочки, одиночный ствол и чужая/незаявленная территория не разрушаются.
- Деревянный декор исчезает после записи исходного BlockData. Повторная обработка того же места не создаёт второй ущерб.
- Сбой записи журнала оставляет блок целым и блокирует новые разрушения до восстановления.
- Завершение события сохраняет обязательный ремонт. Новый пожар, улучшение здания, автоматический ремонт и миграция архитектуры не обходят долг.
- После аварийного перезапуска отверстие и журнал остаются. Неверный материал не подтверждается, право ремонта проверяется, правильный материал восстанавливает исходные направление и половину ступеньки. Подтверждение сохраняется и снимает блокировку Builds.

## Воспроизведение и результаты

На подготовленном одноразовом сервере с зависимостями и 27 JAR:

```bash
python scripts/menus-fire-runtime-probe/build.py --server-dir /path/to/disposable-server --java-home /path/to/jdk25
python scripts/menus-fire-runtime-probe/run.py --server-dir /path/to/disposable-server --java-home /path/to/jdk25
```

Предварительно создайте файл `ALLOW_DISPOSABLE_RELIABILITY_PROBE` и настройте `server-ip=127.0.0.1`. Проба создаёт город, жителя и участки, меняет мир и намеренно прерывает процесс. Для повторного запуска нужна исходная чистая копия сервера. На рабочем сервере её не устанавливать.
