# Suite 0.43.1 — исправление остановки Folia

27.10.2026. Events 0.4.12, Control 0.4.15, Chronicles 0.1.20, Builds 0.8.36. Все версии — в `versions.yml`.

## Причина

В Folia региональные тики прекращаются до отключения плагинов. Events 0.4.11 сохранял данные активного события, затем из `onDisable()` вызывал очистку рейдовых мобов через `WorldTasks.eachEntityCleanup`. Пока Control ещё был включён, общий код выбирал его владельцем задачи и обращался к уже остановленному региональному планировщику. Это приводило к `NullPointerException` в `FoliaRegionScheduler.scheduleInternalOnRegion`.

Порядок остановки описан в официальной документации: https://docs.papermc.io/folia/reference/overview/#server-shutdown-process . Это отдельный сценарий от ожидания общей блокировки, исправленного в 0.43.0. В прежнем тесте не было активного рейда при остановке, поэтому он не выполнял этот путь.

## Изменения

- Общий `SuiteScheduler` не создаёт новые задачи после начала остановки, отменяет ожидающие callback и не переносит очистку исчезнувшей сущности на уже остановленный планировщик.
- Если остановка начинается между проверкой и самой постановкой задачи, ошибка постановки приводит к отмене задачи. Вне остановки исключение не скрывается. Системные ошибки Java `Error` также не скрываются.
- `WorldTasks` не перебирает чанки и не удаляет сущности через региональные задачи при полной остановке. Очистка игроков также пропускается.
- Events продолжает синхронно сохранять активные события, прогресс и щиты новичков. После сохранения при полной остановке очистка мобов не запускается.
- Административное отключение модуля на работающем сервере сохраняет обычный путь очистки через Control.

Все прежние изменения пакета, включая исправление блокировок, развитие сложности рейдов, строительство и интерфейсы, сохранены. Форматы игровых данных, конфигурации и протокол общего ядра v2 не изменены.

## Рейд после перезапуска

Существующий механизм сохраняет оставшихся врагов, а при загрузке возвращает их в очередь появления. Уже побеждённые враги не возвращаются. Новое поколение рейда делает прежние тела мобов недействительными: Events удаляет их при обычной загрузке сущностей. Поэтому удалять мобов из остановленного региона не требуется. Посторонние сущности не затрагиваются.

Исправление не меняет действующие сроки событий и правила административной паузы.

## Установка

1. Полностью остановите сервер и сохраните резервную копию JAR и данных Towny/NeverLandTowny.
2. Замените каждый уже установленный NeverLandTowny JAR соответствующим файлом этого пакета. Уберите прежние версии JAR, чтобы не было дублей. Неиспользуемые модули устанавливать не требуется.
3. Оставьте папки конфигураций и данных на месте. Новые настройки для этого исправления не нужны.
4. Запустите сервер полностью, без `/reload`. Затем проверьте штатную остановку и повторный запуск.

Для устранения этого общего пути во всех аддонах обновляется весь установленный комплект. Сборки 0.43.0 и 0.43.1 используют одинаковый протокол блокировки, но старые JAR сохраняют прежнее поведение при остановке. Сборки до 0.43.0 смешивать с ними нельзя.

`/nltlock` остаётся доступна для OP и `neverlandtownycontrol.admin`.

## Проверка

Новый тест сначала запускается со старым пакетом 0.43.0 и активной частично пройденной волной, затем с исправленным пакетом на сохранённых данных. Он проверяет реальную остановку Folia, сохранение прогресса и оставшихся врагов, удаление старого тела рейдового моба и сохранение посторонней сущности после запуска. Положительные прогоны отклоняются при ошибке включения/отключения любого плагина или watchdog-дампе.

Точные результаты, версии и контрольные суммы проверенных JAR: `docs/validation/shutdown-0.43.1/`. Это изолированный сервер без игроков; проверка не заменяет нагрузочное испытание.
