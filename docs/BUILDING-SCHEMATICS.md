# Собственные схемы зданий

Рабочая ветка 0.52, NeverLandTownyBuilds 0.10.0. Формат — Sponge `.schem` v2/v3, обычный или GZIP; импорт происходит при полном запуске сервера. WorldEdit не требуется. Спецификация: https://github.com/SpongePowered/Schematic-Specification/tree/master/versions.

## Подготовка билдером

1. Сделать отдельную схему каждого из пяти уровней обычного здания; для Чуда нужен один уровень. ID здания берётся из `projects.yml`.
2. Вход направить на север, нижний слой поставить на уровень земли. Подземные помещения этим импортом не поддерживаются. Сохранённое WorldEdit-смещение `Offset` не применяется.
3. Следующий уровень сохраняет прежние блоки и их состояния на прежних местах относительно точки установки. Можно добавлять этажи и пристройки. Снос или замена защищённых блоков при улучшении не поддерживаются: несовместимая семья схем отклоняется до выдачи чертежа.
4. В каждой схеме ратуши должна быть ровно одна кафедра — ядро рейда. Не экспортировать мобов, рамки, стойки и другие сущности.
5. Контейнеры экспортировать пустыми. Переносятся блоки и их состояния, но не содержимое сундуков, книги кафедр, надписи и прочий NBT. Листва получает постоянное состояние.

## Установка

Остановить сервер, сделать копию данных плагинов. Разместить файлы внутри `plugins/NeverLandTownyBuilds/blueprints/source/`, например `medieval/town_hall/1.schem` … `5.schem`. В `blueprints.yml` вместо `projects: {}` указать:

```yaml
schema: 1
projects:
  town_hall:
    medieval:
      levels:
        '1': medieval/town_hall/1.schem
        '2': medieval/town_hall/2.schem
        '3': medieval/town_hall/3.schem
        '4': medieval/town_hall/4.schem
        '5':
          file: medieval/town_hall/5.schem
          origin: [15, 15]
```

`origin` — локальные X/Z точки установки внутри конкретной схемы, отсчёт с нуля. Без него используется центр нижнего слоя. Для схем разных размеров эта точка должна соответствовать одному месту здания. Стиль: `medieval`, `modern`, `fantasy`. Полная семья задаётся отдельно для каждого стиля. Если пара «здание/стиль» не настроена, действует прежняя процедурная модель. Если она настроена с ошибкой, новые чертежи этой пары недоступны; тихой подмены моделью по умолчанию нет.

Запустить сервер и проверить `/townybuilds blueprints` с правом `neverlandtownybuilds.admin` или из консоли. Команда показывает версии и причины ошибок. Обычный `reload` не перечитывает схемы.

Ограничения: сторона до 128 блоков, объём до 262 144 ячеек, до 30 000 непустых блоков одного уровня, до 4096 состояний палитры. Bedrock, барьеры, командные/структурные блоки, порталы, спавнеры, TNT и некоторые служебные блоки запрещены. Существующие цены, ресурсные требования, зависимости и артефакты не пересчитываются по объёму схемы.

## Сохранение старых зданий

При первом получении чертежа фиксируется хеш всей семьи уровней. Превью, выбор места, стройка, отмена, защита, кафедра рейда и ремонт используют эту версию. Замена исходного `.schem` после перезапуска действует на новые чертежи. Уже выданные чертежи, улучшения существующего здания и прежние стройки остаются на своей версии.

`blueprints/versions/` — необходимая часть городских данных. Не удалять её при очистке исходных файлов или обновлении плагина; включать в резервные копии вместе с `town-data.yml`. При утрате или повреждении используемого архива плагин останавливает загрузку, не подменяя геометрию и не меняя мир. Восстановить архив из той же резервной копии.

Старые площадки без `blueprint-set` сохраняют процедурный план. Импортированные площадки используют отдельный код архитектуры: откат на старый JAR требует согласованного восстановления данных и мира из копии до импорта. Нельзя вручную удалять `blueprint-set` или менять код архитектуры: это другая геометрия защищённой постройки.

Сервер CraftoUI 0.8.21 умеет читать закреплённую геометрию и стили. Клиент 0.8.19 остаётся совместимым; протокол не меняется.
