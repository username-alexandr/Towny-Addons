# Программы кандидатов и проверка целей

NeverLandTownyElections 0.2.0 добавляет к существующим выборам текст программы и до трёх проверяемых целей. Голоса, кворум, должности, подсчёт и применение победителей сохраняют прежние правила. Этот раздел не выдаёт деньги, награды или автоматические наказания.

## Игрокам

В меню `/t elections` появилась кнопка «Программы кандидатов». Правый клик по кандидату открывает его программу; голосование остаётся на левой кнопке. В карточке показаны описание, цель, показатель при публикации, текущий показатель и время проверки по Москве.

| Команда | Действие |
| --- | --- |
| `/t elections programs` | Программы текущей кампании |
| `/t elections program [имя]` | Своя программа или программа кандидата |
| `/t elections programs history` | До десяти последних закреплённых кампаний |
| `/t elections promise text <текст>` | Описание до 400 символов |
| `/t elections promise building <ID здания> <1–5>` | Завершить здание указанного уровня |
| `/t elections promise population <1–1000000>` | Достичь указанного населения |
| `/t elections promise pollution <0–100>` | Держать загрязнение не выше предела |
| `/t elections promise remove <1–3>` | Удалить выбранную цель |
| `/t elections promise clear` | Очистить описание и цели |

Просмотр требует `townyelections.use` и членства в городе. Редактирование требует также `townyelections.candidate`, действующей кандидатуры и права гражданства занимать должность. Разрешения и срок проверяются ещё раз непосредственно перед отправкой записи. После завершения приёма кандидатов менять программу нельзя. При смене должности старый текст не переносится автоматически в список программ новой должности.

## Что означает отчёт

Для здания учитывается завершённый уровень из Builds, для населения — подтверждённое значение Population, для загрязнения — готовое значение Environment. Здание должно существовать в действующем каталоге. Нет доступного провайдера, он приостановлен или не готов — выводится «Не хватает данных», а не провал.

«Цель достигнута» означает, что условие выполняется **сейчас**. «Условие уже выполнялось при публикации» помогает отличить исходное состояние от нового результата. Архив хранит неизменную программу, а её показатели также проверяются на момент просмотра. Это не запись исторического максимума и не доказательство личного вклада кандидата.

## Сохранение и совместимость

`programs.yml` — отдельный журнал с подтверждением записи: новый текст виден как сохранённый только после успешной атомарной замены файла. Запись и сериализация выполняются отдельным исполнителем. Исходный журнал выборов сохраняет schema 1; добавлены необязательные поля `programs-binding` и `program-receipts`. Старые выборы без этих полей читаются без пересоздания бюллетеней.

До открытия голосования фиксируется точная подтверждённая версия каждой допустимой программы. Сначала сохраняется снимок программы, затем основной журнал выборов подтверждает привязку к UUID кампании, после чего открываются бюллетени. Завершение записи будит глобальный планировщик Folia; часовой интервал обычной проверки не задерживает этот переход.

Если необязательный журнал не успел подтвердить запись за пять секунд, голосование открывается с явной отметкой недоступности программ. Отсчёт использует монотонное время, продолжение исполняется на ближайшем доступном тике, без ожидания файла в потоке сервера. Продолжительность самого голосования остаётся полной. Поздно записанный снимок не признаётся принятой программой этой кампании и не появляется в принятом архиве. Отложенное продолжение проверяет UUID кампании, фазу, административную паузу и срок; оно не может открыть другую кампанию.

Настройка `programs.enabled: false`, некорректный тип настройки или повреждённый `programs.yml` выключают только программы. Существующие выборы продолжаются; повреждённый файл не перезаписывается. Ошибка основного журнала бюллетеней по-прежнему требует проверки администратора.

Файл программ ограничен 64 МиБ, реестр — 10 000 черновиков и 10 000 кампаний, одна кампания — 128 программ. При достижении ограничения запись закрывается с понятной ошибкой. Подтверждения последних 20 кампаний дополнительно сохраняются в основном журнале, принятые архивы имеют собственную отметку подтверждения. Автоматического удаления истории нет.

API `TownyElectionsApi.programs(UUID)` возвращает неизменный снимок с готовностью, программами и публичными показателями. Индивидуальные бюллетени не раскрываются. Наблюдаемых снимков не более 128, срок актуальности — две минуты; чтение API не опрашивает Towny и не ждёт общий монитор. Меню обновляется по запросу игрока. В существующем основном журнале бюллетеней остаётся прежняя синхронная запись: эта версия не заявляет перенос всего модуля на асинхронное хранение.

## Установка

Остановите сервер и сохраните резервную копию папки `NeverLandTownyElections`. Замените старый JAR на единственный `NeverLandTownyElections-0.2.0.jar`, сохранив существующие `config.yml` и `elections.yml`. Новая настройка по умолчанию включена даже в прежнем конфиге. `programs.yml` появится при первой подтверждённой записи. Для трёх типов показателей нужны обновлённые Builds, Population и Environment; отсутствие любого из них не отменяет выборы.

## Проверка

Сборка на закреплённом Folia API / Java 25: PASS трёх программ — `ElectionProgramsSmoke` (24 проверки), прежние `ElectionSmoke` и `ElectionsRepositorySmoke`.

Нативная Folia: PASS **31 + 6 + 6** проверок в трёх полных загрузках, все завершились с кодом 0. Проверены настоящие Towny/Citizens/Governance, голоса и применение победителя, изменения программы на границе срока, физическая задержка файла, пятисекундный отказ optional-раздела при часовом обычном таймере, исходные и текущие показатели, неизвестные данные при паузе Population, права и отсутствие записи при просмотре, архив после смены кампании и перезапуска. Третья загрузка с намеренно повреждённым `programs.yml` сохранила действующие бюллетени и возможность голосовать, оставив повреждённый файл нетронутым.

Использованы явно обозначенные офлайн-замены Player, InventoryView и EntityScheduler; проверен нативный InventoryClickEvent и серверный инвентарь, а не работа сетевого клиента. Денежные операции не выполнялись. Исходники сценария: `scripts/election-programs-runtime-probe`; проверяемые утверждения и SHA-256 JAR: `docs/validation/city-systems-052/election-programs`.
