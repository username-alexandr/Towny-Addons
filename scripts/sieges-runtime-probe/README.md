# Нативная проверка Sieges+

Запускается только на отдельном одноразовом сервере с адресом `127.0.0.1`, файлом `ALLOW_DISPOSABLE_RELIABILITY_PROBE` в корне и параметром JVM `-Dneverland.runtimeProbe=true`. Сценарий создаёт города, нацию, осаду, жителей, постройки и сущности; для рабочего сервера с игроками он не предназначен.

Подготовьте Purpur 26.2 / Java 25, Towny 0.103.2.0, Vault и провайдера экономики, все JAR из `versions.yml`, а также официальный SiegeWar 3.6.2. Проверенный SHA256 SiegeWar: `61ecc816ff08b6d9b11982b8f633cabf85c92738dd3bcdcace162a2bb854a8aa`.

```bash
python scripts/sieges-runtime-probe/build.py --server-dir /path/to/disposable-server --java-home /path/to/jdk25
python scripts/sieges-runtime-probe/run.py --server-dir /path/to/disposable-server --java-home /path/to/jdk25 --phase first
python scripts/sieges-runtime-probe/run.py --server-dir /path/to/disposable-server --java-home /path/to/jdk25 --phase restart
```

Обе фазы выполняйте последовательно на одном стенде без восстановления снимка между ними. Первая фаза создаёт осаду через инфраструктуру SiegeWar; перезапуск должен загрузить её из Towny. Производственный Sieges+ использует только публичные контракты, а создание данных и reflection к полям соседних сервисов ограничены тестовым плагином.

Каждая фаза проверяет точные версии всех JAR, записывает их SHA256 и список успешно выполненных проверок. Источник перечня API — инвентаризация текущего исходного дерева. На сбое процесс возвращает ошибку; на успехе сервер завершается сам. После прогона сохраните доказательства и удалите `NeverLandSiegesRuntimeProbe.jar`.

Это проверка нативных провайдеров и обработчиков с управляемыми Player-объектами, подготовленными метаданными построек и настоящими сущностями. Она не подменяет проверку с подключёнными клиентами, ресурс-паком или нагрузкой. При повторном запуске восстановите чистый снимок именно одноразового стенда.
