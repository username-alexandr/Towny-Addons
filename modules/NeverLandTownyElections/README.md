# NeverLandTownyElections

Отдельный плагин выборов мэра, городского совета и должностных лиц. Требует Towny 0.103.2.0, Governance 0.1.10, Paper/Purpur 26.2 и Java 25. Citizens 0.1.0 и Ideologies 0.1.8 подключаются через публичные API версии 1.

По умолчанию первая кампания начинается через сутки после обнаружения города. Следующие начинаются раз в 14 дней: 24 часа выдвижения, затем 24 часа голосования. При длительном отключении сервера окно голосования открывается полностью после запуска. Пропущенные кампании не запускаются пачкой. При затянувшейся кампании новый срок отсчитывается от её закрытия.

В `config.yml` меняются интервал, окна, кворум, имена и число мест. Активная кампания сохраняет собственные сроки, кворум и состав должностей; reload действует на новые кампании. Проверка формы правления действует сразу.

## Игроку

- `/t elections` или `/elections` — меню. Откройте должность, выберите кандидатов и нажмите подтверждение.
- `/t elections candidate mayor` — выдвинуть себя в мэры. Для совета: `councillor`; другие ID указаны в меню.
- `/t elections withdraw` — снять кандидатуру до закрытия выдвижения.
- `/t elections vote councillor Player1,Player2` — выбрать до числа доступных мест. Для мэра — одного игрока.
- `/t elections results` — итог по каждой должности, явка и избранные жители.
- `/t elections history` — последние пять записей; журнал хранит последние 20 закрытий кампаний.

Один человек может выдвинуться только на одну должность в кампании. Повторное голосование заменяет предыдущий бюллетень по этой должности. Избиратели фиксируются на старте; при голосовании и подсчёте снова проверяются членство и право `VOTE`. Для кандидатуры и назначения нужен `HOLD_OFFICE`. Временный житель и иностранец по стандартным настройкам Citizens этих прав не имеют. Почётный гражданин должен состоять в городе.

Кворум по умолчанию 25% сохранивших право голоса избирателей. Для каждого места используется одобрительное голосование: до N различных кандидатов на N мест. Избираются кандидаты с наибольшим числом голосов и хотя бы одним голосом. Если ничья пересекает границу мест, вся должность сохраняет прежний состав. При отсутствии кворума состав также сохраняется. Если поддержанных кандидатов меньше числа мест, избирается только это число; прежние держатели успешно разыгранной должности заменяются.

Мэр меняется в самом Towny. Должностные лица записываются в Governance и получают предусмотренные им права на предложения законов. После успешного избрания `councillor` совет для голосований Governance состоит из этих депутатов и мэра, если `council.mayor-is-member` включён. Towny-ранг assistant больше не даёт отдельного места в таком совете. Выборы не назначают дополнительные Towny-ранги и не заменяют штатные команды защиты Towny.

## Формы правления

`Ideologies/config.yml` связывает любой ID идеологии с формой:

```yaml
government:
  ideology-forms:
    none: DEMOCRACY
    agriculture: DEMOCRACY
    monarchy: MONARCHY
    autocracy: AUTOCRACY
```

ID `monarchy` и `autocracy` распознаются и без этой секции; остальные по умолчанию демократические. В новом `ideologies.yml` есть выбираемая Монархия. Для старой установки перенесите её секцию из нового файла вручную. Назначение через штатную команду Ideologies: `/townyideologies set <онлайн-житель города> monarchy 1`. Возврат к обычной идеологии включает выборы снова. Выбор/смена идеологии подчиняется прежним ценам, разрешениям и `settings.selection.change-allowed`.

При `allow-authoritarian: true` формы MONARCHY/AUTOCRACY отключают начало и участие в выборах; открытая кампания отменяется на ближайшей проверке. Правитель остаётся прежним. В Governance снова доступен обычный механизм назначений. Уже начатое применение итогов после сбоя требует проверки администратора. При `allow-authoritarian: false` выборы проводятся при всех формах. Неизвестное значение формы, отключённый установленный провайдер или несовместимый API останавливают операции с диагностикой. Отсутствующий Ideologies означает демократию; отсутствующий Citizens оставляет право всем членам Towny.

## Администратору и сохранение

`townyelections.use`, `.vote`, `.candidate` доступны игрокам по умолчанию. `.admin` — только операторам. Разрешения Citizens дополнительно ограничивают участие. Мэр не получает административное управление кампаниями автоматически.

- `/elections start <город>` — досрочно открыть кампанию, если нет активной/зависшей.
- `/elections reload` — проверить и применить конфигурацию.
- `/elections resume <город> <UUID>` — после проверки завершить записанный результат REVIEW. Нужен полный ID из `results`/журнала.
- `/elections abort <город> <UUID>` — явно закрыть кампанию, сохранив текущие должности и мэра, включая уже применённую часть результата.

Обычный мэр не может через Governance снять или назначить держателя уже избранной должности. Административный `townygovernance.bypass` сохраняет возможность вмешательства. Прямое административное изменение мэра в Towny не блокируется; при несовпадении мэра с ожидаемым Elections останавливает применение для сверки.

`elections.yml` хранит UUID кампании/города/участников, снимок правил, бюллетени, результаты и ограниченную историю. Запись атомарная, состояние в памяти публикуется после успешного сохранения. При ошибке дальнейшие записи блокируются до восстановления и перезапуска. Файл содержит индивидуальные бюллетени и должен быть доступен только администраторам сервера; публичный API их не выдаёт.

Перед изменениями записывается APPLYING. Governance атомарно сохраняет должности вместе с квитанцией UUID кампании, повтор того же результата не создаёт новых назначений. Towny меняет мэра и принимает сохранение через штатный источник данных. Общей транзакции между Towny и двумя файлами нет: после остановки в APPLYING плагин переводит кампанию в REVIEW, не повторяя изменения автоматически. Перед resume сверьте мэра, должности и квитанцию. Сторонняя смена мэра, новые результаты Governance или утрата права занять должность блокируют возобновление. Исправьте причину либо используйте явно подтверждённое администратором abort.

## Проверка

`python scripts/build_suite.py Elections Governance Ideologies --stage dist/plugins` запускает все executable smoke-тесты и проверки контрактов. `scripts/elections-runtime-probe/` содержит воспроизводимый прогон на отдельном сервере с маркером `ALLOW_DISPOSABLE_RELIABILITY_PROBE` и loopback-адресом. Пробный плагин нельзя устанавливать на игровой сервер.
